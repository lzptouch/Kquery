## 3. 设计决策

### D1 「管理区」= 界面分组 + 后端门禁，**不改 URL**

URL 保持 `/knowledge`、`/graph`。改 URL 要动 13 条 Route、nginx×2、vite、4 个后端 `prefix`，收益仅是路径整齐。**取不改。**

### D2 令牌：给 `JwtAuthProvider` 加 `encode()`，不新增 Provider

`JwtAuthProvider`（`auth.py:91-165`）已具备完整验签/过期/`iss`/`aud`/`alg` 白名单校验，只缺签发。密码模式下 `build_auth_provider` **直接返回它**，登录端点经 `request.app.state.auth_provider` 调 `.encode()`。

收益：零新增类、零新增存储，签发与验签共享同一密钥与同一套算法约束，不可能出现「签发一套、验签另一套」的裂缝。
代价：无法服务端吊销，登出=前端清 token（缓解见 D7）。

### D3 四档优先级（原为三档）

```
enabled=True:
  jwt_enabled or password_enabled → JwtAuthProvider      # 本地账号也走 JWT
  else                            → StaticTokenAuthProvider
enabled=False                     → HeaderAuthProvider    # 开发/测试，行为不变
```

`auth_tokens_json` 与密码模式同时配置 → 静态表**被忽略**，启动 `logger.warning` 明示。

### D4 注册策略

新用户角色**硬编码 `["sales"]`**，请求体带 `roles` 一律丢弃；`auth_registration_enabled` 默认 **`false`**。
`sales` 在 `ROLE_CAPABILITIES` 中恰为 `("ask","view_own_data")`（`security.py:295`），最贴合「只能对话」。

### D5 保留多角色，仅把「进管理区」绑定 admin

现有 4 档角色 + 4 个演示用户 + 权限矩阵页按 4 角色渲染。简化为二值要连带改 `UsersPage`/`PermissionMatrix` 及测试，收益极低。**保留 4 档。**

### 5.3 新增 `app/api/auth.py`

路由级**不挂** `get_principal`（否则登录自我死锁）；`/auth/me` 在函数签名里单独依赖。

| 方法 | 路径 | 请求 | 响应 | 门禁 |
|---|---|---|---|---|
| POST | `/auth/login` | `{username, password}` | `{token, user_id, tenant_id, roles[], groups[], expires_in}` | 公开 + 登录限流 |
| POST | `/auth/register` | `{username, password}` | `{user_id, roles[]}` | 公开 + `auth_registration_enabled` |
| GET | `/auth/me` | — | `Principal` + `capabilities[]` | `get_principal` |

要点：
1. **不区分失败原因**：用户不存在/口令错误/账号停用 → 统一 `401 + AUTH_FAILED(1001)` + 同一文案「用户名或密码不正确」。停用也不单独提示，否则等于告知账号存在。
2. **限流复用现成组件**：`TokenBucketLimiter.allow(key, rate, capacity)`（`ratelimit.py:28`）键为任意串，传 `f"login:{username}"`。**另建独立实例**（`build_limiter()`），不与 `app.state.limiter`（租户桶）混用，否则登录会吃掉问答配额。超限 `429 + RATE_LIMITED(6101)`，注释标注语义借用。
3. **注册**：`roles=["sales"]` 硬编码、`enabled=True`、`tenant_id="default"`；重名 `409`。
4. **审计**：登录成功/失败/注册写 `audit_store.append(...)`（`audit.py:33`）。**不用 `log_admin`**（`audit.py:79`，语义为管理员操作）。
5. **落盘只存 `password_hash`**，绝不存明文；`backend/data/` 已 gitignore。

### 5.6 强烈建议：`get_principal` 加目录复核（D7）

```python
# app/dependencies.py，authenticate 之后
directory = getattr(request.app.state, "user_directory", None)
if directory is not None:
    record = directory.get(principal.user_id)
    if record is None or not record.get("enabled", True):
        raise ApiError(ErrCode.UNAUTHORIZED, "账号不存在或已停用", http_status=401)
    principal.roles = list(record.get("roles") or [])   # 角色以目录为准 → 即时生效
```

代价：每请求一次加锁 dict 查找（微秒级）。收益：降权/停用**立即生效**，不必等令牌过期。这是 v1 完全遗漏的安全缺口。

`RequireAdmin` 显式渲染无权页：静默跳回会让用户以为页面坏了，且与 `auth.ts:120-125` 自身「401/403 要与系统故障区分」的设计原则一致。

**单一事实源**：`session` 存在 `localStorage`（键沿用 `kquery.*`），`AuthContext` 只是它的 React 镜像。**不要**在 Context 里另存一份真相，否则与 `authHeaders()` 会漂移。

**启动流程**：`AuthProvider` 挂载时若 localStorage 有 token → 调 `/auth/me` 校验 → 成功置 `session` 失败 `clearPrincipal()`；期间 `ready=false`，`RequireAuth` 渲染加载态（**避免闪一下登录页**）。
