## 〇、定位与现状核查

Kquery 的能力分布有一个**极不对称的断层**：

| 侧 | 现状 | 判定 |
|---|---|---|
| **检索侧** | 指标层（recall@k / nDCG / MRR / 分路 / 候选池天花板 / 缺口三桶）、跑批脚本（file / local / live 三模式）、切块消融实验、索引重建、CI 回退门禁 | ✅ 已实现 |
| **生成侧** | **无 rubric、无 judge、无显著性、无答案正确性链路**；离线评测打分完全不看生成结果 | ❌ 未实现 |
| **上下文侧** | 线性路径有四段式组装（去重 → MMR → 预算 → 硬截断），**Agent 路径绕过**；无分区器、历史不压缩、输出侧无上限 | ⚠️ 部分 |
| **上游治理** | 隔离仓 4 通道 + 三态熔断；**多模态全部绕过**；无模型路由降级 | ⚠️ 部分 |
| **运维侧** | 8 条告警规则 + K8s 清单 + 容量计算器；**无 runbook / 自动回滚 / 部署 canary** | ⚠️ 部分 |

**这条断层的直接后果**：把 `agent_mode` 从 `plan_execute` 切到 `react` 是**一次不可度量的行为变更**——检索指标不变，答案质量却可能变化，而**没有数据能证明哪边更好**。改切块大小有 recall 可看，改提示词只能靠感觉。

**本篇的目标**：把生成侧与上下文侧从「有机制无度量」补到「**能进 CI 门禁**」。

**外部依据**（本篇方案均经公开实践对照）：

| 领域 | 依据 | 用在哪 |
|---|---|---|
| 提示词注入防御 | OWASP LLM Top 10 · LLM01 的四层防御模型 | §二 5 |
| 配对评估与样本量 | 配对自举法、「最小可检测效应」导向的样本量规划、judge 与人工标注校准 | §三 1、§三 4 |
| 熔断 / 隔离仓 / 重试 | 超时与熔断的层级关系、重试只能由一层拥有 | §四 3 |
| SLO 与告警 | 「告警症状而非原因」、错误预算与 burn-rate 告警、事件分级与无责复盘 | §五 1 |
| 状态机与人在回路 | 状态字段必须显式声明（未声明的键被静默丢弃）、中断点持久化、危险动作需人工确认 | §二 1、§四 4 |

### 4.4 `LM-04`：VLM 结构化输出

**问题**：项目**已经在用视觉模型系列**（用于 caption、直答与 OCR），但**没有一处是结构化输出**：

| 路径 | 现状 | 证据 |
|---|---|---|
| 图像 caption | 提示词要求固定四段，但解析只剥围栏压空行，**无 schema 校验、无失败兜底** | `services/graph/images.py:31-37`（四段提示词）、`:109-112`（`_parse_caption`） |
| 视觉直答 | 纯自由文本 | `services/multimodal.py:26-29`、`:72` |
| OCR | 纯自由文本 + 正则清洗 | `services/parsers/ocr.py:40`、`:105-133` |
| 图谱实体抽取（**文本侧**） | **有**严格 JSON + 字段校验 + 重试 + 降级为空 | `services/graph/extractor.py:19-37`、`:44-75`、`:101-109` |

后果：`images.py:9-10` 声明的硬约束「描述结构化」**在代码层没有任何强制**——模型不按四段输出时，系统照单全收，下游无法按字段消费 caption（如「图中文字」无法单独用于 OCR 检索）。

**目标**：caption 走结构化输出（有 JSON 则用 JSON，无则回落四段解析），解析失败有兜底且**不阻塞入库**。

**目标态的 caption 契约**：主体描述、属性列表、场景描述、图中文字，外加一个「是否走了回落解析」的标记。

**改造计划**：

1. **新增 `backend/app/services/multimodal/schema.py`**：caption 数据结构与解析入口——剥围栏 → 定位四段标题 → 缺段补空 → 全乱返回 None。
   四段标题与现提示词**严格一致**（`images.py:29-35` 的「主体 / 属性 / 场景 / 图中文字」）。
2. **解析优先 JSON（但注意 API 现实）**：caption 走**多模态会话接口**（`images.py:57`），**不是**文本生成接口；JSON 模式的视觉模型支持**须以 SDK 实测为准**。实现顺序：**先探测**（带 JSON 参数调用，平台拒绝即记警告并降级）→ 非法 / 不支持则回落四段文本解析 → 仍失败则原文落库并标「非结构化」（**不阻塞入库**）。探测结果按模型缓存进程内，同模型只试一次。
3. **向量内容保持不变**：结构化后**渲染回原来的四段文本**再进向量库（`images.py:151-162`），保证**已有索引的向量内容与新内容一致**——否则换实现等于换语料，评测基线全部作废。这是本条改造最容易踩的坑。
4. **保留直答与 OCR 的自由文本**：直答是生成不是抽取；OCR 输出本就是自由文本。**不要为了「结构化」而套 schema**。
5. **schema 版本化**：`images.py:27` 的模型版本旁增加 schema 版本，两者任一变化都需重建图像索引（复用现有重建判据机制）。

**验收**：`tests/unit/test_caption_schema.py` 断言 ① 标准四段 → 解析成功、字段正确 ② 缺「图中文字」段 → 成功且该字段为空 ③ 全乱 → 返回 None ④ JSON 输入 → 解析成功 ⑤ **渲染结果与输入四段文本逐字一致**（保证向量内容不变）；**回归**：图像索引的既有集成用例全绿。
