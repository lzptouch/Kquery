## 一、一句话摘要

Kquery 测试体系按 **Mock 默认 + 真实千问可选** 双模式运行；当前测试覆盖 9 阶段核心链路，关键路径（CRAG / Agent / GraphRAG / 多智能体）均有单元测试与集成测试；2026-10-17 起新增**登录注册与管理区角色门禁**的专门回归（`tests/integration/test_auth_flow.py`）。

> **口径说明**：用例数随版本变化，具体数应以 `pytest --collect-only` 实时口径为准。当前实测约 731 个用例（其中登录注册/门禁相关 51 个），本处不写死数字以免随版本漂移。

## 二、当前实现

### 2.1 测试模式

```bash
# Mock 模式（无 API Key）
cd backend && uv run pytest

# 真实千问模式
NEXUS_DASHSCOPE_API_KEY=<key>  # 或 DASHSCOPE_API_KEY
uv run pytest --real-qwen

# 标记运行
uv run pytest -m "stage_5"  # 仅
```

**关键设计**：
- **Mock 默认**：`uv run pytest` 无需真实 API Key，CI 友好
- **真实千问可选**：`--real-qwen` 标志启用，开发者本地验证
- **markers 按阶段**：`stage_1` ~ `stage_9` pytest markers
- **认证/门禁回归为无 marker 的独立集成测试**：`tests/integration/test_auth_flow.py`（51 用例）用独立 fixture + 临时 `DATA_DIR` + 环境变量注入，**不复用 conftest 的 `client`**——后者强制 `AUTH_ENABLED=false`（身份头档），与这里要验证的"令牌认证 + 登录签发"不是同一条代码路径

```python
def test_crag_router_correct():
```

#### Agent 工具调用（`tests/test_agent/test_tools.py`）

```python
@pytest.mark.asyncio
async def test_vector_search_tool():
    # Mock retriever
    mock_retriever = MockHybridRetriever(results=[{"text": "...", "score": 0.9}])
    tool = VectorSearchTool(mock_retriever, config={})
```

#### ACL 默认拒绝 + deny 优先（`tests/test_security/test_acl.py`）

```python
def test_acl_default_deny():
    acl = ACLService(acl_path=Path("test_acl.json"), user_directory=[])
    # 用户不在 allowed → 拒绝
    assert acl.check(user_id="alice", doc_id="doc_123") is False

def test_acl_deny_priority():
    acl = ACLService(acl_path=Path("test_acl.json"), user_directory=[])
    # 同时在 allowed + denied → 拒绝
    acl._acl = {"doc_123": ["alice"]}
    acl._deny = {"doc_123": ["alice"]}
    assert acl.check(user_id="alice", doc_id="doc_123") is False

def test_acl_allow():
    acl = ACLService(acl_path=Path("test_acl.json"), user_directory=[])
    acl._acl = {"doc_123": ["alice"]}
    assert acl.check(user_id="alice", doc_id="doc_123") is True
```

## 三、设计原则与原理剖析

### 原理①　Mock 默认 + 真实千问可选：CI 友好

| 模式 | 优势 | 代价 |
|---|---|---|
| **Mock 默认（当前）** | 无需 API Key、CI 友好、秒级跑 | 不能验证真实 LLM 行为 |
| **真实千问可选** | 验证真实集成 | 需要 API Key、慢、有配额消耗 |

> **业内参考**：LangChain / LlamaIndex / OpenAI Cookbook 均采用双模式；CI 用 Mock，开发者本地用真实 API。

### 原理②　markers 按阶段：粒度可控

```toml
# pyproject.toml
[tool.pytest.ini_options]
markers = [
    "stage_1: Naive RAG",
    "stage_2: Hybrid retrieval",
    "stage_3: Smart chunking + multimodal",
    "stage_4: Query preprocessing",
    "stage_5: Self-reflection",
    "stage_6: Agentic RAG",
    "stage_7: GraphRAG",
    "stage_8: Multi-agent reports",
    "stage_9: Enterprise guardrails",
]
```

**价值**：单阶段调试时只跑该阶段测试 → 反馈更快。

### 原理③　启动期 fail-fast：索引损坏拒绝服务

`app/main.py` 的 `lifespan`：
```python
store = build_vector_store(settings)
store.load()  # 索引损坏 → 抛异常 → 进程退出
```

**测试策略**：测试启动前必须保证索引完整（`test_conftest.py` 的 fixture 自动重建）。

## 四、改进建议

### 1. 覆盖率统计

当前未集成 `pytest-cov`；建议：
```bash
uv run pytest --cov=app --cov-report=html
```

### 2. CI 接入

```yaml
# .github/workflows/test.yml
name: Test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
    - uses: actions/checkout@v4
    - uses: actions/setup-python@v5
      with: { python-version: "3.11" }
    - run: pip install uv
    - run: uv sync
    - run: uv run pytest --cov=app --cov-report=xml
```

### 3.  GraphRAG E2E

GraphRAG 构建 + 查询链路复杂，建议补：
- 大规模图谱（100+ 实体）构建性能测试
- BFS 深度 / 广度性能对比
- 社区摘要质量人工评估

### 4.  多智能体 E2E

Writer ↔ Critic 循环难自动化评估，建议：
- 引入 LangSmith / LangGraph Studio 可视化追踪
- 准备 golden dataset（人工撰写报告）→ 对比 Writer 输出
- 评分阈值调优的统计测试

### 5.  护栏测试

ACL / 敏感词 / 配额的边界条件需穷举：
- ACL 默认拒绝 / 显式允许 / 显式拒绝 / deny 优先（已覆盖）
- 配额：0 配额 / 边界值 / 并发请求
- 敏感词：长词优先 / 跨词边界 / 大小写
