## 一、需求与范围确认

### 1.1 三个功能的代码锚点

| 功能 | 实质 | 代码锚点 |
|---|---|---|
| 快问临时通道 | F4「单文档上传即问」：上传 → 解析 → 临时索引（不入库）→ 只对这一篇提问 → TTL 到期清理 | 后端 `backend/app/api/quickask.py`（5 端点）+ `backend/app/services/quickask.py`（424 行）+ 前端 `QuickAttachPanel.tsx` |
| 聊天输入区附件面板 | 聊天输入框左侧 📎 按钮 + 弹出的附件上传面板 | `frontend/src/features/chat/components/ChatInput.tsx:63-74`（按钮）+ `QuickAttachPanel.tsx`（面板）|
| 多副本共享语义 | F6/批次 4「共享状态层」：Redis 后端的 SharedState 门面 + ExternalDocStore 外置状态 + 各组件的 Redis 分支 | `backend/app/core/shared_state.py`（507 行）+ `backend/app/services/external_state.py`（146 行）+ cache/ratelimit/idempotency/sessions/config_store/ingest 的 Redis 分支 |

### 1.2 关键事实（已逐行核实）

1. **附件面板就是快问面板**。聊天输入区**没有**其它附件能力：`ChatInput.tsx:63-74` 的 📎 按钮只把 `attachOpen` 置反（`ChatPage.tsx:470`），从而渲染 `QuickAttachPanel`（`ChatPage.tsx:452-463`）；`rg -i 'attach|附件' frontend/src` 无第二个独立附件功能（`lib/file-types.ts` 的白名单服务于知识库上传向导，不是聊天附件）。因此「删除聊天输入区附件面板」是「删除快问」的前端子集，两者一并执行（§三统一列出，§四给出归属映射）。
2. **快问的全部消费方已穷尽**（`rg -i 'quickask|quick_ask|quickdoc|quick-attach'` 全仓）：后端 8 文件、前端 5 文件、测试 12 文件、部署/配置 4 文件、文档若干，逐条见 §三。
3. **`doc_id` 单文档检索链为快问专属**：`RetrievalFilters(doc_id=...)` 全仓只有 `services/generation/retrieve_stage.py:39-40` 一处构造（快问路径）；Agent 的 `doc_scope` 注入链（`state.py:56-58` → `runner.py:269,287` → `graph.py:43-51,124-125,240,248,268`）也只为快问服务。**但** `RetrievalFilters.doc_id` 字段本身与 `vector_search` 工具的 `doc_id` 入参（`agent/tools.py`「限定在某一篇文档内检索」）是知识库文档内检索的通用能力，**保留**。
4. **Redis 在仓内唯一用途就是共享状态**（`rg 'import redis'` 仅 `core/shared_state.py` 两处按需导入，`fastapi`/业务层无其它 Redis 客户端）。删除多副本共享语义后，Redis 依赖可整体下线：`backend/pyproject.toml:29` 的 `redis>=5.0`、`deploy/docker/docker-compose.yml:65-78` 的 redis 服务、k8s 的 `redis-url` 引用全部可删。
5. **降级语义变化必须显式接受**：删除后限流/幂等/缓存/会话/检索配置/入库任务从「配了 Redis 即多副本共享」收口为**单副本进程内/本地文件**语义。这正是删除该功能的预期结果，需在文档与 PR 描述中写明。

## 二、总体删除策略

| 策略 | 决定 |
|---|---|
| 快问后端 | **整体删除**（服务、路由、装配、配置、错误码），不留开关 |
| `doc_id` 请求链路 | **随快问一并拆除**：`AskRequest.doc_id` → `ask.py` → `pipeline.ask/ask_stream(doc_id)` → `build_filters` / `cache_key(scope)` → Agent `doc_scope` 注入，全链路移除（理由：唯一生产入口是快问，留着即成无生产调用点的死代码，违反仓库 N5 纪律） |
| 保留不动 | `RetrievalFilters.doc_id` 字段、`vector_search` 工具的 `doc_id` 入参、缓存 `scope` 维度（通用维度，默认 `""`）、`pipeline._doc_name_resolver`（证据文件名回填，`pipeline.py:109`） |
| 多副本共享 | **整体删除** `SharedState` 门面与 `ExternalDocStore`，各消费方收口到进程内/本地文件实现；Redis 依赖整体下线 |
| 幂等 | 功能保留（在飞去重 + 结果重放是真实需求，`ask.py:206-331`），仅把存储从 SharedState 换成自带的进程内实现，对外 API（`acquire/release/begin/complete/fail`）不变 |
| 会话/检索配置/入库任务 | 删除 `docs` 形参与外置分支，回到本地 JSON 文件（本地路径代码原本就是 fallback，删除的是外置分支） |
