## 2. 用户认证与账户管理

### 2.1 功能概述

提供完整的用户注册、登录、Token 刷新和个人信息查看功能。基于 JWT Token 机制，支持 access_token 和 refresh_token 双令牌认证。

### 2.2 操作步骤与接口对照

| 步骤 | 操作 | 前端 Service | 后端接口 | 方法 | 请求参数 | 响应 |
|------|------|-------------|---------|------|---------|------|
| 1 | 用户注册 | `authService.register()` | `/api/v1/auth/register` | POST | `{ username, email, password }` | `{ access_token, refresh_token, user }` |
| 2 | 用户登录 | `authService.login()` | `/api/v1/auth/login` | POST | `{ username, password }` | `{ access_token, refresh_token, user }` |
| 3 | 刷新令牌 | `authService.refreshToken()` | `/api/v1/auth/refresh` | POST | `{ refresh_token }` | `{ access_token, refresh_token }` |
| 4 | 查看个人信息 | `authService.getProfile()` | `/api/v1/auth/me` | GET | — | `{ id, username, email, role, created_at }` |

### 2.3 数据流

```
用户输入凭证 → AuthService → POST /auth/login
  → 后端验证 → 生成JWT → 返回Token
  → 前端存储Token → 后续请求携带Authorization Header
  → Token过期时调用 /auth/refresh 刷新
```

### 2.4 前端组件

- **页面**: `pages/Login.tsx`, `pages/Register.tsx`
- **Service**: `services/authService.ts`
- **Store**: `stores/authStore.ts`

## 3. 知识库管理 RAG

### 3.1 功能概述

知识库（Collection）管理是系统核心功能，支持创建知识库、上传文档自动处理（解析、切片、向量化、入库）、语义检索（多路召回 + RRF 融合 + 重排序 + HyDE）、知识图谱自动构建等。

### 3.2 操作步骤与接口对照

#### 3.2.1 知识库管理

| 步骤 | 操作 | 前端 Service | 后端接口 | 方法 | 请求参数 | 响应 |
|------|------|-------------|---------|------|---------|------|
| 1 | 创建知识库 | — | `/api/v1/kquery/collections` | POST | `{ name, description }` | `{ name, status }` |
| 2 | 查看知识库列表 | — | `/api/v1/kquery/collections` | GET | — | `[{ name, doc_count, status }]` |
| 3 | 查看知识库详情 | — | `/api/v1/kquery/collections/{name}` | GET | path: `name` | `{ name, doc_count, stats }` |
| 4 | 删除知识库 | — | `/api/v1/kquery/collections/{name}` | DELETE | path: `name` | `{ success: true }` |
| 5 | 查看知识库文档列表 | — | `/api/v1/kquery/collections/{name}/documents` | GET | path: `name`, query: `page, page_size` | `{ documents, total }` |
| 6 | 查看知识库统计 | — | `/api/v1/kquery/collections/{name}/stats` | GET | path: `name` | `{ doc_count, chunk_count, size }` |

#### 3.2.2 文档处理与检索

| 步骤 | 操作 | 前端组件 | 后端接口 | 方法 | 请求参数 | 响应 |
|------|------|---------|---------|------|---------|------|
| 1 | 上传并处理文档 | 文件上传对话框 | `/api/v1/kquery/documents/process` | POST | FormData: `file`, `collection_name`, `chunk_size?`, `chunk_overlap?` | `{ success, collection_name, file_name, chunk_count, document_id }` |
| 2 | 上传并构建知识图谱 | 文件上传对话框 | `/api/v1/kquery/documents/process-and-build` | POST | FormData: `file`, `collection_name`, `enable_kg?`, `chunk_size?`, `chunk_overlap?` | `{ success, collection_name, file_name, chunk_count, document_id, graph_built? }` |
| 3 | 批量处理文档 | 批量上传界面 | `/api/v1/kquery/documents/batch-process` | POST | FormData: `files[]`, `collection_name`, `chunk_size?` | `{ success, collection_name, file_count, total_chunks, document_ids }` |
| 4 | 语义查询 | 搜索框输入 | `/api/v1/kquery/documents/query` | POST | `{ query, collection_name, top_k?, enable_hyde? }` | `{ query, results: [{chunk_id, text, score, metadata, source}], total_count }` |
| 5 | 全文关键词搜索 | 搜索框输入 | `/api/v1/kquery/documents/search` | POST | `{ query, collection_name?, top_k? }` | `{ query, results }` |
| 6 | 图谱增强搜索 | 搜索框输入 | `/api/v1/kquery/documents/search-with-kg` | POST | `{ query, collection_name?, top_k? }` | `{ query, results, graph_context? }` |
| 7 | 删除文档 | 文档列表操作 | `/api/v1/kquery/documents/{document_id}` | DELETE | path: `document_id` | `{ success: true }` |

### 3.3 数据流

```
文档上传 → LoaderRegistry 选择解析器 → 文档分块 → Embedding 向量化 → Milvus 入库
    │
    ├─ [额外] 实体抽取 → 关系抽取 → Neo4j 知识图谱构建
    │
查询请求 → 多路召回（向量 + BM25 + HyDE）→ RRF 融合 → Reranker 重排序 → 返回结果
```

### 3.4 前端组件

- **页面**: `pages/Chat.tsx`（搜索界面）
- **Service**: 内嵌于 RAG router 中
- **后端 router**: `backend/app/api/router.py`

```

    └─ 语音问答: ASR → 文本 → 同上
    │
答案生成 → 来源引用 → 返回前端展示
```

## 6. GraphRAG 增强检索

### 6.1 功能概述

GraphRAG 在传统 RAG 基础上融合知识图谱的上下文信息，提供混合检索、智能问答、问题类型自动分类等能力，显著提升复杂推理问题的回答质量。

### 6.2 操作步骤与接口对照

| 步骤 | 操作 | 前端 Service | 后端接口 | 方法 | 请求参数 | 响应 |
|------|------|-------------|---------|------|---------|------|
| 1 | 生成图谱上下文 | `knowledgeGraphService.graphRAGSearch()` | `/api/v1/graphrag/search` | POST | `{ query, collection_name?, top_k?, kg_weight? }` | `{ results, graph_context, entities_used }` |
| 2 | 智能问答 | `knowledgeGraphService.graphRAGAsk()` | `/api/v1/graphrag/ask` | POST | `{ query, collection_name?, history? }` | `{ answer, reasoning_path, cited_entities, sources }` |
| 3 | 问题类型分类 | `knowledgeGraphService.classifyQuestionType()` | `/api/v1/graphrag/question-type` | GET | query: `query` | `{ type, confidence, suggested_strategy }` |
| 4 | 实体增强检索 | `knowledgeGraphService.enrichEntities()` | `/api/v1/graphrag/entities` | POST | `{ entities, query? }` | `{ enriched_entities, context }` |
| 5 | GraphRAG 统计 | `knowledgeGraphService.graphRAGStats()` | `/api/v1/graphrag/statistics` | GET | — | `{ total_queries, avg_latency, entity_usage_rate }` |
| 6 | 健康检查 | — | `/api/v1/graphrag/health` | GET | — | `{ status, graph_connected }` |

### 6.3 数据流

```
用户问题 → 问题类型分类 → 路由策略:
    │
    ├─ 简单事实: 向量检索 → LLM
    ├─ 关系推理: 图谱检索 → 上下文融合 → LLM
    └─ 综合分析: 向量 + 图谱 → RRF 融合 → LLM
    │
答案 + 推理路径 + 引用实体 → 前端展示
```

### 6.4 前端组件

- **Service**: `services/knowledgeGraphService.ts`（graphRAG 相关方法）
- **后端 router**: `backend/app/api/graphrag.py`

```
    │
导入知识库: 笔记内容 → 分块 → Embedding → 入库
```
