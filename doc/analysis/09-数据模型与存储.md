## 〇、摘要

1. **无传统关系数据库**：真相源 = 向量库（Milvus/FAISS）+ `data/` 下的一组 JSON/JSONL/SQLite 文件；领域模型集中在 `app/domain/schemas.py` 一个文件（16 个 Pydantic 模型），字段按"将来要进数据库"的标准设计（`app/domain/schemas.py:1-5`）。
2. **三处存储损坏即拒绝启动**：文档元数据、向量索引、DocStore——宁可起不来，不以脏数据对外服务（`app/services/knowledge.py:110-125`、`app/services/vectorstore.py:61-76`、`app/services/docstore.py:27-36`）。原「ACL / 知识库实体与授权 / 用户目录」三处随之整体下线（2026-11-12），不再有权限类数据需要"拒绝以空集对外服务"。
3. **索引版本化是核心一致性机制**：`chunk_id` 形如 `{doc_id}@v{n}#{seq}`，reparse 改名旧块保留供溯源，全局 `index_version` 进缓存键——知识库任何变更使旧缓存自然失效（`app/services/vectorstore.py:28-49`、`app/services/knowledge.py:591-629`、`:79-91`）。
4. **原子写是全域纪律**：metadata / docstore / index_alias / sessions / tasks / FAISS 落盘全部走"临时文件 + replace"（如 `app/services/knowledge.py:126-137`、`app/services/index_alias.py:54-58`）。
5. **会话 30 天 TTL、快问临时文档 2 小时 TTL、入库任务终态记录 30 分钟淘汰、Agent 检查点 7 天 TTL**（后两者分别见 `app/services/ingest.py:239-270`、`backend/app/assembly/agent.py:196-225`）；仍无 TTL 的是 `data/ingest/<task_id>/` 源文件与 `data/assets/`（见「八」）。
6. **图存储默认 SQLite（WAL）**，旧 `graph.json` 启动时自动迁移并改名备份不删除（`app/services/graph/sqlite_store.py:483-519`）。

连 `tests/data/eval/` 一起排除掉（表现是"本地能跑、CI 上没有这份数据"，且 git 不报错）。
守卫测试 `tests/unit/test_multimodal_corpus.py` 与 `test_eval_metrics.py` 守住这条边界。

**状态外置（多副本语义）**：

| 状态 | 落地形态 | 说明 |
|---|---|---|
| 会话 | 共享状态（JSON 文档 + zset 索引） | **只在配置了 Redis 时外置**；未配置时用本地文件 |
| 检索配置（含灰度覆盖层） | 同上 | 外置模式**读穿透**（每次读刷新）——只加载一次会让副本看旧快照 |
| 入库任务 | 同上 | 任务状态与进度跨副本可见 |
| 指标 | Prometheus HTTP API（回落进程内） | 响应带 `source` 字段，说明看的是哪个副本 |
| 检查点 | 本地 SQLite + `prune_checkpoints(before_ts)` | 已在装配期挂周期任务（保留 7 天 / 每小时一轮，`backend/app/assembly/agent.py:196-225`）；此前**只增不减**（磁盘泄漏） |
| 图谱 | SQLite（复合主键 + 迁移） | KQ-06 修复：跨租户不再互相覆盖 |

**新增存储原语**：`core/shared_state.py` 的 `zrange`（按分数取成员）、`zrem`（索引删成员）
——选 zset 而不是 SCAN：SCAN 在大 keyspace 上不保证一次拿全，而"最近 N 个会话"正是 zset 的强项。

## 一、领域模型全景

全部模型定义在 `app/domain/schemas.py`。模块 docstring 定了三条设计基调：标识稳定可组合、租户字段从第一天就存在、证据是一等实体（`:1-5`）——其中"租户字段"如今只是**数据分区键**，不再是鉴权依据（`Principal` 恒为 `default/local`，见 `10-可观测性与成本.md` 与 `app/core/identity.py`）。

### 1.3 分模块要点

- **知识资产**（DocumentRecord / Chunk / TableRecord / MediaAsset）：`chunk_count` 入库后回填用于完整性校验；`short_chunk_count` 是质量红线（占比 >10% 需调切块参数）；`version` 重新解析时 +1，旧版本块保留供历史引用溯源（`schemas.py:17-37`）。Chunk 冗余存 `tenant_id`，检索时一次过滤完成（`schemas.py:38-61`）；`injection_risk` / `injection_hits` 是入库期打的注入风险标记，检索侧**降权而非排除**（`schemas.py:55-60`）。
- **问答**（AskRequest / AskResult / Evidence / RetrievalStats / SelfCheckRecord）：拒答是一等公民（`verdict=refused` 走成功状态码）；`RetrievalStats` 同时产出平铺与嵌套两种形态，新旧消费者不必同步切换（`schemas.py:242-289`）。原 `acl_filtered` 计数随 ACL 下线移除（2026-11-12）。
- **运行配置**（RetrievalConfig）：变更不立即生效——先存 pending，到生效时刻晋升 active（`schemas.py:292-336`）；`with_fallbacks` 把存量 JSON 里缺失的新字段（值为 0）回落到全局配置，防止"检索突然什么都召不回"。

## 三、损坏即拒绝启动的存储

三类存储把"损坏"看得比"缺失"严重：缺失可以按空库起步，损坏意味着真相源不可信。

| 存储 | 拒绝启动条件 | 代码位置 |
|---|---|---|
| 文档元数据 `metadata.json` | 文件存在但 JSON 解析/模型校验失败 → `StorageCorruptedError("文档元数据文件损坏或格式非法")` | `app/services/knowledge.py:110-125` |
| 向量索引 `index.faiss` + `chunks.json` | 两文件都不存在 = 空索引启动；存在但读取失败、或**索引行数与元数据条数不一致** → 拒绝启动 | `app/services/vectorstore.py:61-76`（一致性校验在 `:72-73`） |
| DocStore `docstore.json` | JSON 损坏或模型校验失败 → `RuntimeError("DocStore 数据损坏，拒绝启动")` | `app/services/docstore.py:27-36` |

**已下线（2026-11-12）的三处**：ACL `acl.json`、知识库 `knowledge_bases.json` / `kb_grants.json`、用户目录 `users.json`。对应服务模块（`app/services/security/{acl,kb,auth}.py`）已删除，`data/` 下同名历史文件若存在也不再被读取——`app/core/config.py:795-803` 的 `users_file` 属性保留但 docstring 明写"认证已下线…新的代码不应使用它"。因此"权限数据不能以空集对外服务"这条拒绝启动理由随能力一起消失。

对照组（**不**拒绝启动）：`tasks.json` 损坏忽略重置（`ingest.py:139-161`）、会话文件损坏隔离后按不存在处理（`sessions.py:152-167`）、图 JSON 迁移失败用空库（`sqlite_store.py:506-519`）、检查点初始化失败降级内存（`checkpointer.py:31-68`）。取舍逻辑：拒绝启动留给"以坏数据服务会给出错误答案"的存储；可再生的派生数据一律降级而非阻断。

## 四、关键实体生命周期

### 4.1 文档（DocumentRecord）

```
上传/入库 ──→ uploaded ──→ parsing ──→ indexed ─┬─→ reparse：status→parsing，version+1，
  （同步 upload                        ↑        │   旧块改名 @v旧 保留供溯源，
   或异步 ingest）                     └────────┘   超出 index_version_keep 份才真删
        任处理态 ──→ failed（error 记录原因，可 rebuild 按原内容原策略重建）
indexed ──→ offline：删索引、chunk_count 归零，源文件与记录保留（knowledge.py:654-662）
indexed/offline ──→ delete：级联删除（见「七 · 7.3」）
```

- 状态常量：`schemas.py:11-14` + `offline`（`:64`）。
- reparse 的版本化纪律（`app/services/knowledge.py:591-629`）：旧实现先物理删旧块再重建、chunk_id 复用同一序号空间，导致历史答案里的引用全部指向不存在的块；现做法是先 `_retire_version`（`:630-652`）把当前版本块改名为 `@v{旧}` **不删除**，新块打 `@v{新}` 序号空间天然隔离，历史块不参与召回但可在预览接口按 chunk_id 直接溯源。
- rebuild 不改版本（chunk_id 稳定，`:576-589`）；每次版本变更 `_bump_version()`（`:86-91`）使旧缓存键失效。

### 4.2 会话（SessionStore，`app/services/agent/sessions.py`）

```
create（id = 租户:用户:随机号，防枚举，`make_session_id` :63-64）
  ──→ 每轮 save_turn：turn+1、快照截断（证据 ≤8 条、历史 ≤6 轮，:26-27）、expires_at 顺延 30 天（:253 起）
  ──→ 读取时过期即删文件并 410（:168-171）；list 时惰性清理过期快照（:173 起）
  ──→ delete：快照与锁一并删除，不留残留原文（:229 起）
```

## 七、跨存储一致性策略与已知残留

### 7.1 向量条数 == 块条数

FAISS 加载时强校验 `index.ntotal == len(order)`，不一致即拒绝启动（`app/services/vectorstore.py:71-72`）；写入侧 `add` 先校验 chunks 与 vectors 数量一致（`:96-97`）。入库纪律（嵌入整批中止时保留已完成向量，不允许半成品索引）见 `app/services/knowledge.py:10-11` 与 `06-入库与解析链路.md`。

### 7.2 BM25 与向量的版本一致性

BM25 索引**不独立持久化**：启动时从向量库全量块重建（`backend/app/assembly/storage.py:52-53`），天然与向量库同源同版本；召回前的版本过滤（历史 `@v` 块不参与召回）在融合前完成。快问临时块双写两侧，防止 RRF 退化为单路（`quickask.py:15`）。

### 7.3 删除的级联（`app/services/knowledge.py:676-735`）

`delete(doc_id)` 编排：purge 向量/BM25 块 → 移除文档记录 → best-effort 逐项清理派生副本（ACL 条目、图谱中来源块、图像索引、资产文件、任务文件）。单项失败**不中断整体删除**，失败项记入 residuals 写 warning 日志——运维据此做残留巡检。已知残留：图像索引 `remove_doc` 的清理不彻底（`app/services/graph/images.py:183-196`，缺口 7）。

### 7.4 无 TTL 的存储（登记为缺口）

| 存储 | 增长方式 | 现状 |
|---|---|---|
| `agent_checkpoints.db` | 每轮 Agent 运行若干行 | 无 TTL 清理（`checkpointer.py:17-18` 注释说明刻意不在装配期引入定时器，缺口 2） |
| `tasks.json` + `ingest/` | 每批入库一份记录 + 源文件 | 无清理（缺口 3） |
| `assets/` | 解析产物 | 仅随文档删除 best-effort 清理（缺口 4） |

有自限机制的对照组：会话（30 天 TTL）、快问（2h TTL + 清扫）、长期记忆（500 条/租户淘汰）、查询分析（1000 条）、校验历史（20MB×20 滚动）、FAISS/Milvus 历史版本块（`index_version_keep` 份数上限）。

### B. 状态机速查

- 文档：`uploaded → parsing → indexed / failed`；`indexed →(reparse, version+1)→ indexed`；`indexed → offline →（rebuild）→ indexed`；任意 → `delete`（级联）。
- 文件：`pending → uploading → queued → parsing → chunking → indexing → done / failed`；可取消阶段 = `{queued, parsing, chunking}`。
- 任务：`queued → running → done / partial_failed / failed / cancelled`；重启时 running 中的文件标 failed。
（常量定义：`app/domain/schemas.py:9-12`、`:85-107`）
