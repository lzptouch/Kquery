## 2. 实体抽取

### 2.1 基础用法

```python
from app.services.graph.entity_extraction import EntityExtractionService
from app.models.graph import EntityType

# 创建服务实例
service = EntityExtractionService()

# 从文本中抽取实体
text = """
张三是腾讯公司的技术总监，负责AI部门的管理工作。
他在清华大学获得计算机科学硕士学位，有15年的互联网从业经验。
"""

entities = await service.extract_entities(
    text=text,
    entity_types=[EntityType.PERSON, EntityType.ORGANIZATION, EntityType.TECHNOLOGY, EntityType.LOCATION],
    strategy=ExtractionStrategy.HYBRID  # 混合模式（LLM + 规则）
)

for entity in entities:
    print(f"实体: {entity.name}")
    print(f"类型: {entity.type.value}")
    print(f"置信度: {entity.confidence}")
    print("---")
```

### 2.2 实体类型过滤

```python
# 只抽取人名和组织
entities = await service.extract_entities(
    text=text,
    entity_types=[EntityType.PERSON, EntityType.ORGANIZATION]
)

# 只抽取技术相关实体
entities = await service.extract_entities(
    text=text,
    entity_types=[EntityType.TECHNOLOGY, EntityType.PRODUCT, EntityType.CONCEPT]
)

# 抽取所有类型
entities = await service.extract_entities(
    text=text,
    entity_types=None  # None表示所有类型
)
```

### 2.3 实体消歧

```python
# 启用实体消歧
entities = await service.extract_entities(
    text=text,
    enable_disambiguation=True  # 启用消歧
)

# 消歧策略：
# - 同名消歧：根据上下文选择最合适的实体
# - 指代词消歧：解析"他"、"她"等指代
# - 缩写消歧：识别全称和缩写的对应关系
```

## 3. 关系抽取

### 3.1 基础用法

```python
from app.services.graph.relation_extraction import RelationExtractionService
from app.models.graph import RelationType

# 创建服务实例
service = RelationExtractionService()

# 已抽取的实体
entities = [
    Entity(id="e1", name="张三", type=EntityType.PERSON),
    Entity(id="e2", name="腾讯公司", type=EntityType.ORGANIZATION)
]

# 从文本中抽取关系
text = "张三是腾讯公司的技术总监"

relations = await service.extract_relations(
    text=text,
    entities=entities,
    relation_types=[RelationType.EMPLOYEE_OF, RelationType.MANAGER_OF],
    strategy=ExtractionStrategy.HYBRID  # 混合模式（LLM + 规则）
)

for relation in relations:
    print(f"关系: {relation.source_entity_id} -[{relation.relation_type}]-> {relation.target_entity_id}")
    print(f"置信度: {relation.confidence}")
    print("---")
```

### 3.2 关系类型过滤

```python
# 只抽取雇佣关系
relations = await service.extract_relations(
    text=text,
    entities=entities,
    relation_types=[RelationType.EMPLOYEE_OF, RelationType.MANAGER_OF]
)

# 抽取所有类型的关系
relations = await service.extract_relations(
    text=text,
    entities=entities,
    relation_types=None
)
```

### 3.3 关系验证

```python
# 启用关系验证
relations = await service.extract_relations(
    text=text,
    entities=entities,
    enable_validation=True  # 启用验证
)

# 验证检查：
# - 实体存在性验证
# - 关系类型合法性验证
# - 语义合理性验证
# - 方向合理性验证
```

## 5. 图谱查询

### 5.1 实体查询

```python
from app.services.graph.graph_query import GraphQueryService

# 创建服务实例
service = GraphQueryService(
    graph_client=Neo4jConnector(),
    query_cache=QueryCache(),
    query_optimizer=QueryOptimizer()
)

# 精确查询
entities = await service.query_entity(
    entity_name="腾讯公司",
    entity_type=EntityType.ORGANIZATION,
    collection_name="default",
    fuzzy=False
)

print(f"找到 {len(entities)} 个实体")

# 模糊查询
entities = await service.query_entity(
    entity_name="腾讯",
    entity_type=None,  # 不限制类型
    collection_name="default",
    fuzzy=True  # 启用模糊匹配
)
```

### 5.2 邻居查询

```python
# 查询1跳邻居
graph = await service.query_neighbors(
    entity_id="entity_tencent_001",
    relation_types=None,  # 所有关系类型
    direction="both",  # inbound + outbound
    depth=1,
    limit=10,
    collection_name="default"
)

# 查询2跳邻居
graph = await service.query_neighbors(
    entity_id="entity_tencent_001",
    relation_types=[RelationType.EMPLOYEE_OF],
    depth=2,
    limit=20,
    collection_name="default"
)

print(f"找到 {len(graph.nodes)} 个节点")
print(f"找到 {len(graph.edges)} 条边")
```

### 5.3 路径查询

```python
# 查询最短路径
paths = await service.query_path(
    source_entity_id="entity_zhang_san_001",
    target_entity_id="entity_pony_ma_001",
    max_depth=3,
    relation_types=None,
    collection_name="default"
)

for path in paths:
    print(f"路径: {' -> '.join(node.name for node in path.nodes)}")
    print(f"长度: {len(path.nodes)}")
    print("---")
```

### 5.4 图谱语义检索（Local / Global / Hybrid）

自然语言层面的图谱推理由 `GraphQueryService` 的图检索方法与 GraphRAG 引擎共同承担（`app/services/graph/graph_query.py` 提供 `LocalSearchResult` / `GlobalSearchResult` / `HybridGraphSearchResult`；`app/services/graphrag/graphrag_engine.py` 负责查询实体抽取与图谱上下文扩展）。

```python
from app.services.graph.graph_query import GraphQueryService

service = GraphQueryService(
    graph_client=Neo4jConnector(),
    query_cache=QueryCache(),
    query_optimizer=QueryOptimizer()
)

# 以实体为中心的局部检索（Local Search）
local = await service.local_search(
    entity_id="entity_zhang_san_001",
    depth=2,
    collection_name="default"
)

print(f"局部子图节点数: {len(local.nodes)}")
```

> 面向"张三的同事是谁？"这类自然语言问题，推荐直接调用 GraphRAG 的 `POST /api/v1/graphrag/ask`（见 6 与 7.5），由引擎完成问题分类 → 实体抽取 → 图谱扩展 → 融合。

## 6. GraphRAG集成

### 6.1 基础用法

```python
from app.services.graphrag.graphrag_engine import GraphRAGEngine

# 创建引擎实例
service = GraphRAGEngine(
    rag_service=rag_service,
    graph_service=GraphQueryService(),
    entity_extractor=EntityExtractionService(),
    reranker=RerankerService()
)

# GraphRAG查询
result = await service.query_with_graph(
    query="张三在腾讯公司担任什么职位？",
    collection_name="default",
    top_k=5,
    enable_graph=True,  # 启用图谱检索
    enable_hyde=True  # 启用HyDE
)

print(f"查询: {result.query}")
print(f"返回结果: {len(result.results)} 个")
print(f"查询实体: {result.query_entities}")

# 显示图谱相关实体
for entity in result.query_entities:
    print(f"图谱实体: {entity.name}")
```

### 6.2 结果融合

```python
# 融合策略：
# - 向量相似度 * 0.6 + 图谱相关度 * 0.4
# - 优先返回与查询实体相关的结果
# - 提升相关结果的分数（1.2倍）

# 结果示例
result.results[0].score = 0.85  # 图谱相关结果，分数提升
result.results[1].score = 0.70  # 普通向量结果
result.results[2].score = 0.75  # 图谱相关结果，分数提升
```

## 7. API接口

> 所有知识图谱 API 已实现于 `backend/app/api/knowledge_graph.py`（前缀 `/api/v1/graph`），GraphRAG API 已实现于 `backend/app/api/graphrag.py`（前缀 `/api/v1/graphrag`）。完整清单见 `doc/接口设计/接口设计文档.md` 第 7、8 章。

### 7.1 知识图谱端点一览（/api/v1/graph）

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/graph/entities` | 检索/列出实体 |
| `GET` | `/graph/entities/{entity_id}` | 实体详情 |
| `POST` | `/graph/entities/build` | 从文本抽取并构建图谱 |
| `POST` | `/graph/build-from-collection` | 从整个集合构建图谱 |
| `GET` | `/graph/check-collection` | 检查集合图谱构建状态 |
| `GET` | `/graph/entities/{entity_id}/neighbors` | 邻居查询 |
| `GET` | `/graph/path` | 两实体间路径 |
| `POST` | `/graph/subgraph` | 抽取子图 |
| `POST` | `/graph/visualization` | 可视化数据 |
| `GET` | `/graph/algorithms/pagerank` | PageRank |
| `GET` | `/graph/algorithms/communities` | 社区发现 |
| `GET` | `/graph/statistics` | 图谱统计 |
| `GET` | `/graph/schema` | 图谱 Schema（22 实体 + 25 关系） |
| `GET` | `/graph/lineage/{document_id}` | 文档数据血缘 |

### 7.5 GraphRAG 检索与问答（/api/v1/graphrag）

## 8. 最佳实践

### 8.1 性能优化

1. **批量处理**
   - 批量抽取实体，减少LLM调用次数
   - 批量插入关系，优化数据库写入
   - 批量查询，提升吞吐量

2. **缓存策略**
   - 缓存常用实体
   - 缓存常见查询
   - 缓存LLM响应

3. **异步处理**
   - 所有IO操作使用async/await
   - 并行执行独立任务

### 8.2 数据质量

1. **实体消歧**
   - 始终启用实体消歧
   - 提供实体别名列表
   - 维护实体上下文

2. **关系验证**
   - 启用关系验证
   - 验证语义合理性
   - 检查方向性

3. **图谱一致性**
   - 定期验证图谱一致性
   - 清理孤儿节点
   - 修复错误关系

### 8.3 可扩展性

1. **插件化设计**
   - 支持自定义实体类型
   - 支持自定义关系类型
   - 支持自定义抽取规则

2. **多提供商支持**
   - 支持阿里云和科大讯飞
   - 支持扩展其他提供商
   - 使用Provider模式

## 9. 常见问题

### 9.1 实体抽取

**Q: 实体抽取不准确怎么办？**
- 调整LLM temperature参数
- 提供更多上下文信息
- 使用混合策略（LLM + 规则）
- 增加实体消歧

**Q: 如何添加自定义实体类型？**
```python
class CustomEntityType(EntityType):
    CUSTOM_TYPE = "custom_type"
```

### 9.2 关系抽取

**Q: 关系抽取遗漏怎么办？**
- 增加关系类型覆盖
- 提供更多示例
- 调整置信度阈值
- 使用混合策略

**Q: 关系方向错误怎么办？**
- 验证关系方向的合理性
- 检查语义上下文
- 使用关系验证规则

### 9.3 图谱查询

**Q: 查询速度慢怎么办？**
- 优化图数据库索引
- 使用缓存机制
- 限制返回结果数量
- 使用分页查询

**Q: 多跳查询超时怎么办？**
- 限制最大跳数
- 优化查询语句
- 使用路径优化算法

## 10. 从知识图谱生成思维导图（已实现）

> 该能力已落地于 `backend/app/api/mindmap_router.py`（前缀 `/api/v1/mindmap`）。KQuery Pro 的差异化优势：直接复用已构建的 Neo4j 知识图谱生成思维导图，避免重复 LLM 抽取。内部复用 `app/services/graph/graph_query.py`。

### 10.1 图谱驱动生成（从实体）

```
GET /api/v1/mindmap/from-entity/{entity_id}?max_depth=2
```

```json
// 响应（MindMapResponse）
{
  "root": "腾讯公司",
  "branches": [
    { "label": "员工", "children": ["张三", "马化腾"] },
    { "label": "产品", "children": ["微信", "QQ"] }
  ]
}
```

### 10.2 LLM 驱动生成（从文本 / 笔记）

```
POST /api/v1/mindmap/from-text          # body: { "text": "总结本周客户跟进要点：..." }
POST /api/v1/mindmap/from-note/{note_id}?max_depth=3
GET  /api/v1/mindmap/export/{entity_id} # 导出 Markdown 大纲
```

### 10.3 输出与渲染

- `mermaid`：直接粘贴到支持 Mermaid 的编辑器 / 前端组件渲染
- `json`：自定义渲染或导出为 XMind / Markdown 大纲

```json
{
  "root": "腾讯公司",
  "branches": [
    { "label": "员工", "children": ["张三", "马化腾"] },
    { "label": "产品", "children": ["微信", "QQ"] }
  ]
}
```

### 10.4 最佳实践

- 已有知识库优先走图谱驱动（成本低、结构稳定）
- 长分支使用 `prune_threshold` 剪枝，避免导图过载
- 多租户场景务必传入 `collection_name`，复用 `kb_id` 隔离
- 生成结果建议落库（SQLite `notes` / `mindmap` 表），支持二次编辑
