# 事件分级与升级路径

> 分级的唯一作用是回答一个问题：**「现在要不要叫醒人，叫醒谁」。**

## 分级定义

| 级别 | 定义 | 用户影响 | 响应时限 | 叫人 |
|---|---|---|---|---|
| **P0** | 服务整体不可用 / 数据损坏 / 凭据泄漏 | 全部用户无法使用，或数据不可信 | **15 分钟** | 一线 + 二线 + 决策者，立即 |
| **P1** | 核心功能显著降级（问答大面积 5xx / 延迟 > 3× 基线） | 大部分用户受影响 | **1 小时** | 一线 + 二线 |
| **P2** | 局部功能不可用（非核心端点）、单个租户异常 | 部分用户受影响 | **4 小时**（工作时间内） | 一线 |
| **P3** | 可绕过的缺陷、有降级但体验明显变差 | 少数用户感知 | **1 个工作日** | 记录，不用叫人 |
| **P4** | 优化项、技术债 | 无直接用户影响 | 进 backlog | 记录 |

## 定级规则

1. **按用户影响定级，不按技术原因定级**。
   「向量库连接超时」是原因；「所有问答返回 502」是症状——**按后者定级**。
2. **不确定时取高一级**。P1 与 P2 之间犹豫 → 定 P1；
   理由：升级成本是多叫一个人，漏判的成本是用户多等两小时。
3. **同一事故只定一个级别**，后续按影响变化**调整**（并在复盘里记录调整过程）。
4. **数据类问题一律不低于 P1**：数据错了比服务慢了严重——
   错误的答案会被用户当作事实使用。

## 升级路径

```
一线（值班同学）
  │  P0 / P1：15 分钟内未恢复 → 二线
  │  P0：立即同时通知决策者
  ▼
二线（模块负责人）
  │  30 分钟内未恢复 → 决策者
  │  需要回滚 / 数据修复 → 决策者批准
  ▼
决策者（技术负责人）
     决定：继续修 / 回滚 / 降级对外口径 / 结束事件
```

| 角色 | 职责 | 到位时限 |
|---|---|---|
| 一线 | 按处置卡执行、确认影响面、记录时间线 | 告警触发后立即 |
| 二线 | 定位根因、给出处置方案 | P0 15 分钟 / P1 1 小时内 |
| 决策者 | 批准回滚与数据修复、对外通报 | P0 立即 / P1 1 小时内 |

## 对外通报口径

- **只说用户能感知的事**：「部分问答请求失败」而不是「Milvus 连接池耗尽」。
- **不确定影响面时说「正在确认」**，不要猜（「数据库可能挂了」会引发不必要的用户侧动作）。
- **P0/P1 结束时必须给结论**：恢复时间 + 是否有数据影响 + 后续动作。

## 时间线记录（复盘要用）

值班期间随手记，每 5 分钟一条就够：

```
23:04  告警 KqueryHighErrorRate 触发
23:06  定级 P1，确认影响面：全部问答失败（5xx 比例 100%）
23:12  定位：向量库连接失败（健康检查 down）
23:20  处置：切换到备用向量库（配置切换，已回滚验证）
23:23  恢复：错误率回落到 0.2%
```

复盘只看这条时间线——**没有时间线的复盘会变成甩锅会**。
