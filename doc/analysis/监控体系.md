### 1.3 告警（Alerting）—— 平台配额监控（阶段 9）

`PlatformQuotaMonitor`（`app/services/security/platform_quota.py`）：

```python
class PlatformQuotaMonitor:
    def __init__(self, per_day, warn_ratio):
        self._limit = per_day
        self._warn_ratio = warn_ratio  # 0.8 = 80% 告警
        self._usage = 0
    
    def report(self, tokens: int):
        self._usage += tokens
        ratio = self._usage / self._limit
        if ratio >= self._warn_ratio:
            logger.warning(f"平台配额接近上限: {ratio:.1%}")
```

**关键设计**：模型客户端上报 token 用量 → `install_monitor` 注入到 gateway → 监控接近上限告警。

### 1.4 链路追踪（Tracing）

`app/core/tracing.py` 的 `new_trace_id()`：

```python
import uuid

def new_trace_id() -> str:
    return f"tr_{uuid.uuid4().hex[:12]}"
```

**trace_id 贯穿**（当前实现）：
- trace 中间件（`@app.middleware("http")`）为**每个请求**生成/复用 `X-Trace-Id`，写入 contextvar 并在响应头回带——正常路径同样贯穿
- 信封 `meta.trace_id`、日志 `trace_id=...`、SSE 事件均携带同一 trace_id
- 跨线程经 `app/core/tracing.py` 的 `spawn_thread` 传递（入库 worker / 报告队列）
- OTel 已接入（`app/core/otel.py`，TASK-132）：检索/生成阶段 span + token 用量属性；未配置 endpoint 时静默降级 NoOp

## 二、设计原则与原理剖析

### 1. 业务指标 vs 系统指标分层

| 层 | 工具 | 用途 |
|---|---|---|
| **系统指标** | prometheus_client 默认（python_gc / process_*） | 进程级 CPU / 内存 / FD / GC |
| **业务指标** | `MetricsStore` + `PromMetrics` | 业务级（ask 计数 / LLM 调用 / 配额） |

> **关键设计**：业务指标独立于 prometheus_client，避免 prometheus_client 升级 / 配置变更影响业务埋点。

### 2. trace_id 双层含义

Kquery 的 `trace_id` 是 **error envelope 内的业务 trace_id**，区别于 OTel 的 `trace_id`：

| 类型 | 用途 | 实现 |
|---|---|---|
| **业务 trace_id** | 错误排查 / 客服工单关联 | `new_trace_id()` 生成 → envelope |
| **OTel trace_id** | 完整请求链路追踪 | 未实施（阶段 10 演进） |

> **进一步方向**：阶段 10 引入 OTel SDK，把业务 trace_id 与 OTel trace_id 关联。

### 3. 平台配额 vs 应用配额分层

| 层 | 工具 | 触发位置 |
|---|---|---|
| **平台配额**（千问账号） | `PlatformQuotaMonitor` | 模型客户端 token 上报 |
| **应用配额**（租户） | `SlidingWindowQuota` | 端点 Depends 检查 |
| **API 限流**（用户 / IP） | `TokenBucketLimiter` | 端点 Depends 检查 |

**关键设计**：三层独立，任一超额即独立反馈（429 + 不同错误码）。

### 4. 健康探针缺口

当前 `/health` 仅返回 `{"status": "up"}`，K8s 三级探针模型未实现：

| 探针 | 当前 | 建议 |
|---|---|---|
| `/health/live` | ❌ 无 | 仅存活（无依赖检查） |
| `/health/ready` | ❌ 无 | 探 Milvus / Redis / 千问 |
| `/health` | ✅ 仅返回 `{"status": "up"}` | 综合探针 |

> **进一步方向**：阶段 10 引入 K8s 部署时补三级探针。

import json

class JsonFormatter(logging.Formatter):
    def format(self, record):
        return json.dumps({
            "ts": record.created,
            "level": record.levelname,
            "name": record.name,
            "message": record.getMessage(),
