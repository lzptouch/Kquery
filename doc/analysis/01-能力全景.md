## 〇、摘要

1. **Kquery 已是一个「有默认关闭项的完整 RAG 系统」**：能力域覆盖 D1~D10 共 101 条能力，其中 74 条默认可用、24 条有条件可用、2 条不可用、1 条已下线——但「有条件可用」里集中了 ReAct、HITL、独立 verify 节点、OTel、降级阶梯等最容易被误认为「已经支持」的能力。
2. **混合检索是本项目唯一同时满足「有生产调用点 + 默认开启 + 有主路径测试」三条硬规则的重能力**：`HybridRetriever.search_multi` 是管线内唯一的检索入口（`backend/app/services/retrieval/hybrid.py:101`），默认双路开启，并有 `backend/tests/integration/test_stage2.py` 覆盖主路径。
3. **Agent 侧的三条「进阶」通道全部默认关闭**：ReAct 仅在 `agent_mode=="react"` 时才装配 thinker（`backend/app/services/agent/runner.py:153-155`），默认 `agent_mode="plan_execute"`（`backend/app/core/config.py:152`）；HITL 默认 `agent_hitl_enabled=False`（`backend/app/core/config.py:134`）；独立 verify 节点默认 `agent_verify_enabled=False`（`backend/app/core/config.py:164`）。
4. **检索质量是「有机制无度量」的典型**：混合检索、RRF 融合、重排降级、ACL 下推一应俱全，但**不存在检索金标集**，recall@k / nDCG 无从测量，混合检索相对单路的增益没有任何数据支撑。
5. **快问（F4）能力存在但受限**：`req.doc_id` 存在时强制走线性路径，因为 Agent 路径的检索未接 `doc_id` 过滤（`backend/app/api/ask.py:53-58`）；且 `redis_url` 默认空时快问临时态只在本进程内（`backend/app/core/config.py:158`），多副本之间互不可见。
6. **两条外部依赖型能力处于「不可用」态**：SQL 业务库工具与联网搜索工具在 `sql_dsn` / `web_search_endpoint` 为空时**根本不注册**（`backend/app/main.py:464-487`），因此在默认部署中这两项能力不存在。
7. **知识库实体与逐用户授权是 2026-10-27~28 新落地的能力**：KB 作为文档的上位容器，管理员按 `user_id` 授权；KB 判定合并进 `acl_filter_of` 兜底闭包（`backend/app/dependencies.py:92-111`），与文档 ACL 叠加取交集，撤权通过复合版本号使旧缓存立即失效（`backend/app/main.py:417`）。它默认开启，但**只有用户粒度**，且与 `acl_enabled` 强耦合——详见 D7-8~D7-10。

## 二、逐域能力清单

> **状态判据**（唯一标准，见 `README.md` §「关键数字」与本篇第五章）：✅ 可用 = 有生产调用点 + 默认配置即可工作 + 有覆盖主路径的测试，三条全满足；⚠️ 有条件可用 = 默认关闭 / 有机制无度量 / 已知缺口，满足其一即降级；⛔ 不可用 = 无生产调用点或依赖外部系统未配置且无降级；🚫 已下线 = 代码已删除。
> **三条硬规则**：①「有代码」≠「可用」，只被测试调用的最高 ⚠️；② 默认关闭一律 ⚠️；③ 「有机制无度量」一律 ⚠️。
