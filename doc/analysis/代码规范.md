### 3.2 错误处理

`app/core/envelope.py` 定义 `ApiError` 与 `error_envelope()`：

```python
class ApiError(Exception):
    def __init__(self, code: str, message: str, http_status: int = 400, data: dict = None, retry_after: int = None):
        self.code = code
        self.message = message
        self.http_status = http_status
        self.data = data or {}
        self.retry_after = retry_after

# main.py
@app.exception_handler(ApiError)
async def api_error_handler(request: Request, exc: ApiError) -> JSONResponse:
    trace_id = new_trace_id()
    envelope = error_envelope(exc.code, exc.message, trace_id, 0)
    headers = {}
    if exc.retry_after is not None:
        headers["Retry-After"] = str(exc.retry_after)
    return JSONResponse(status_code=exc.http_status, content=envelope.model_dump(), headers=headers)
```

## 五、模型基线（强制约定）

Kquery 全系列**统一使用阿里云百炼（DashScope）千问平台**，**不得引入本地模型**：

| 能力 | 平台模型 |
|---|---|
| 生成 / 规划 / 评审 / 判定 | qwen-plus（默认）、qwen-max（复杂推理）、qwen-turbo（高频轻量） |
| 文本向量 | text-embedding-v3（1024 维） |
| 重排 / 证据相关度 | gte-rerank-v2 |
| 图文理解 | qwen-vl-max / qwen-vl-plus |
| OCR | qwen-vl-ocr |
| 语音转写 | paraformer-v2 |

**关键设计**：
- 阶段 7 放弃双塔对比模型（CLIP/BGE-VL），改为「qwen-vl-max 生成结构化描述 → text-embedding-v3 编码」→ 统一向量空间
- 阶段 9 评测必须绑定评测集版本 + 千问档位版本
- 阶段 9 新增「平台凭证管理」（密钥托管 / 双凭证轮换 / 启动期只校验格式）

## 六、设计原则小结

1. **阶段递进**：每阶段在上一阶段基础上增量
2. **统一向量空间**：放弃双塔对比模型，图像描述走文本向量
3. **模型分层**：qwen-turbo / qwen-plus / qwen-max 按成本分层
4. **运行时配置**：RetrievalConfigStore 支持热更新
5. **企业级护栏（阶段 9）**：认证 / 配额 / ACL / 敏感词 / 审计
6. **三层熔断**：单次迭代 / 整个 pipeline / 单 LLM 调用
7. **真相源 = FAISS / Milvus + JSON 文件**：无传统关系数据库
