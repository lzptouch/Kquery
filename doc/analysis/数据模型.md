## 0. 摘要（一句话）

Kquery 数据模型按 **9 阶段递进** 组织，**真相源**由 FAISS / Milvus 向量库 + 文件系统 JSON 共同构成（无传统关系数据库），**派生端**有语义缓存、补全缓存、检索配置； 引入 ACL / 配额 / 审计等企业级护栏。

## 1. 模型分层架构

### 1.1 三层职责

| 层 | 文件 | 职责 | 关键类型 |
|---|---|---|---|
| **应用层** | `app/services/{pipeline,agent,graph,query}/` | 业务模型（请求 / 响应 / 状态机） | `RagRequest`、`AgentState` |
| **存储层** | `app/services/{vectorstore,docstore,cache,config_store}.py` + `app/services/agent/sessions.py` | FAISS / Milvus / JSON 文件 | `VectorStore`、`DocStore`、`SessionStore` |
| **护栏层** | `app/services/security/{auth,password,acl,quota,sensitive,audit,platform_quota}.py` |  企业级数据 | `ACLService`、`SlidingWindowQuota`、`SensitiveScanner`、`UserDirectory` |

### 1.2 模型流转

```
HTTP Request
  │ (Pydantic model: RagRequest / AgentRequest)
  ▼
Route (api/*.py)
  │ → service 编排
  ▼
Service (services/*)
  │ (业务模型: PipelineState / AgentState)
  ▼
Storage (vectorstore / docstore / cache / sessions)
  │ (FAISS index / Milvus Collection / JSON file)
  ▼
FAISS / Milvus / JSON file
  │
  ▼ (业务响应模型)
HTTP Response (含 trace_id / evidence / verdict)
```

### 2.9 企业级护栏

#### `ACLService`（`app/services/security/acl.py`）

```python
class ACLService:
    def __init__(self, acl_path, user_directory):
        self._acl: dict[str, list[str]] = {}  # doc_id → allowed user_ids
        self._deny: dict[str, list[str]] = {}  # doc_id → denied user_ids
        self._user_directory: list[Principal] = user_directory
```

**核心规则**：
- 默认拒绝（用户不在 `_acl[doc_id]` → 拒绝）
- deny 优先（同时在 allowed 和 denied → 拒绝）

#### `UserDirectory`（`app/services/security/auth.py`）—— 用户目录持久化

```python
class UserDirectory:
    def __init__(self, path: Path, initial: list[dict] | None = None):
        # path = settings.users_file → data/users.json
        # initial = auth_users_json 解析结果（仅首次为空时的种子）
    def upsert(self, user_id, patch): ...   # 跳过 user_id/tenant_id，其余任意 key 落盘
    def set_password(self, user_id, encoded): ...   # 仅写入哈希
```

**记录字段**（每条）：`user_id`（主键）/ `tenant_id` / `roles` / `groups` / `enabled` / `password_hash`（可选）。

**口令哈希格式**（`password.py`，零第三方依赖）：

```
pbkdf2_sha256$<iterations>$<salt_b64>$<hash_b64>
```

- 600 000 轮（实测约 60 ms/次）；轮数写在记录里，调参后旧口令仍可校验
- `verify_password` 用 `hmac.compare_digest` 常量时间比较；`encoded` 非法或为空一律返回 False（不区分"未设口令"与"口令错"，否则账号状态可被探测）
- 登录时对不存在的用户也执行一次哈希（`burn()`），抹平用户枚举的时序侧信道

#### `PlatformQuotaMonitor`（`app/services/security/platform_quota.py`）

```python
class PlatformQuotaMonitor:
    def __init__(self, per_day, warn_ratio):
        self._limit = per_day
        self._warn_ratio = warn_ratio  # 0.8 = 80% 告警
        self._usage = 0  # 模型客户端上报
    
    def report(self, tokens: int):
        self._usage += tokens
        ratio = self._usage / self._limit
        if ratio >= self._warn_ratio:
            logger.warning(f"平台配额接近上限: {ratio:.1%}")
```

## 4. 索引与检索参数

### 4.1 FAISS（demo）

```python
# app/services/vectorstore.py
self.index = faiss.IndexFlatL2(dim)
self.index.add(np.array(vectors, dtype=np.float32))
```

- **IndexFlatL2**：精确 L2 距离，无近似
- 优势：实现简单，结果准确
- 局限：>100k 向量性能下降

### 4.2 Milvus（生产）

```python
# app/services/milvus_store.py
collection = Collection(name="kquery_chunks")
collection.create_index(
    field_name="embedding",
    index_params={
        "metric_type": "COSINE",
        "index_type": "HNSW",
        "params": {"M": 16, "efConstruction": 200},
    },
)
```

- **HNSW**：层次导航小世界图，召回率高
- **M=16**：每节点最大连接数
- **efConstruction=200**：构建时搜索深度

## 5. 数据生命周期

### 5.1 文档生命周期

```
上传 (POST /knowledge/ingest 异步任务 或 POST /knowledge/upload 同步)
  ↓ multipart 解析 + 扩展名/大小/PII 硬拦截
解析 (ParserRouter)
  ↓ PDF → 文本 + 表格 + 图片; Docx → 段落; 音频 → 转写
分块 (Chunker: recursive / semantic / parent_child / raptort)
  ↓ chunks = [chunk_1, chunk_2, ...]
向量化 (text-embedding-v3, 1024 维)
  ↓ vectors = [[...], ...]
入库 (FAISS.add / Milvus.insert)
  ↓ doc_id + chunk_ids 写入 DocStore
可检索
  ↓ delete / reindex
归档 / 重建
```

### 5.2 Agent 会话生命周期

```
用户发起 Agent 任务 (POST /ask 或 /ask/stream，mode="agent" 或带 session_id)
  ↓ session_id 新建或续接（thread_id 前缀即归属凭证）
Plan (LLM Planner)
  ↓ plan_steps = [{tool: vector_search, ...}]
Tool 执行 (并行 / 串行)
  ↓ tool_results = [...]
Reflect (Reflector)
  ↓ verdict = supported / partial / unsupported
Replan (if needed)
  ↓ ...
Answer (Answer LLM)
  ↓ final_answer
写入 SessionStore (sessions/{session_id}.json)
```

### 5.3 ACL 决策生命周期

```
用户请求文档 (user_id)
  ↓
ACL.check(user_id, doc_id)
  ↓
  ├─ user_id in _acl[doc_id]? 否 → ❌ 默认拒绝
  ├─ user_id in _deny[doc_id]? 是 → ❌ deny 优先
  └─ 通过 → ✅ 允许
  ↓
  audit 事件（仅哈希）
```

## 6. 设计原则与原理剖析

### 6.1 真相源 = FAISS / Milvus + JSON 文件

Kquery 不用传统关系数据库；数据全部存文件系统（JSON）+ 向量库：

| 数据 | 存储 |
|---|---|
| 向量 | FAISS / Milvus |
| 切片文本 + 元数据 | 随向量一起存 Milvus / FAISS metadata |
| 文档 / 表格 / 媒体 | JSON 文件 |
| 配置 / 分析 / 反馈 | JSON 文件 |
| 会话 / 图谱 / 报告 | JSON 文件 |
| 用户 / ACL / 配额 |  JSON / Keychain |

> **优势**：零数据库依赖、演示友好、易调试
> **代价**：无事务、无 SQL 查询；规模扩大需切 Postgres / SQLite

### 6.2 阶段化数据模型：每阶段增量

每阶段在上一阶段的数据模型基础上增量：
- `KnowledgeChunk` + `VectorStore`
- + `RetrievalConfig` + `SemanticCache`
- + `DocStore`（parent / table / media）+ `ParserRouter`
- + `QueryAnalysis`
- + `FeedbackRecord`
- + `Session` + `ToolCall`
- + `Entity` + `Relation` + `Community` + `EntityResolver`

### 6.3  护栏设计原则

**默认拒绝 + deny 优先**：
```python
if user_id not in self._acl.get(doc_id, []):
    return False  # 默认拒绝
if user_id in self._deny.get(doc_id, []):
    return False  # deny 优先
return True
```

**审计最小化**：
- 仅存 payload 哈希 + 必要字段（user_id / timestamp）
- 原始 payload 不落盘 → 满足 GDPR / 等保 2.0 最小化原则

**平台配额 vs 应用配额分层**：
- **平台配额**：千问账号级（模型客户端上报 → 监控）
- **应用配额**：租户滑动窗口（每分钟 / 每天）

# app/services/security/sensitive.py

避免 "中华人民共和国居民身份证" 被 "身份证" 先匹配掩码。

### 6.5 评测门禁：pass_rate / cost / latency 三指标

> ⚠️ **已下线**：`EvalRunner`（`evalrunner.py`）已随评测平台移除，本节仅作历史设计参考。

```python
# app/services/security/evalrunner.py
class EvalRunner:
    async def compare(self, baseline_id: str, current_id: str) -> dict:
        base = self.store.get(baseline_id)
        cur = self.store.get(current_id)
        
        pass_rate_delta = cur.pass_rate - base.pass_rate
        cost_ratio = cur.cost / base.cost
        latency_ratio = cur.latency / base.latency
        
        verdict = "pass"
        if pass_rate_delta < -0.02:  # 回归 >2%
            verdict = "fail"
        if cost_ratio > 1.2:  # 成本 >1.2 倍
            verdict = "fail"
        if latency_ratio > 1.1:  # 延迟 >1.1 倍
            verdict = "fail"
        
        return {"verdict": verdict, "pass_rate_delta": pass_rate_delta, ...}
```

**关键**：评测必须绑定 `eval_set_version` + `model_version`（平台升级由平台方发起，应用侧无法拒绝）。
