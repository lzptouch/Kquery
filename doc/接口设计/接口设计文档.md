## 1. 概述

KQuery Pro API 采用 RESTful 风格设计，基于 FastAPI 框架构建。所有业务接口均挂载在 `/api/v1` 前缀下，支持 JSON 格式的请求与响应。接口涵盖文档处理、语义检索、知识图谱构建与查询、GraphRAG 混合检索、用户认证、AI 写作笔记、思维导图、联网搜索、语音、长期记忆、任务式 Agent、共享知识库、Skills 生态、多模型对话、图表与多模态检索等核心功能。

后端逻辑上遵循 **七层架构** 分层思想（多端交互 → API 网关 → 会话管理 → 业务服务 → 核心决策 → 连接集成 → 数据持久），但 API 路由在物理上按 **功能域** 分组注册（详见第 3 章），而非按七层一一映射。本文档按真实的功能域组织各章接口。

### 1.1 中间件栈

请求经过的中间件顺序（由外到内，由 `app/api/main.py` 注册）：

```
安全响应头 → 速率限制(Redis 滑动窗口) → [请求日志(仅 debug)] → CORS → [Prometheus 指标(可开关 enable_metrics)]
```

> 注：当前版本未启用独立的"审计日志中间件"；审计日志由 `core/audit_logger.py` 在各业务操作中主动写入。全局异常由 `exception_handlers.py` 统一捕获并转换为标准错误响应。

### 1.2 通用认证方式

需要认证的接口采用 JWT Bearer Token 方式：

```
Authorization: Bearer <access_token>
```

未认证请求返回 `401 Unauthorized`，无权限请求返回 `403 Forbidden`。

> 说明：`get_current_user` 依赖用于用户级鉴权（如创建 Skill、创建/管理知识库）；`require_kb_role(min_role)` 依赖用于知识库成员的角色鉴权。多数检索/图谱只读接口当前未强制登录，便于本地开发与演示。

## 2. 基础 URL 与通用规范

### 2.1 基础 URL

| 环境 | 基础 URL |
|------|---------|
| 本地开发 | `http://localhost:8000/api/v1` |
| Docker 部署 | `http://<host>:8000/api/v1` |
| 交互式文档 | `http://<host>:8000/docs`（Swagger UI）、`/redoc` |

### 2.2 通用响应格式

大部分接口使用 `StandardResponse` 包装（`知识图谱`、`图表`、`多模态`等），部分接口直接返回业务对象：

```json
// StandardResponse 成功响应
{
  "success": true,
  "message": "success",
  "data": { ... }
}

// 错误响应（由全局异常处理器生成）
{
  "detail": {
    "error": "ERROR_CODE",
    "message": "错误描述",
    "details": { ... }
  }
}
```

### 2.3 HTTP 状态码

| 状态码 | 说明 |
|--------|------|
| 200 | 请求成功 |
| 201 | 创建成功 |
| 204 | 删除成功（无返回体） |
| 400 | 请求参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 429 | 请求频率超限 |
| 500 | 服务器内部错误 |

### 2.4 请求头

| 请求头 | 说明 | 必需 |
|--------|------|------|
| `Authorization` | Bearer Token | 需鉴权的接口 |
| `Content-Type` | `application/json` 或 `multipart/form-data` | 是 |
| `Accept-Language` | `zh-CN` 或 `en-US`（国际化支持） | 否 |

## 3. 路由分组概览

所有业务路由统一挂载在 `/api/v1` 前缀下；`health` 路由无前缀（直接暴露 `/health*`）。后端采用按"功能域"划分的路由分组（而非严格按七层一一对应），由 `app/api/main.py` 统一注册。各路由文件与真实路径前缀如下：

| 路由文件 | 挂载前缀 | 功能域 |
|---------|---------|--------|
| `api/router.py` → `rag_router` | `/api/v1/kquery` | 文本 RAG：文档处理/查询/集合管理 |
| `api/agent_router.py` | `/api/v1/agent` | Agent 智能问答/会话/WebSocket/SSE/语音上传 |
| `api/knowledge_graph.py` | `/api/v1/graph` | 知识图谱：实体/邻居/路径/子图/算法/可视化/血缘 |
| `api/graphrag.py` | `/api/v1/graphrag` | GraphRAG 混合检索与智能问答 |
| `api/auth_router.py` | `/api/v1/auth` | 用户注册/登录/刷新/资料 |
| `api/knowledge_base_router.py` | `/api/v1/knowledge-bases` | 共享知识库：创建/成员/邀请 |
| `api/config_router.py` | `/api/v1/config` | 配置查看与热重载 |
| `api/chart_data.py` | `/api/v1/chart-data` | 仪表盘图表数据 |
| `api/multimodal.py` | `/api/v1/multimodal` | 多模态内容检索 |
| `api/llm_router.py` | `/api/v1/models`、`/api/v1/chat` | 多模型列表与统一对话 |
| `api/notes_router.py` | `/api/v1/notes` | AI 写作笔记 CRUD + AI 生成 |
| `api/mindmap_router.py` | `/api/v1/mindmap` | 思维导图生成 |
| `api/web_search_router.py` | `/api/v1/web-search` | 联网搜索增强 |
| `api/speech_router.py` | `/api/v1/speech` | 语音 ASR / TTS |
| `api/memory_router.py` | `/api/v1/memory` | 用户长期记忆 |
| `api/tasks_router.py` | `/api/v1/tasks` | 任务式 Agent（DAG 编排） |
| `api/skills_router.py` | `/api/v1/skills` | Skills 技能生态 |
| `api/health.py` | `/health`（无前缀） | 健康检查与就绪/存活探针 |
| `main.py` | `/`（无前缀） | 根欢迎信息、`/health` 兼容端点 |

> **说明**：早期版本曾规划按七层（多端交互/网关/会话/业务/决策/集成/持久）划分 `ws/`、`sessions/`、`rbac/`、`crm/`、`orders/`、`external/` 等路由。当前代码实际采用上述"功能域"分组：
> - **会话能力**并入 `agent` 路由（`GET /agent/session/{id}`、`DELETE /agent/session/{id}`），**不存在独立的 `/api/v1/sessions` 路由**。
> - **RBAC**：`core/rbac.py` 提供 `require_kb_role` 用于知识库成员角色校验，并由 `api/rbac.py` 暴露 `/api/v1/rbac` 角色/权限管理端点。
> - CRM/订单/企业微信等对接仅可能在 `services/integration/` 层以适配器形式实现，**未暴露为公开 API**（`/crm`、`/orders`、`/external` 均不存在）。
>
> 各端点完整清单见第 4–10 章。

## 4. 认证接口（/auth）

对应 `app/api/auth_router.py`，基础路径：`/api/v1/auth`。基于 JWT，`core/security.py` 负责签发/校验，`core/database.py` 提供 `UserORM` 持久化。

| 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|
| `POST` | `/auth/register` | 用户注册，成功后直接返回 Token | 否 |
| `POST` | `/auth/login` | 用户登录 | 否 |
| `POST` | `/auth/refresh` | 使用 Refresh Token 刷新 | 否 |
| `GET` | `/auth/me` | 获取当前用户资料 | 是 |

> 注：当前认证路由仅实现上述 4 个端点，**不含** `/logout`、`/me/password` 等端点（登出由前端丢弃 Token 实现）。

### 4.1 注册

```
POST /api/v1/auth/register
Content-Type: application/json

{
  "username": "string",
  "password": "string",
  "email": "string"
}
```

响应（`TokenResponse`，HTTP 201）：
```json
{
  "access_token": "string",
  "refresh_token": "string",
  "token_type": "bearer",
  "expires_in": 86400
}
```

### 4.2 登录

```
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "string",
  "password": "string"
}
```

响应同 `TokenResponse`。

### 4.3 刷新 Token

```
POST /api/v1/auth/refresh
Content-Type: application/json

{ "refresh_token": "string" }
```

### 4.4 获取当前用户

```
GET /api/v1/auth/me
Authorization: Bearer <access_token>
```

响应（`UserProfileResponse`）：
```json
{
  "user_id": "string",
  "username": "string",
  "email": "string",
  "created_at": "2026-07-19T10:00:00Z"
}
```

### 4.5 速率限制策略

速率限制由 `core/rate_limiter.py` 的中间件与路由级依赖实现。文档上传相关接口通过 `RateLimiter` 依赖显式限流，例如：

| 路径 | 限制策略（来源：路由级 `Depends(RateLimiter(...))`） |
|------|---------|
| `/kquery/documents/process` | 每小时 30 次（`key_prefix="upload"`） |
| `/kquery/documents/process-and-build` | 每小时 20 次（`key_prefix="upload_build"`） |
| `/kquery/documents/process-batch` | 每小时 30 次（`key_prefix="upload_batch"`） |
| 全局默认 | `rate_limit_middleware` 基于 Redis 滑动窗口 |

## 5. 文本 RAG 接口（/kquery）

对应 `app/api/router.py` 中的 `rag_router`，基础路径：`/api/v1/kquery`。承载文档处理、语义检索与集合管理。

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/kquery/documents/process` | 处理单个文档（加载→分块→向量化入库） |
| `POST` | `/kquery/documents/process-and-build` | 处理文档并同步构建知识图谱 |
| `POST` | `/kquery/documents/process-batch` | 批量处理多个文档 |
| `POST` | `/kquery/documents/query` | 语义查询（支持 HyDE） |
| `POST` | `/kquery/documents/add-text` | 直接添加文本片段 |
| `GET` | `/kquery/collections` | 列出所有集合 |
| `GET` | `/kquery/collections/{collection_name}/stats` | 集合统计 |
| `DELETE` | `/kquery/collections/{collection_name}` | 清空/删除集合 |
| `GET` | `/kquery/documents/{collection_name}` | 列出集合下的文档 |
| `GET` | `/kquery/supported-file-types` | 支持的文件类型 |
| `GET` | `/kquery/status` | RAG 服务状态 |

### 5.1 文档处理

```
POST /api/v1/kquery/documents/process
Content-Type: multipart/form-data

file: <文档文件>
collection_name: default
```

### 5.2 语义查询

```
POST /api/v1/kquery/documents/query
Content-Type: application/json

{
  "query": "查询内容",
  "collection_name": "default",
  "top_k": 5,
  "enable_hyde": true
}
```

### 5.3 处理并构建图谱

`POST /kquery/documents/process-and-build` 在文档入库的同时触发实体/关系抽取与图谱写入，是"文档 → 向量库 + 知识图谱"一体化入口。

## 6. Agent 智能问答接口（/agent）

对应 `app/api/agent_router.py`，基础路径：`/api/v1/agent`。提供普通/流式对话、WebSocket、语音上传及会话管理（会话能力即在此路由下，非独立 `/sessions` 路由）。

| 方法 | 路径 | 说明 | 协议 |
|------|------|------|------|
| `POST` | `/agent/chat` | Agent 对话 | HTTP |
| `POST` | `/agent/chat/stream` | Agent 流式对话 | SSE |
| `WebSocket` | `/agent/ws` | WebSocket 实时对话（`?session_id=`） | WebSocket |
| `POST` | `/agent/upload` | 上传并处理文档（Agent 上下文） | HTTP |
| `POST` | `/agent/voice/upload` | 语音文件上传 | HTTP |
| `GET` | `/agent/session/{session_id}` | 获取会话信息 | HTTP |
| `DELETE` | `/agent/session/{session_id}` | 清理/删除会话 | HTTP |
| `GET` | `/agent/collections` | 可用集合列表 | HTTP |
| `GET` | `/agent/status` | Agent 服务状态 | HTTP |
| `GET` | `/agent/tools` | 已注册工具列表 | HTTP |

### 6.1 Agent 对话

```
POST /api/v1/agent/chat
Content-Type: application/json

{
  "message": "用户消息",
  "session_id": "会话ID（可选，不传则创建新会话）",
  "collection_name": "default"
}
```

### 6.2 流式对话（SSE）

```
POST /api/v1/agent/chat/stream
Content-Type: application/json

{ "message": "用户消息", "session_id": "会话ID", "collection_name": "default" }
```

响应为 Server-Sent Events (SSE) 流式输出。

### 6.3 WebSocket 实时对话

```
WebSocket /api/v1/agent/ws?session_id=<会话ID>
```

**消息格式（客户端 → 服务端）：**
```json
{ "type": "message", "content": "用户消息", "collection_name": "default" }
```

**消息格式（服务端 → 客户端）：**
```json
{ "type": "message", "content": "回复内容", "session_id": "会话ID" }
{ "type": "status", "status": "thinking|done|error", "message": "状态描述" }
```

WebSocket 连接由 `app/api/ws_manager.py` 统一管理。

### 6.4 语音上传

```
POST /api/v1/agent/voice/upload
Content-Type: multipart/form-data

file: <音频文件>
session_id: 会话ID
collection_name: default
```

支持格式：WAV、MP3、OGG、M4A 等。ASR 识别能力由 `/speech/asr` 提供（见 9.5）。

### 6.5 会话管理

```
GET    /api/v1/agent/session/{session_id}   # 获取会话信息
DELETE /api/v1/agent/session/{session_id}   # 清理会话
```

会话上下文存储于 Redis，由 `session_service` 管理生命周期。

| `GET` | `/graph/check-collection` | 检查集合的图谱构建状态 |

| `GET` | `/graph/algorithms/pagerank` | PageRank 实体重要度 |
| `GET` | `/graph/algorithms/communities` | 社区发现 |
| `GET` | `/graph/statistics` | 图谱统计信息 |

### 7.1 从文本构建图谱

```
POST /api/v1/graph/entities/build

{ "text": "待抽取文本", "collection_name": "default" }
```

### 7.2 邻居 / 路径 / 子图查询

```
GET  /api/v1/graph/entities/{entity_id}/neighbors?depth=1&limit=20
GET  /api/v1/graph/path?source_id=...&target_id=...&max_depth=3
POST /api/v1/graph/subgraph
```

### 7.3 图谱 Schema

`GET /api/v1/graph/schema` 返回预置的 **22 种实体类型** 与 **25 种关系类型**（定义于 `app/repositories/graph/schema.py`）。

## 8. GraphRAG 接口（/graphrag）

对应 `app/api/graphrag.py`，基础路径：`/api/v1/graphrag`。在向量检索之上融合知识图谱上下文，提供混合检索与智能问答。

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/graphrag/search` | GraphRAG 混合检索（返回融合后的证据） |
| `POST` | `/graphrag/ask` | GraphRAG 智能问答（生成答案 + 引用） |
| `GET` | `/graphrag/question-type` | 问题类型分类 |
| `POST` | `/graphrag/entities` | 从查询抽取实体 |
| `GET` | `/graphrag/statistics` | GraphRAG 统计信息 |
| `GET` | `/graphrag/health` | GraphRAG 健康检查 |

### 8.1 混合检索

```
POST /api/v1/graphrag/search
Content-Type: application/json

{
  "query": "查询内容",
  "collection_name": "default",
  "top_k": 5,
  "enable_graph": true,
  "enable_hyde": true
}
```

### 8.2 智能问答

```
POST /api/v1/graphrag/ask
Content-Type: application/json

{ "query": "查询内容", "collection_name": "default", "top_k": 5 }
```

### 8.3 5 阶段检索流程

1. 问题分类（8 种类型：FACTOID/RELATION/REASONING/LISTING/COMPARISON/DEFINITION/PROCEDURAL/UNKNOWN）
2. 查询实体抽取
3. 图谱上下文扩展（Local Search / Global Search / 路径发现）
4. 向量语义检索（向量检索 + HyDE 增强 + BM25 关键词检索）
5. 结果融合与重排序（RRF 自适应权重 + 多样性惩罚 + Reranker）

## 9. 拓展能力接口

以下能力在 v3.0 已全部实现并注册到 `app/api/main.py`，统一遵循 `/api/v1` 前缀与通用规范。各能力在 `app/core/settings.py` 提供 `*_enabled` 开关，支持灰度。

### 9.1 多模型统一接入（/llm）

对应 `app/api/llm_router.py`。在 `llm_client.py` 多通道调用之上提供模型注册表与统一路由。

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/llm/models` | 列出可用模型（含名称、能力、是否默认） |
| `GET` | `/llm/status` | 模型服务状态 |
| `POST` | `/llm/chat/completions` | 通用对话补全，支持 `model` 参数并流式返回 |
| `GET` | `/llm/health` | 健康检查 |

```
GET /api/v1/llm/models

// 响应
{
  "models": [
    {"name": "qwen-turbo", "display": "通义千问 Turbo", "provider": "openai", "capabilities": ["chat","stream"], "is_default": true},
    {"name": "deepseek-chat", "display": "DeepSeek-V3", "provider": "openai", "capabilities": ["chat","stream"], "is_default": false}
  ]
}
```

## 11. 错误码体系

系统定义 40+ 错误码，组织为 7 大类：

| 错误码前缀 | 类别 | 说明 |
|-----------|------|------|
| `AUTH_*` | 认证错误 | Token 过期、无效凭证、权限不足 |
| `VALIDATION_*` | 验证错误 | 参数非法、文件格式不支持 |
| `NOT_FOUND_*` | 资源不存在 | 集合、文档、用户不存在 |
| `RATE_LIMIT_*` | 限流错误 | 请求频率超限 |
| `DATABASE_*` | 数据库错误 | 连接失败、查询超时 |
| `EXTERNAL_*` | 外部服务错误 | LLM API 调用失败 |
| `INTERNAL_*` | 内部错误 | 系统内部异常 |

### 11.1 数值错误码范围（简要参考）

| 数值范围 | 含义 |
|---------|------|
| `0` | 成功 |
| `1xxx` | 客户端错误（参数校验） |
| `2xxx` | 认证/授权错误 |
| `3xxx` | 业务错误（知识库/文档不存在） |
| `4xxx` | AI 服务错误 |
| `5xxx` | 外部服务错误（Milvus/Neo4j） |
