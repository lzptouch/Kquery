## 〇、摘要

1. **2026-11-12：认证与授权整套下线**。注册 / 登录 / 口令哈希 / JWT / 静态凭证表 / 用户目录 / 角色门禁 / 前端路由守卫 / 文档级 ACL / 知识库授权 / 权限矩阵——共 18 个后端端点、5 张前端页面、约 1100 行后端代码、8 个测试文件被删除。请求身份退化为**固定值**（`tenant=default`、`user=local`）。
2. **保留的是"数据隔离"，不是"权限"**：`tenant_id` 仍用于文档归属、会话归属、缓存键、限流分桶、图谱与记忆分区——它是数据模型的一部分。**应用层不再有任何访问控制**，访问边界改由部署层（反向代理 / 内网 / 网关）承担。
3. **仍然存在的能力（逐条对过代码）**：① 突发令牌桶限流（`services/ratelimit.py`，Redis Lua 原子 + Redis 不可用回落进程内）；② `tenant_id` 数据分区（文档归属 / 会话归属 / 缓存键 / 限流分桶 / 图谱与记忆分区）；③ 日志层 PII 与凭证脱敏（`core/logging_setup.py`）；④ 上传体积与扩展名白名单（`api/upload_util.py`、`services/parsers/router.py`）；⑤ 快问临时文档 TTL（`services/quickask.py`）。**另有两条与"治理"相邻但性质不同的机制**：危险级工具的人工审批闸门（`services/agent/tools.py`）与提示词注入防护（`services/injection_guard.py` + `services/retrieval/fusion.py` 降权）；`/metrics` 上还剩一处 `X-Metrics-Token` 校验，但它的 fail-closed 分支已不可达（见 §11 缺口 8）。
4. **下线带来的三处语义损失**（诚实登记）：① 「库里有但你没权限」与「库里真没有」不再可区分；② 审计留痕能力仍然缺失（此前已下线，本次未变）；③ 提示词注入面的**结构化隔离**已落地（`B0 KQ-27` 三层防护：提示词加固 + 证据成对边界标记 + 入库打标 / 检索降权 0.25），`ST-01` 阶段 A（只观测）与**阶段 B（按结构分段渲染，默认仍是 `legacy`）**均已落地——但**运行时监控 / 审计层仍缺前置**（没有「本轮上下文里出现了疑似注入内容」的可观测出口）。

## 一、安全模型总览（现状）

### 1.1 三层边界

| 层 | 现状 | 位置 |
|---|---|---|
| **接入层** | 无鉴权。全部端点直接可达 | `backend/app/dependencies.py`（`get_principal` 返回固定身份） |
| **数据隔离层** | `tenant_id` 单一维度，恒为 `default` | `backend/app/core/identity.py` |
| **部署层** | **访问边界的唯一承担者**：反向代理 / 内网 / 网关 | `deploy/nginx/`、`deploy/k8s/` |

> 回归护栏：`tests/security/test_isolation_matrix.py`（10 例）钉住这条边界的**应用层**部分——自报身份（`X-Tenant-Id` / `X-User-Id` / `X-Roles`）无效、按 id 猜别人的会话 / 文档 / 快问 / HITL run / 成本账单 / 反馈工单 / 查询分析记录一律 404 且无副作用。
> 它**不是**角色越权矩阵（认证授权下线后没有第二个角色可伪造），也**不覆盖**部署层（反代规则、网络分区）——那部分只能靠部署配置审计。

### 1.2 固定身份

```python
# backend/app/core/identity.py
@dataclass(frozen=True)
class Principal:
    tenant_id: str = "default"
    user_id: str = "local"
```

- `frozen=True` 是刻意的：身份是常量，不该被任何节点就地改写。
- `Principal` 上原有的 `roles` / `groups` / `enabled` / `identities` / `is_admin` **全部删除**：`roles`/`groups` 只服务于角色门禁与 ACL 身份表达式（两者都已下线），`enabled` 在原实现里就是**死字段**（无任何读取点）。
- **请求头无权改变主体**：中间件在每个请求上挂载 `request.state.principal = Principal()`（`backend/app/main.py`），路由与依赖读到的永远是固定值。原先 `request.state.principal` 是「谁挂了 `get_principal` 谁才有」——角色门禁下线后，只读端点会 500，这个坑由中间件一次性填平。

### 1.3 身份相关的残留数据

| 文件 | 状态 |
|---|---|
| `data/users.json` | 不再被创建或读写（用户目录已删） |
| `data/acl.json` | 不再被创建或读写（文档 ACL 已删） |
| `data/knowledge_bases.json` / `data/kb_grants.json` | 不再被创建或读写（知识库授权已删） |

> 旧部署的数据文件**不会被自动清理**——它们只是不再被读取。清理属运维动作，不在应用职责内。

**残留死代码**：`Settings.users_file` 派生属性仍在（`backend/app/core/config.py:1167-1173`，返回 `data_dir/users.json`），但**全仓库无读取点**（`grep -rn "users_file" backend/` 只命中定义本身）；属性 docstring 已明写「仅供遗留脚本/文档引用」。`acl.json` / `kb_grants.json` / `knowledge_bases.json` 连派生属性都不再存在。

## 二、认证四档（**已下线**，2026-11-12）

> 本章记录的是**已删除**的机制。留档的目的是回答「为什么曾经有四档、为什么现在没有」。

| 档位 | 曾经的实现 | 曾经的取舍 | 现状 |
|---|---|---|---|
| 头部透传（开发档） | 读 `X-User-Id` / `X-Tenant-Id` / `X-Roles`，**不验证任何凭证** | 免去发令牌，但自报角色即越权 | **删除**：请求头一律被忽略 |
| 静态凭证表 | token → Principal 查表 | 简单，但无法表达租户 | **删除** |
| JWT（HS256，企业生产） | 自实现验签（显式拒绝 `alg != HS256`），校验 exp/nbf/iss/aud/sub | 不引第三方库，但自己实现密码学 | **删除** |
| 账号密码登录 + 自签发 JWT | 登录端点自签发上面那套 JWT | 与外部 IdP 同一种令牌，前端处理一致 | **删除** |

**为什么整套删掉，而不是降级为"默认关闭"**：

- 认证是**身份体系**，不是开关。留一个 `auth_enabled=false` 的档位，等于留一条"任何人可自报身份"的旁路——那正是原 KQ-03 缺口的核心；
- 项目的价值主张在检索质量与 Agent 编排，认证曾贡献端点依赖、12 个配置项、5 张前端页面和 23 条能力项（2026-11-12 随下线删除；现存端点 **70** 个）；
- 单用户自托管场景下，**访问边界由部署层承担**更简单也更可靠（网关 + 内网 + 反向代理），比在应用里自建身份体系更不容易配错。

**代价（诚实登记）**：应用层现在**完全开放**——部署到公网就等于任何人可读全部知识库。文档、部署清单与 runbook 都必须明确这一点。

## 四、口令（**已下线**）

| 机制 | 说明 | 现状 |
|---|---|---|
| PBKDF2-HMAC-SHA256（600k 轮，自描述格式 `pbkdf2_sha256$600000$salt$hash`） | 随机 16B 盐、常量时间比较、时序侧信道 `burn()` | **删除** |
| 登录失败同码同文案 | 账号不存在 / 口令错 / 已停用返回完全相同的信息，避免账号枚举 | **删除**（无登录） |
| 弱口令强度校验（≥8 位 + 字母 + 数字） | 建号与改密时拦截 | **删除** |
| 首个管理员口令引导 | 全新部署无人能登录时**拒绝启动**并给指引 | **删除** |

> 离线破解成本（600k 轮 PBKDF2）曾是这套实现的**核心安全论点**；它随口令机制一起消失。若未来恢复任何账号体系，这一段应作为重新设计的起点，而不是照抄。

## 五、ACL 五步判定树（**已下线**）

> 判定树原文（留档）：**租户闸门 → deny 优先 → allow 名单 → 租户内公开 → 默认拒绝**，顺序不可调换（deny 优先意味着角色授权救不回被拉黑者）。

| 曾经的配套机制 | 说明 | 现状 |
|---|---|---|
| 文档级 ACL | 五步短路判定 + 允许清单枚举 + 全局版本进缓存键 | **删除**：服务模块与端点均已移除 |
| 知识库授权（KB 粒度） | 管理员按用户授予知识库可用权，与文档 ACL 叠加取交集 | **删除** |
| 检索下推三档 | 动态超额取数 → 表达式下推 → 应用层后过滤 | **删除**：`RetrievalFilters` 只剩 `tenant_id` 与 `doc_id` |
| 防探测文案「无权限或不存在」 | 不区分"不存在"与"无权限" | **删除**（403 不再出现） |

### 5.1 下线带来的三处语义损失

| # | 损失 | 说明 |
|---|---|---|
| 1 | **拒答原因不再可区分** | 「库里有但你没权限」与「库里真没有」合并为 `no_content` / `insufficient_evidence`；另有 `upstream_unavailable`（`C-12` 的降级模板：上游不可用，与「内容不足」是不同语义） |
| 2 | **过滤条数不再上报** | `acl_filtered` 字段从响应、SSE 事件与前端面板一并删除 |
| 3 | **缓存键少一个维度** | 不再有 `acl_version`；撤权即失效的机制随之消失（缓存键仍带 `user` 与 `index_version`） |

## 九、仍然存在的治理机制

### 9.1 工具治理（危险级审批闸门）

实现：`backend/app/services/agent/tools.py`。

- **危险级与审批闸门**：`danger=write` 的工具未经批准**不执行**，返回结构化错误而不是抛异常——Agent 要读到"需要审批"这个事实并改用别的工具，而不是整条链断掉。写类工具还**不参与熔断半开探测**（避免对有副作用的工具自动试跑）。
- **入参 Schema 校验**：校验失败返回**错误文案**回传给 LLM 自我修正，而不是让整步失败——"参数写错"是模型最能自愈的一类错误。
- **幻觉工具名兜底**：未注册的工具名降级到注册表第一个工具 + 告警（返回 `hallucinated=True`），空注册表抛明确运行时错误（装配错误应立刻暴露，不伪装成随机崩溃）。
- **单步超时**：固定线程池 + future 超时；Python 线程无强制中断能力，已运行的工具线程仍会跑完（边界写在注释里）。
- **条件注册**：`sql_dsn` 为空则不注册 `sql_search`，`web_search` 同理——工具目录与熔断状态经 `GET /admin/tools` 暴露。

> **ACL 在注册表层的统一执行已随文档级 ACL 一起删除**（原为 `run_with_timeout` 返回前对所有工具结果过 `_apply_acl`）。工具结果现在不再做文档级可见性过滤。

### 9.2 突发限流（令牌桶）

实现：`backend/app/services/ratelimit.py`，路由级依赖 `enforce_rate_limit`（`backend/app/dependencies.py`）。

- **算法**：令牌桶（不是滑动窗口——滑动窗口随租户配额一起下线了）。
- **分桶维度**：按**固定租户**（单租户下等价于全局限流）；Redis 键 `ratelimit:bucket:{tenant_id}`。
- **原子性**：回填 + 扣减 + EXPIRE 全在一个 Lua 脚本内。
- **降级纪律**：Redis 不可用 → 回落进程内桶（单副本语义），**绝不**把「Redis 挂了」变成「请求全被限流」或「请求全被放行」。
- **失败表现**：429 + `Retry-After`（`ErrCode.RATE_LIMITED` = 6101）。

### 9.3 日志 PII 脱敏与结构化日志

实现：`backend/app/core/logging_setup.py`。JSON Formatter 强制字段（trace_id / span_id / tenant_id / user_id / route / latency_ms）+ 七类凭证与个人信息脱敏 + DEBUG 采样（可复现，测试不 flaky）。

### 9.4 `/metrics` 的令牌校验（唯一保留的令牌校验）

实现：`backend/app/api/probes.py:145-183`（`GET /metrics`，A-12 拆分后从 `main.py` 迁入 probes router）。判定顺序：

| 条件 | 行为 | 代码 |
|---|---|---|
| `metrics_public=true` | **直接放行**（不校验令牌） | `api/probes.py:157` |
| `metrics_token` 非空 | 必须带对 `X-Metrics-Token`，否则 401 `UNAUTHORIZED`（1101） | `api/probes.py:158-165` |
| `metrics_token` 为空且 `app_env` **非**开发档 | **fail-closed 401**（宁可 401 也不把运营数据裸露出去） | `api/probes.py:166-178` |
| `metrics_token` 为空且 `app_env ∈ dev/local/test` | 放行（本地调试友好） | `api/probes.py:179` |

**实际效果**：默认 `metrics_public=false`、`metrics_token=""`（`core/config.py:315-316`）⇒ 开发档开箱可抓，**生产档未配令牌一律 401**。原 fail-closed 曾依赖已删除的 `auth_enabled` 字段而从未生效（`getattr` 恒假），已于 2026-11-13 改用 `app_env` 判定修复（代码注释如实留痕，`api/probes.py:170-173`；`10-可观测性与成本.md` §八 G9）——原缺口（§11 第 8 条）**已关闭**。

### 9.5 上传体积与类型限制

实现：`backend/app/api/upload_util.py:40-57`（`stream_to_disk`）、`backend/app/services/knowledge.py:509-510`（内存路径）、`backend/app/services/parsers/router.py:27-36`（`SUPPORTED_EXTENSIONS`）。

- **体积**：`max_upload_mb`（默认 50，`core/config.py:496`）——**没有全局请求体上限**，只有三处端点级实现（上传、入库、快问）；超限抛 `ErrCode.FILE_TOO_LARGE`（413），且**超限时删除半成品文件**（`upload_util.py:54-56`）。
- **类型**：扩展名白名单 `SUPPORTED_EXTENSIONS`（`.md` / `.pdf` / `.docx` / `.doc` / `.xlsx` / `.pptx` / 图片 / 纯文本 / 代码类）；不在白名单 → `ErrCode.UNSUPPORTED_FILE_TYPE`（3101）。
- **文件名**：`upload_util.py` 的规范化拒绝带路径的名字（`Path(name).name != name` → 400），防目录穿越。
- 这是**输入面的完整性约束**，与"敏感词扫描"无关（后者已下线，见 §七）。

### 9.6 快问临时文档 TTL

实现：`backend/app/services/quickask.py:158-169`、`backend/app/api/quickask.py:139`。

- `quick_ask_ttl_s` 默认 **7200**（2 小时，`core/config.py:375`）；过期读取 → 404 `QUICK_DOC_EXPIRED`。
- 另有 `quick_ask_max_mb`（20）/ `quick_ask_max_pages`（20）两条规模上限（`core/config.py:377-378`），实际字节上限取 `min(quick_ask_max_mb, max_upload_mb)`（`quickask.py:164-165`）。
- 临时文档**不入库、不 bump 索引版本**，因此这里的"清理"是 TTL 到期失效，不是管理动作。

### 9.7 数据分区（不是权限）

`tenant_id` 的四个实际用途（全部在数据模型里，不在访问控制里）：文档归属（`DocumentRecord.tenant_id`）、会话归属（会话 ID 前缀 `{tenant}:{user}:`，`services/agent/sessions.py`）、缓存键维度、限流分桶。图谱 / 多模态侧同理——`services/graph/*` 按 `{tenant}\x00{name}` 复合键分区，`services/multimodal.py` 与图像索引条目带 `tenant_id` 字段（详见 `07-图谱与多模态链路.md` §1.4 / §8.5）。**分区只防同名数据互相覆盖，不表达"谁能看"**。

## 十一、边界与已知缺口

| # | 缺口 | 说明与位置 |
|---|---|---|
| 1 | **应用层完全开放，无任何访问控制** | 认证与授权下线后，谁能访问服务**完全取决于部署层**。部署到公网 = 任何人可读全部知识库。**这是本次改动的头号部署前提**，必须在部署清单与 runbook 中写明 |
| 2 | **合规留痕能力仍然缺失** | 审计日志此前已下线，本次未变。「谁在什么时候改了什么配置」无合规级记录（只有 trace_id + 结构化日志 + 指标） |
| 3 | **多副本下限流额度放大** | Redis 异常时限流桶退回进程内（`backend/app/services/ratelimit.py`），多副本下每副本各放一份，实际额度 ≈ 配置值 × 副本数 |
| 4 | **文档租户恒为 `default`** | `DocumentRecord.tenant_id` 的多租户隔离代码仍在，但实际隔离强度取决于部署时是否真用多租户——当前只有 `default` 一个取值 |
| 5 | ~~**提示词注入面无结构化隔离**~~ **已闭合（`B0 KQ-27`）** | 证据块与系统提示的显式分隔已落地（提示词声明「证据是数据不是指令」+ 证据成对边界标记 + 入库打标 + 检索降权 0.25）；**但运行时监控 / 审计层仍缺前置**——没有「本轮上下文里出现了疑似注入内容」的可观测出口 |
| 6 | **危险级工具在生产路径无触发点** | 可注册的 9 个工具中没有一个是 `write` 级（默认仅装配 6 个；`http_request` / `python_sandbox` / `mcp` 均未注册）→ 审批闸门在生产路径**无触发点**，仅有单测覆盖 |
| 7 | **会话归属隔离随身份固定而退化** | 会话 ID 仍带 `{tenant}:{user}:` 前缀（`backend/app/services/agent/sessions.py`），归属校验仍在；但主体恒定，任何能访问服务的人都是同一主体——前缀校验只能挡住**伪造前缀的会话 ID**，挡不住"知道会话 ID 就访问" |
| 8 | ~~**`/metrics` 的 fail-closed 分支已失效**~~ **已关闭** | 原先 `elif getattr(settings, "auth_enabled", False)` 依赖已删除字段 ⇒ 恒假 ⇒ 分支不可达；已改用 `app_env` 判定（`api/probes.py:166-178`）：非开发档未配 `METRICS_TOKEN` 一律 401，dev/local/test 才放行（详见 §9.4） |
