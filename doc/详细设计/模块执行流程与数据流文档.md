## 1. API 网关层模块

### 1.1 主路由器 — `app/api/router.py`

| 属性 | 说明 |
|------|------|
| **文件** | `backend/app/api/router.py` |
| **角色** | 系统 RAG 相关的 RESTful 入口，聚合所有/kquery/前缀的路由 |
| **依赖** | `RAGService`, `GraphBuilderService`, `LoaderRegistry`, `MilvusConnector`, `chunk_text` |

#### POST `/kquery/documents/process` — 文档处理

```
输入: UploadFile(file, filename, content_type) + form: collection_name(str), chunk_size(int, opt), chunk_overlap(int, opt)
        │
        ▼  FileValidator.validate() → 检查扩展名、MIME 类型、文件大小
        │
        ▼  LoaderRegistry.get_loader(ext) → 获取对应文件加载器
        │
        ▼  loader.load(file_path) → List[DocumentChunk]
        │     输入: 文件原始字节 → 输出: [{page_content, metadata}]
        │
        ▼  chunk_text(content, chunk_size, chunk_overlap) → List[TextChunk]
        │     输入: 原始文本 → 输出: [{text, chunk_index, page_number, metadata}]
        │
        ▼  embed_batch(chunks) → List[List[float]]
        │     输入: 文本块 → 输出:  embedding 向量数组
        │
        ▼  MilvusConnector.insert(collection, vectors, metadata) → MutationResult
        │     输出: {insert_count, ids}
        │
输出: DocumentProcessResult(success, collection_name, file_name, chunk_count, document_id)
```

**字段变换**:
| 输入字段 | 变换过程 | 输出字段 |
|---------|---------|---------|
| `file.filename` | 提取文件名 | `file_name` |
| `collection_name` | 透传 | `collection_name` |
| 文本块计数 | 统计 | `chunk_count` |
| Milvus insert_result | 提取 id | `document_id` |

#### POST `/kquery/documents/query` — 语义查询

```
输入: QueryRequest(query, collection_name, top_k=5, enable_hyde=True)
        │
        ▼  RAGService.query_documents(query, top_k, collection_name, enable_hyde)
        │      ├─ embedding.embed_query(query) → query_vector (List[float])
        │      ├─ vector_search(query_vector, top_k*2) → [ScoredResult(...)]
        │      ├─ [HyDE] hyde_generator.generate(query) → hypothetical doc → embed → search
        │      ├─ [BM25] bm25_retriever.search(query, top_k) → [BM25Result(...)]
        │      ├─ RRF 融合: 对 3 路结果做 reciprocal rank fusion
        │      └─ [Reranker] reranker.rerank(query, candidates) → reranked [ScoredResult]
        │
输出: QueryResult(query, results=[{chunk_id, text, score, metadata, source}], total_count)
```

**字段变换**:
| 输入字段 | 变换过程 | 输出字段 |
|---------|---------|---------|
| `query` | 透传 | `query` |
| `query` | embed → vector | `query_vector`（内部） |
| `top_k` | 控制返回数量 | `total_count` |
| `enable_hyde` | 控制是否启用 HyDE | `results[].score`（融合后分数） |

#### POST `/kquery/documents/process-and-build` — 处理+图谱构建

```
输入: file + collection_name + enable_kg(bool)
        │
        ▼  同 process() → DocumentProcessResult
        │
        ▼  [enable_kg=true] GraphBuilderService.build_from_documents(collection_name)
        │      ├─ 读取集合内所有文档 → 切片
        │      ├─ EntityExtractionService.extract(texts) → entities:[{name, type, ...}]
        │      ├─ RelationExtractionService.extract(texts, entities) → relations:[{source, target, type}]
        │      └─ Neo4jConnector.batch_create(entities, relations) → {node_count, rel_count}
        │
输出: {rag: DocumentProcessResult, kg_build: {success, entity_count, relation_count}}
```

### 1.2 GraphRAG API — `app/api/graphrag.py`

| 属性 | 说明 |
|------|------|
| **文件** | `backend/app/api/graphrag.py` |
| **角色** | GraphRAG 混合检索的 API 入口，5 阶段检索流程 |
| **依赖** | `GraphRAGEngine`, `classify_question`, `QuestionType` |

#### POST `/graphrag/search` — 混合检索

```
输入: HybridSearchRequest(query, collection_name, kb_id=None, top_k=10, enable_hyde=True)
        │
        ▼  GraphRAGEngine.hybrid_search()
        │
阶段1 ──► classify_question(query) → QuestionType
        │     输入: 用户问题文本
        │     输出: FACTOID | RELATION | REASONING | LISTING | COMPARISON | DEFINITION | PROCEDURAL | UNKNOWN
        │
阶段2 ──► QueryEntityExtractor.extract(query) → [Entity(name, type, matched)]
        │     输入: 查询文本 + [规则匹配 / LLM / 数据库匹配]
        │     输出: [{entity_name, entity_type, kb_matched}]
        │
阶段3 ──► GraphContextExpander.expand(entities, depth=2) → GraphContext
        │     输入: 实体列表 → 输出: {subgraph:{nodes, edges}, paths:[], communities:[]}
        │     内部: graph_query.query_neighbors() + query_path() + community_match()
        │
阶段4 ──► RAGService.query_documents(query, top_k) → [ScoredResult]
        │     向量检索 + HyDE + BM25 → RRF 融合 → Reranker 重排
        │
阶段5 ──► ResultFusionEngine.fuse(vector_results, graph_context, question_type) → [ScoredChunk]
        │     1. Min-Max 归一化向量和图谱分数
        │     2. 自适应权重: 根据问题类型调整向量vs图谱权重
        │     3. 多样性惩罚: 避免重复语义片段
        │     4. 最终 Top-K 排序
        │
输出: HybridSearchResult(
        question_type, extracted_entities, graph_context,
        vector_results, fused_results=[{text, score, source_type, metadata}],
        performance_metrics={total_time, stages:[{name, time_ms}]}
      )
```

**问题类型自适应权重策略**:
| 问题类型 | 向量权重 | 图谱权重 | 说明 |
|---------|---------|---------|------|
| FACTOID (事实型) | 0.4 | 0.6 | 依赖图谱精确查询 |
| RELATION (关系型) | 0.3 | 0.7 | 高度依赖图谱路径 |
| REASONING (推理型) | 0.5 | 0.5 | 平衡两种来源 |
| PROCEDURAL (程序型) | 0.7 | 0.3 | 偏重向量语义匹配 |

#### POST `/graphrag/ask` — 智能问答

```
输入: AskRequest(query, collection_name, kb_id, system_prompt, conversation_history=[{role, content}])
        │
        ▼  GraphRAGEngine.generate_answer(query, collection_name, system_prompt, history)
        │     1. hybrid_search() → 获取融合结果 + 图谱上下文
        │     2. 构建 prompt: system_prompt + 图谱证据 + 检索块 + 对话历史 + 用户问题
        │     3. LLM 调用生成答案
        │     4. 标注来源实体
        │
输出: StandardResponse(success=true, data={answer, sources:[{text, score, source_type}], entities:[{name, type}]})
```

## 3. 会话管理层模块

### 3.1 会话状态机 — `app/core/session/state_machine.py`

| 属性 | 说明 |
|------|------|
| **文件** | `backend/app/core/session/state_machine.py` |
| **角色** | 对话状态有限状态机 (FSM)，管理 6 种状态和 10 种事件 |

**状态定义**:
| 状态 | 含义 |
|------|------|
| `IDLE` | 空闲/初始状态 |
| `LISTENING` | 等待用户输入 |
| `PROCESSING` | 正在处理请求 |
| `AWAITING_CONFIRMATION` | 等待用户确认 |
| `ERROR` | 错误状态 |
| `CLOSED` | 会话结束 |

**状态迁移**:
```
IDLE ──[start_session]──► LISTENING
LISTENING ──[user_input]──► PROCESSING
PROCESSING ──[response_ready]──► LISTENING
PROCESSING ──[need_confirmation]──► AWAITING_CONFIRMATION
AWAITING_CONFIRMATION ──[confirmed]──► LISTENING
AWAITING_CONFIRMATION ──[rejected]──► PROCESSING
PROCESSING ──[error]──► ERROR
LISTENING ──[timeout]──► CLOSED
* ──[force_close]──► CLOSED
```

## 4. 业务服务层模块

### 4.1 RAG 服务 — `app/services/rag_service.py`

| 属性 | 说明 |
|------|------|
| **文件** | `backend/app/services/rag_service.py` |
| **角色** | RAG 检索主服务，协调多路检索、融合、重排序 |
| **依赖** | `Retriever`, `EmbeddingService`, `BM25Retriever`, `HydeGenerator`, `Reranker` |

```
query_documents(query, top_k=5, collection_name="default", enable_hyde=True)
        │
        ▼  Step 1: 向量检索
        │     query_embedding = embedding.embed_query(query)
        │     vector_results = milvus.search(query_embedding, top_k*2)
        │
        ▼  Step 2: [可选] HyDE 增强检索
        │     hyde_doc = hyde_generator.generate(query)           # 假设文档
        │     hyde_embedding = embedding.embed_query(hyde_doc)     # 向量化
        │     hyde_results = milvus.search(hyde_embedding, top_k)  # 二次检索
        │
        ▼  Step 3: [可选] BM25 关键词检索
        │     bm25_results = bm25_retriever.search(query, top_k)
        │
        ▼  Step 4: RRF 融合
        │     fused = reciprocal_rank_fusion([vector, hyde, bm25], k=60)
        │     公式: score = sum(1 / (k + rank_i))
        │
        ▼  Step 5: [可选] Reranker 重排序
        │     reranked = reranker.rerank(query, fused[:top_k*2])
        │
输出: [{text, score, metadata, chunk_id, collection_name, source_type}]
```

### 4.2 检索器 — `app/services/retriever.py`

```
query_documents(query, top_k, collection_name, filters={})
        │
        ▼  处理查询: 文本预处理 → embed → 向量检索
        │
        ▼  后处理: 基于时间衰减调整分数
        │     decay_factor = 2^(-days / half_life)   (默认half_life=30天)
        │
        ▼  聚合: 按 document_id 去重 + 合并相同来源的片段
        │
输出: [ScoredResult(text, score, metadata, chunk_id, collection_name)]
```

### 4.8 图像理解 — `app/services/image_understanding.py`

### 9.1 多级缓存 — `app/core/cache.py`

```
L1 (MemoryCache / lru_cache)
   输入: key, value → 存储到进程内 LRU 字典
   输出: 缓存命中/未命中
   TTL 范围: 30s (热点数据) ~ 5min (配置项)

L2 (RedisCacheService)
   输入: key, value, ttl → SET key value EX ttl
   输出: 缓存命中/未命中
   TTL 范围: 30min (会话) / 1h (检索结果) / 24h (话术模板)

MultiLevelCache (L1+L2 联合)
   get(key): L1 → 命中返回 → L2 → 命中则回填 L1 → DB/API
   set(key, value, ttls): 同时写入 L1 和 L2
   invalidate(pattern): Redis KEYS pattern → DEL + 广播 L1 清除
```
