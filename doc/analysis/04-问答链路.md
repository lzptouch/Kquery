## 一、三条路径的分叉规则

### 1.1 分叉点位置

分叉发生在 **API 层**（`backend/app/api/ask.py`），不在 pipeline 内部：

```python
# backend/app/api/ask.py:54-60
def _use_agent(req: AskRequest, settings: Settings) -> bool:
    if req.doc_id:
        return False
    return settings.agent_enabled and (req.mode == "agent" or req.session_id is not None)
```

`POST /ask`（`backend/app/api/ask.py:178`）与 `POST /ask/stream`（`:408`）都调用它，两条路径的分叉结果一致。

### 1.2 判定表

| 序 | 判定条件 | 结果路径 | 证据 |
|---|---|---|---|
| 1 | `req.doc_id` 非空 | **强制线性**（快问） | `backend/app/api/ask.py:57-58` |
| 2 | `req.doc_id` 为空 且 `settings.agent_enabled` 为假 | 线性 | `backend/app/api/ask.py:60` |
| 3 | `req.doc_id` 为空 且 `agent_enabled` 为真 且 `req.mode == "agent"` | **Agentic** | `backend/app/api/ask.py:60` |
| 4 | `req.doc_id` 为空 且 `agent_enabled` 为真 且 `req.session_id` 非空 | **Agentic** | `backend/app/api/ask.py:60` |
| 5 | 以上皆否 | 线性 | 兜底 |

### 1.3 三条路径的形态对照

| 维度 | 线性 | Agentic | 快问 |
|---|---|---|---|
| 触发条件 | 默认 | `mode="agent"` 或带 `session_id` | `req.doc_id` 指向快问临时文档 |
| 入口端点 | `POST /ask`、`POST /ask/stream` | 同左 | `POST /quickask/ask`（另有 `/ask` 带 `doc_id` 的等价路径） |
| 核心实现 | `services/generation/core.py:69-481` `core_events` | `services/agent/graph.py` 状态机 + `services/agent/runner.py` | 线性路径 + `doc_id` 范围过滤 |
| 是否写会话快照 | 否（线性路径不落快照） | 是（`agent/sessions.py:253-317` `save_turn`） | 否 |
| 是否消耗 Agent 预算 | 否 | 是（token / cost / deadline） | 否 |
| 拒答口径 | CRAG 分支 + 提示词级归一 | 反思分 + 证据为空 + 提示词级归一 | 同线性 |
| `token` 语义 | 真流式（`C-13`，逐块外发） | 终稿后切片重放 | 同线性 |

### 1.4 为什么 `doc_id` 强制线性

`backend/app/api/ask.py:55-56` 的注释给出理由：**Agent 路径的检索没有接 `doc_id` 过滤**，放行会变成"限定单文档的提问却检索了全库"。这是硬红线，不是性能取舍。

配套的存在性校验在 `_assert_quick_doc`（`backend/app/api/ask.py:62-75`）：`doc_id` 必须能被 `quickask.get_meta(doc_id, principal, session_id=...)` 取到，否则按 3004（`QUICK_DOC_EXPIRED`）处理。**注意**：授权已下线，这里校验的是"文档仍有效且会话匹配"，不再有"属于当前主体"的越权语义（`principal` 恒为 `default/local`）。

### 3.4 为什么刻意不加 `interrupt_before`

`backend/app/services/agent/graph.py:936-938`：

```python
# checkpointer 是断点续跑 / 多轮状态继承 / 完整回放 / HITL 的共同前提。
# 刻意**不加** `interrupt_before`：那是**静态**中断（指定节点每次都挂起），
# 而 HITL 需要的是「低置信才挂起」的条件性中断——必须由 interrupt() 在
# answer 节点内部动态调用，静态声明会让该节点每次都停。
return graph.compile(checkpointer=checkpointer)
```

静态 `interrupt_before` 会让 `answer` 节点每次都停 —— 哪怕证据充足、置信度极高。这是**语义错误**，不是风格问题。

### 4.4 过期清扫

`backend/app/services/quickask.py:360-423`：启动时清理两类残留——① 登记信息已失效的僵尸条目；② 磁盘临时目录里还在但登记信息已失效的 `quick_*` 文件（TTL 到期后元数据没了但向量还在）。

## 六、预算三维度

### 6.1 三个维度

`backend/app/services/agent/budget.py:25-134`：

| 维度 | 字段 | 语义 | 判定 |
|---|---|---|---|
| token | `token_limit` | 累计 token 上限；0 = 不限 | `backend/app/services/agent/budget.py:52-63` |
| cost | `cost_limit_yuan` | 累计金额上限（元）；0 = 不限 | `backend/app/services/agent/budget.py:52-63` |
| deadline | `deadline_ms` | 整体墙钟上限；0 = 不限 | `backend/app/services/agent/budget.py:52-63` |

判定入口 `exhausted()`（`:52-63`）返回耗尽原因（`deadline` / `token` / `cost` / 空串）；一旦耗尽，原因被**固化**，后续不再重新判定。`max_output_tokens()`（`:64-86`）在剩余额度内反推"本次最多还能生成多少 token"，把预扣落到实处。

`can_afford(tokens, cost_yuan)`（`:87-101`）回答"能否承担**下一次**调用的下界开销"——**判定用"是否已耗尽"而非"是否会耗尽"**，避免执行到一半才发现超限（那时钱已经花了）。结算入口 `settle_tokens()`（`:102-110`），快照 `snapshot()`（`:111-142`）。

**预算耗尽不报错，降级作答**（`status="budget_exhausted"`）：预算控制的目的是"别把用户和平台的钱烧光"，不是"拒绝服务"——用户至少该拿到基于已有证据的部分答案（`backend/app/services/agent/budget.py:13-14`）。

预算按租户可覆盖（`_scoped("<name>_<tenant>")`），未配置时用全局默认值（`backend/app/services/agent/budget.py:143-157`）。

## 七、长期记忆

### 7.1 设计约束：不存用户原话

`backend/app/services/agent/memory.py:16-22`：记忆是**长期驻留**的数据，明文原话会成为一份绕过内容治理的"影子副本"（审计与敏感词下线后，已无任何环节再对记忆内容做哈希化或掩码）。因此条目只存三样：

| 字段 | 语义 |
|---|---|
| `kind` | 问题类型（由分类器产出，不是原文） |
| `key` | 归一化后的**实体/话题键**（如文档名、指标名），不是整句话 |
| `value` | 结论（"该看 A 文档"）或无效查询的**指纹** |

### 7.2 长问题指纹化

`backend/app/services/agent/memory.py:249-258` 的 `_topic_key()`：

| 问题长度 | 处理 |
|---|---|
| ≤ 24 字（通常是实体/指标名） | 原样保留作为话题键 |
| > 24 字 | 退化为 `指纹:{sha256 前 16 位}`（`query_fingerprint` 在 `:71-79`） |

避免把用户的长句描述写进长期存储。同一问题得到同一指纹，但**不可反推原文**。

### 7.3 四类 kind

`backend/app/services/agent/memory.py:51-54`：

| kind | 常量 | 语义 | 注入时的措辞 |
|---|---|---|---|
| `missing_doc` | `KIND_MISSING_DOC` | 知识库缺这类内容 | "关于「X」的问题知识库通常没有内容，…" |
| `invalid_query` | `KIND_INVALID_QUERY` | 该查询串从未召回 | "查询「X」此前从未召回结果，不要重复尝试同一查询" |
| `correction` | `KIND_CORRECTION` | 用户/人工确认过的正确指向 | "「X」的正确指向是：…" |
| `preference` | `KIND_PREFERENCE` | 答案风格偏好 | "「X」：…" |

### 7.4 淘汰策略

| 项 | 语义 | 证据 |
|---|---|---|
| 每租户上限 | 记忆不能无限增长（否则注入成本失控） | `backend/app/services/agent/memory.py:56`（`MAX_ENTRIES_PER_TENANT=500`）、`:83` |

| 存储 | JSONL 追加 + 内存索引；Redis 后端由 `core/shared_state.py` 提供，未配置时用本地文件 | `backend/app/services/agent/memory.py:33-36`、`:91-114` |

### 7.5 注入提示词

`backend/app/services/agent/memory.py:190-210` 的 `render_hint()`，首行固定为：

> "以下是你之前在这个租户处理类似问题时的经验（**供参考，不必盲从**）："

措辞刻意如此——记忆是**经验**不是**事实**：知识库更新后旧经验可能已失效，让模型有权忽略它（`backend/app/services/agent/memory.py:190-191`）。

### 7.6 消费与写入路径

| 环节 | 位置 | 说明 |
|---|---|---|
| 读取 → 渲染 | `backend/app/services/agent/runner.py:747-761`（`_memory_hint()`） | 失败一律返回空串——记忆是**增强**，拿不到不该影响问答 |
| 注入 plan | `backend/app/services/agent/graph.py` 的 `plan_node`（与 replan 提示同通道合并） | — |
| 注入 think | `backend/app/services/agent/graph.py` 的 `think_node` | ReAct 模式的思考提示 |

## 九、成本账单

### 9.1 两个查询入口

| 端点 | 作用 | 租户收敛 | 证据 |
|---|---|---|---|
| `GET /ask/{trace_id}/cost` | 单次问答的成本账单，按阶段与模型归集 token 与金额 | **按租户过滤**（单租户部署下等价全可见） | `backend/app/api/ask.py:657-678`；`CostLedger.for_trace` 的租户过滤 `services/agent/cost.py:60-94` |
| `GET /admin/costs` | 成本看板：按 phase / model / tenant 聚合 + 消耗最高的问答 | 无门禁（admin 路由仍挂载，鉴权随认证下线） | `backend/app/api/admin.py` |

`/ask/{trace_id}/cost` 的 docstring 明确：`priced=False` 表示价格表未覆盖某个模型，此时金额**不可信**（显示为未知而非免费），前端应据此提示（`backend/app/api/ask.py:657-678` 的 docstring）。

### 9.2 `CostLedger` 环形缓冲

| 项 | 语义 | 证据 |
|---|---|---|
| 存储 | **进程内**环形缓冲（`deque(maxlen=...)`），非持久化 | `backend/app/services/agent/cost.py:20`、`:35-40` |
| 取舍 | 账单是运维视图，不是账务凭证；真要做账务应接供应商账单，而不是信任本地估算。保留上限避免无界增长 | `backend/app/services/agent/cost.py:9-13` |
| 记录粒度 | 按 **阶段（phase）× 模型** 归集；phase 取值 `think` / `answer` / `reflect` / `compress` | `backend/app/services/agent/cost.py:27` |
| 记账点 | think 阶段按每次工具调用的保守估算入账；answer 阶段按供应商返回的真实 usage 入账 | `backend/app/services/agent/runner.py:354-358`、`:563-567` |
| 零值丢弃 | tokens 与 cost 都为 0 的记录不入账 | `backend/app/services/agent/cost.py:42-59`（`record`） |
| 聚合维度 | `group_by` 支持 `phase` / `model` / `tenant_id` | `backend/app/api/admin.py`；实现 `services/agent/cost.py:95-127`（`aggregate`）、`:128-`（`top_traces`） |

### 9.3 `priced` / `estimated` 双标记

| 标记 | 含义 | 证据 |
|---|---|---|
| `priced`（布尔） | 价格表是否覆盖该模型；`False` = **成本未知，不是"免费"** | 字段定义 `backend/app/services/agent/cost.py:31`；单次账单聚合 `all(r.priced for r in rows)`（`:91`）；看板聚合 `:124`；写入时 `priced=(self._model_name in self._prices)`（`services/agent/runner.py:485`） |
| `estimated`（布尔） | token 用量是估算值还是供应商返回的真值 | 线性路径的 token 估算标记取自 `TokenUsage.estimated`（`backend/app/services/llm.py:70-87`；`_final` 载荷不再单列 tokens 字段）；Agent 路径 answer 阶段入账时 `priced=… and not getattr(usage,"estimated",True)`（`services/agent/runner.py:707`） |

> 两个标记正交：`priced=False` 表示"算不出钱"，`estimated=True` 表示"token 数是推算的"。前端应把 `priced=False` 显示为**未知**而非 0。

### 9.4 已知边界

| 边界 | 说明 |
|---|---|
| 非持久化 | 进程重启即清空；多副本下**每个副本各有一份**，跨副本的账单不完整 |
| 线性路径不入账 | 成本账本的写入点只在 Agent 路径（`services/agent/runner.py:354-358`、`:563-567`）；线性路径的 token 用量原先走**配额结算**（配额已下线），现在不进 `CostLedger` |
| 未知即0 | 价格表未覆盖的模型记 0 元——聚合总额因此**偏小**，`priced` 标记是唯一的可信度指示 |
