## 三、模型基线（强制约定）

Kquery 全系列**统一使用阿里云百炼（DashScope）千问平台**，**不得引入本地模型**：

| 能力 | 平台模型 |
|---|---|
| 生成 / 规划 / 评审 / 判定 | qwen-plus（默认）、qwen-max（复杂推理）、qwen-turbo（高频轻量） |
| 文本向量 | text-embedding-v3（1024 维） |
| 重排 / 证据相关度 | gte-rerank-v2 |
| 图文理解 | qwen-vl-max / qwen-vl-plus |
| OCR | qwen-vl-ocr |
| 语音转写 | paraformer-v2 |

**关键设计决策**：
- 阶段 7 放弃双塔对比模型（CLIP/BGE-VL），改为「qwen-vl-max 生成结构化描述 → text-embedding-v3 编码」→ 图像描述向量与正文向量**共用同一个向量库/向量空间**
- 阶段 9 评测必须同时绑定评测集版本 + 千问档位版本
- 阶段 9 新增「平台凭证管理」（密钥托管 / 双凭证轮换 / 启动期只校验格式）

## 四、写作约定

- **文档风格**：每篇统一"原理 → 工程要点 → 反模式清单 → 项目案例 → 落地检查清单"五段式
- **网络资料**：补充章节均标注资料来源（官方文档 / 知名开源项目 / 技术博客）
- **跨文档引用**：使用相对路径链接
- **更新策略**：每篇文档头部注明"整理日期 / 最近更新 / 依据项目"，便于追溯时效

## 五、写作原则（来自 imageIdentify）

本文档遵循 imageIdentify 的《写作原则.md》核心三条原则：

1. **不引用代码位置**（避免行号漂移；改用函数 / 类符号名）
2. **借助代码说明实现过程**（贴代码片段 + 注释）
3. **不说明每次修改过程**（当前实现的快照，不写"改造日志"）

完整规范见 imageIdentify `docs/analysis/写作原则.md`。
