## 3. 依赖方向分析

### 3.1 评测平台（最安全）

```
main.py ──import──► services/security/evalrun.py
api/security.py ──app.state.eval_*──► evalrun.py
evalrun.py ──import──► 仅标准库（hashlib/json/os/subprocess/uuid/pathlib…）
```

**零出向依赖** —— 不被任何业务模块反向引用。删除爆炸半径 = 一个文件 + 5 个端点 + 1 个前端页面。

### 3.2 报告中心（出向依赖可控）

```
main.py ──装配──► services/multiagent/{orchestrator,roles,store,blackboard,topology}
api/reports.py ──Depends──► dependencies.get_orchestrator ──► app.state.orchestrator
api/reports.py ──依赖──► acl_filter_of（共享）        ← 出向，但 acl_filter_of 保留
multiagent/* ──import──► core/{tracing,envelope,tasks}、services/agent/tools、services/llm
```

出向依赖全部指向**保留模块**（tracing / envelope / tasks / agent.tools / llm），删除 `multiagent/` 包不会让任何被引用方变成孤儿。
反向引用（`main.py`、`dependencies.py`）已在 §5 逐行列出。

### 3.3 数据存储

**两个功能都没有 SQL 表，全部 JSON 落盘**：

| 功能 | 落盘路径 | 写入点 |
|---|---|---|
| 报告 | `data_dir/reports/{report_id}.json` | `multiagent/store.py:106` |
| 评测集/运行 | `data_dir/eval/dataset-{name}@{version}.json`、`run-{run_id}.json` | `security/evalrun.py:95,117` |

全仓 `CREATE TABLE` 仅 3 处，均为 GraphRAG 与测试夹具，与本次无关。
→ **无数据库迁移需求**，只需删除空目录（`backend/data/eval/`、`backend/data/reports/`）。

## 4. 关键风险点（动手前必读）

### 🔴 R1 — `/admin/costs` 随 `reports.py` 一起消失
见 §2.1。**必须在删文件之前先迁出**（顺序见 §6.2 第 0 步）。

### 🔴 R2 — 监控大盘的多智能体指标卡片
`MonitorPage.tsx:211-255` 整块是报告中心指标。删后端后 `fetchMultiAgentMetrics()` 会 404，
而 `Promise.all`（`MonitorPage.tsx:75-85`）**任一失败即整块 catch**，导致**监控大盘整体报错、所有卡片消失**。
→ 必须同步删掉 `MonitorPage` 里的 `ma` 这一路请求，否则监控大盘直接不可用。

### 🔴 R3 — `test_stage8_multiagent.py` 被其他测试文件反向导入
`test_stage7_8_completion.py:247` 与 `:473`、`:499` 三处 `from tests.integration.test_stage8_multiagent import make_orchestrator`。
→ 删除该文件前，必须先删掉 `test_stage7_8_completion.py` 中的 `TestReportStreamEvents`(`:243`) 与 `TestParallelEventOrdering`(`:470`) 两个类，否则 **collection error**（不是断言失败，是整个测试文件导入即崩）。

### 🟡 R4 — nginx SSE 超时与 vite 代理一致性
- `deploy/nginx/nginx.conf:78` 与 `frontend/nginx.conf:56`（两份拷贝）的前缀正则含 `reports`
- `vite.config.ts:29` 注释明写"这份列表必须与 `frontend/nginx.conf` 的 location 保持一致"
→ **三处必须同步改**，否则 dev 能访问而 prod 404（或反之），属于最难排查的一类问题。
- 注意 `deploy/nginx/nginx.conf:97` 的 `proxy_read_timeout 600s` 与 `:102` 的 `/stream$` 兜底虽为报告长 SSE 设计，但 **`/ask/stream` 同样依赖**，**必须保留**。

### 🟡 R5 — `CAPABILITIES` 权限矩阵自洽
`security.py:400` 的 `{"key": "run_eval", ..., "by": "/admin/eval"}` 指向被删端点。
删该行后 `admin` 角色能力自动收口（`_ALL_CAPABILITIES` 由 CAPABILITIES 派生，`:402`）。
同时检查 `test_p0_fixes.py:988` 的权限矩阵端点测试是否对能力数有硬编码断言。

def cost_dashboard(
    request: Request,
    from_ts: float = Query(default=0.0, alias="from"),
    to_ts: float = Query(default=0.0, alias="to"),
    group_by: str = Query(default="phase", pattern="^(phase|model|tenant_id)$"),
    tenant_id: str = Query(default=""),
) -> Envelope:
    """成本看板（TASK-134）。按 phase/model/tenant 聚合，并可看消耗最高的问答。"""
    trace_id = new_trace_id(); set_trace_id(trace_id); started = now_ms()
    from app.services.agent.cost import get_ledger
    ledger = get_ledger()
    data = ledger.aggregate(since=from_ts or None, until=to_ts or None,
                            tenant_id=tenant_id or None, group_by=group_by)
    data["top_traces"] = ledger.top_traces(limit=10)
    return ok_envelope(data, trace_id, elapsed_ms_since(started))
