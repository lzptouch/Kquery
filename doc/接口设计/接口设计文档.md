## 1. 概述

KQuery Pro API 采用 RESTful 风格设计，基于 FastAPI 框架构建。所有业务接口均挂载在 `/api/v1` 前缀下，支持 JSON 格式的请求与响应。接口涵盖文档处理、语义检索、知识图谱构建与查询、GraphRAG 混合检索、用户认证授权、异步任务管理等核心功能。

系统采用 **七层架构** 设计，从外到内依次为：多端交互层、API 网关层、会话管理层、业务服务层、核心决策层、连接集成层、数据持久层。

### 1.1 中间件栈

请求经过的中间件顺序（由外到内）：

```
安全头 → CORS → 速率限制 → 请求日志 → Prometheus → 审计日志
```

### 1.2 通用认证方式

接口认证采用 JWT Bearer Token 方式：

```
Authorization: Bearer <access_token>
```

未认证请求返回 `401 Unauthorized`，无权限请求返回 `403 Forbidden`。

## 2. 基础 URL 与通用规范

### 2.1 基础 URL

| 环境 | 基础 URL |
|------|---------|
| 本地开发 | `http://localhost:8000/api/v1` |
| Docker 部署 | `http://<host>:8000/api/v1` |

### 2.2 通用响应格式

```json
// 成功响应
{
  "data": { ... },
  "message": "success"
}

// 错误响应
{
  "detail": {
    "error": "ERROR_CODE",
    "message": "错误描述",
    "details": { ... }
  }
}
```

### 2.3 HTTP 状态码

| 状态码 | 说明 |
|--------|------|
| 200 | 请求成功 |
| 201 | 创建成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 429 | 请求频率超限 |
| 500 | 服务器内部错误 |

### 2.4 请求头

| 请求头 | 说明 | 必需 |
|--------|------|------|
| `Authorization` | Bearer Token | 认证接口除外 |
| `Content-Type` | `application/json` 或 `multipart/form-data` | 是 |
| `Accept-Language` | `zh-CN` 或 `en-US`（国际化支持） | 否 |

## 3. 七层架构路由结构概览

```
/api/v1/
│
├── 🌐 第一层：多端交互层 (Multi-Client Interaction Layer)
│   ├── ws/*                       # WebSocket 实时通信
│   ├── voice/*                    # 语音上传接口
│   └── sse/*                      # SSE 流式对话
│
├── 🔐 第二层：API 网关层 (API Gateway Layer)
│   ├── auth/*                     # 认证接口
│   └── rbac/*                     # RBAC 权限管理
│
├── 💬 第三层：会话管理层 (Session Management Layer)
│   ├── sessions/*                 # 会话创建/恢复/清理
│   └── health/live                # 存活检查与会话活性
│
├── 🧩 第四层：业务服务层 (Business Service Layer)
│   ├── kquery/*                   # 文本 RAG 接口
│   ├── knowledge-graph/*          # 知识图谱接口
│   └── graph-rag/*                # GraphRAG 混合检索
│
├── 🧠 第五层：核心决策层 (Core Decision Layer)
│   ├── agent/*                    # Agent 对话接口
│   └── tasks/*                    # 异步任务接口
│
├── 🔗 第六层：连接集成层 (Integration Layer)
│   ├── crm/*                      # CRM 对接接口
│   ├── orders/*                   # 订单查询接口
│   └── external/*                 # 外部服务管理
│
└── 🗄️ 第七层：数据持久层 (Data Persistence Layer)
    ├── config/*                   # 配置管理
    ├── health                      # 健康检查
    ├── health/ready                # 就绪检查
    ├── health/detailed             # 详细健康状态
    └── metrics                    # Prometheus 监控指标
```

### 各层职责说明

| 层次 | 层名 | 职责 |
|------|------|------|
| 1 | **多端交互层** | 处理 WebSocket、SSE、语音等实时/流式通信协议，适配多种客户端 |
| 2 | **API 网关层** | 认证鉴权、RBAC 权限控制、速率限制、请求路由 |
| 3 | **会话管理层** | 会话生命周期管理（创建、恢复、清理、活性检测） |
| 4 | **业务服务层** | 核心业务逻辑：RAG 检索、知识图谱查询、GraphRAG 混合检索、话术模板 |
| 5 | **核心决策层** | Agent 智能对话、流程编排与执行引擎 |
| 6 | **连接集成层** | 外部系统对接：CRM、订单系统、第三方服务适配 |
| 7 | **数据持久层** | 配置持久化、数据管理接口、健康检查与监控指标暴露 |

## 4. 第一层：多端交互层接口

基础路径：`/api/v1`

多端交互层负责处理 WebSocket 实时通信、语音上传、SSE 流式对话等非标准 HTTP 协议，适配不同客户端（Web、移动端、桌面端等）。

| 方法 | 路径 | 说明 | 协议 |
|------|------|------|------|
| `WebSocket` | `/ws/chat` | WebSocket 实时对话 | WebSocket |
| `POST` | `/voice/upload` | 语音文件上传 | HTTP |
| `POST` | `/sse/chat` | SSE 流式对话（Agent 流式接口别名） | SSE |

### 4.1 WebSocket 实时对话

```
WebSocket /api/v1/ws/chat?token=<jwt_token>
```

**消息格式（客户端 → 服务端）：**
```json
{
  "type": "message",
  "session_id": "会话ID",
  "content": "用户消息",
  "collection_name": "default"
}
```

**消息格式（服务端 → 客户端）：**
```json
{
  "type": "message",
  "content": "回复内容",
  "session_id": "会话ID"
}
{
  "type": "status",
  "status": "thinking|done|error",
  "message": "状态描述"
}
```

### 4.2 语音上传接口

```
POST /api/v1/voice/upload
Content-Type: multipart/form-data

file: <音频文件>
session_id: 会话ID
collection_name: default
```

**支持格式：** WAV、MP3、OGG、M4A、AMR

响应：
```json
{
  "task_id": "uuid-string",
  "text": "语音识别文本",
  "duration": 12.5
}
```

### 4.3 SSE 流式对话

```
POST /api/v1/sse/chat
Content-Type: application/json

{
  "message": "用户消息",
  "session_id": "会话ID（可选，不传则创建新会话）",
  "collection_name": "default"
}
```

响应为 Server-Sent Events (SSE) 流式输出。

> **说明：** `/api/v1/agent/chat/stream` 为内部路由，多端交互层通过 `/sse/chat` 对外暴露流式对话能力，两者功能一致。

## 5. 第二层：API 网关层接口

API 网关层提供认证鉴权、RBAC 权限控制和速率限制能力。

### 5.1 认证接口

基础路径：`/api/v1/auth`

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/auth/register` | 用户注册 |
| `POST` | `/auth/login` | 用户登录 |
| `POST` | `/auth/refresh` | 刷新 Token |
| `POST` | `/auth/logout` | 登出 |
| `GET` | `/auth/me` | 获取当前用户信息 |
| `PUT` | `/auth/me/password` | 修改密码 |

#### 5.1.1 注册

```
POST /api/v1/auth/register
Content-Type: application/json

{
  "username": "string",
  "password": "string",
  "email": "string"
}
```

响应：
```json
{
  "user_id": "string",
  "username": "string"
}
```

#### 5.1.2 登录

```
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "string",
  "password": "string"
}
```

响应：
```json
{
  "access_token": "string",
  "refresh_token": "string",
  "token_type": "bearer",
  "expires_in": 86400
}
```

**Token 有效期**：
- Access Token：24 小时
- Refresh Token：7 天
- Token 黑名单：Redis 存储已登出的 Token

### 5.2 RBAC 权限管理接口

基础路径：`/api/v1/rbac`

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/rbac/roles` | 角色列表 |
| `POST` | `/rbac/roles` | 创建角色 |
| `PUT` | `/rbac/roles/{id}` | 更新角色 |
| `DELETE` | `/rbac/roles/{id}` | 删除角色 |
| `GET` | `/rbac/permissions` | 权限列表 |
| `GET` | `/rbac/users` | 用户列表 |
| `PUT` | `/rbac/users/{id}/role` | 设置用户角色 |
| `PUT` | `/rbac/users/{id}/status` | 切换用户状态 |
| `GET` | `/rbac/users/{id}` | 获取用户详情 |
| `POST` | `/rbac/roles/{id}/permissions` | 设置角色权限 |

#### 5.2.1 权限模型

预置的 13 个权限：

| 权限标识 | 说明 |
|---------|------|
| `read:document` | 读取文档 |
| `write:document` | 创建文档 |
| `delete:document` | 删除文档 |
| `manage:collection` | 管理集合 |
| `manage:user` | 管理用户 |
| `query:collection` | 查询集合 |
| `manage:role` | 管理角色 |
| `manage:permission` | 管理权限 |
| `read:knowledge-graph` | 读取知识图谱 |
| `write:knowledge-graph` | 写入知识图谱 |
| `manage:knowledge-graph` | 管理知识图谱 |
| `manage:config` | 管理配置 |
| `manage:system` | 系统管理 |

预置的 4 个角色：

| 角色 | 权限范围 |
|------|---------|
| `super_admin` | 全部权限 |
| `admin` | 文档/集合/用户管理 |
| `editor` | 文档读写和知识图谱操作 |
| `viewer` | 文档只读和查询权限 |

#### 5.2.2 速率限制策略

API 网关层对以下端点实施速率限制：

| 路径 | 限制策略 |
|------|---------|
| `/auth/login` | 每分钟 10 次/IP |
| `/auth/register` | 每小时 5 次/IP |
| `/kquery/documents/query` | 每分钟 60 次/用户 |
| `/agent/chat` | 每分钟 30 次/用户 |
| 其余接口 | 每分钟 120 次/用户 |

## 6. 第三层：会话管理层接口

会话管理层负责会话的创建、恢复、清理和活性检测。

基础路径：`/api/v1/sessions`

| 方法 | 路径 | 说明 |

```
GET /api/v1/sessions/{session_id}
```

```json
{
```

### 6.3 清理会话

```
DELETE /api/v1/sessions/{session_id}
```

响应：

### 6.4 会话心跳保活

```
PUT /api/v1/sessions/{session_id}/heartbeat
```

响应：
```json
{
  "session_id": "uuid-string",
  "ttl_extended": true,
  "expires_at": "2026-06-20T12:30:00Z"
}
```

## 7. 第四层：业务服务层接口

业务服务层提供核心业务能力，包括文本 RAG 检索、知识图谱查询和 GraphRAG 混合检索。

### 7.1 文本 RAG 接口

基础路径：`/api/v1/kquery`

| 方法 | 路径 | 说明 | 参数 |
|------|------|------|------|
| `POST` | `/kquery/documents/process` | 处理单个文档 | `file`, `collection_name`, `chunk_size`, `chunk_overlap` |
| `POST` | `/kquery/documents/process-batch` | 批量处理文档 | `files[]`, `collection_name`, `max_concurrency` |
| `POST` | `/kquery/documents/add-text` | 直接添加文本 | `text`, `collection_name`, `metadata` |

| `GET` | `/kquery/collections` | 列出所有集合 | — |
| `GET` | `/kquery/collections/{name}/stats` | 集合统计 | `collection_name` |
| `DELETE` | `/kquery/collections/{name}` | 清空集合 | `collection_name` |
| `GET` | `/kquery/supported-file-types` | 支持的文件类型 | — |
| `GET` | `/kquery/status` | 服务状态 | — |

#### 7.1.1 文档处理

```
POST /api/v1/kquery/documents/process
Content-Type: multipart/form-data

file: <文档文件>
collection_name: default
```

#### 7.1.2 语义查询

```
POST /api/v1/kquery/documents/query
Content-Type: application/json

{
```

### 7.2 知识图谱接口

基础路径：`/api/v1/knowledge-graph`

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/knowledge-graph/entities/extract` | 实体抽取 |
| `POST` | `/knowledge-graph/relations/extract` | 关系抽取 |
| `POST` | `/knowledge-graph/build` | 图谱构建 |
| `POST` | `/knowledge-graph/query` | 图谱查询 |

#### 7.2.1 图谱查询

```
POST /api/v1/knowledge-graph/query
Content-Type: application/json

{
  "query": "查询内容",
  "query_type": "subgraph|path|neighbors|pagerank",
  "depth": 2,
  "limit": 20
}
```

### 7.3 GraphRAG 接口

基础路径：`/api/v1/graph-rag`

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/graph-rag/query` | GraphRAG 混合检索 |
| `GET` | `/graph-rag/stats` | 统计信息 |

#### 7.3.1 混合检索

```
POST /api/v1/graph-rag/query
Content-Type: application/json

{
  "query": "查询内容",
  "collection_name": "default",
  "top_k": 5,
  "enable_graph": true,
  "enable_hyde": true
}
```

**5 阶段检索流程**：
1. 问题分类（8 种类型：FACTOID/RELATION/REASONING/LISTING/COMPARISON/DEFINITION/PROCEDURAL/UNKNOWN）
2. 查询实体抽取
3. 图谱上下文扩展（Local Search / Global Search / 路径发现）
4. 向量语义检索（向量检索 + HyDE 增强 + BM25 关键词检索）
5. 结果融合与重排序（自适应权重 + 多样性惩罚 + Reranker）

## 11. 错误码体系

系统定义 40+ 错误码，组织为 7 大类：

| 错误码前缀 | 类别 | 说明 |
|-----------|------|------|
| `AUTH_*` | 认证错误 | Token 过期、无效凭证、权限不足 |
| `VALIDATION_*` | 验证错误 | 参数非法、文件格式不支持 |
| `NOT_FOUND_*` | 资源不存在 | 集合、文档、用户不存在 |
| `RATE_LIMIT_*` | 限流错误 | 请求频率超限 |
| `DATABASE_*` | 数据库错误 | 连接失败、查询超时 |
| `EXTERNAL_*` | 外部服务错误 | LLM API 调用失败 |
| `INTERNAL_*` | 内部错误 | 系统内部异常 |

### 11.1 数值错误码范围（简要参考）

| 数值范围 | 含义 |
|---------|------|
| `0` | 成功 |
| `1xxx` | 客户端错误（参数校验） |
| `2xxx` | 认证/授权错误 |
| `3xxx` | 业务错误（知识库/文档不存在） |
| `4xxx` | AI 服务错误 |
| `5xxx` | 外部服务错误（Milvus/Neo4j） |
