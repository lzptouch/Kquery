## 0. 为什么 Kquery 的测试计划必须"以格式为轴"

### 0.1 与 koder 的根本差异

koder 是 Electron 桌面应用，最大风险面在**打包态**与**原生层**；Kquery 是服务端 RAG 系统，最大风险面在**解析**与**检索质量**。两者不可套用同一份用例表。差异在下表 8 点：

| # | 通用做法默认的假设 | Kquery 的实际情况 | 直接后果 |
| --- | --- | --- | --- |
| 1 | "上传 = 存文件" | 上传 = **解析 → 切块 → embed → 向量库 + BM25 + DocStore + 表格 + 资源** 五级落地，任一级失败即"上传成功但检索不到" | 必须断言**可检索性**，不能只断言 HTTP 200 |
| 2 | "解析成功 = 有内容" | `PdfParser` 对**加密 PDF / 损坏 PDF / 扫描件无 OCR** 三种情况都**抛错**（3003），对**扫描页超上限**只写 warning（`pdf.py:80-87`） | 必须区分"失败"与"静默半成功"（warning 不阻断） |
| 3 | "文件格式"是少数几种 | Kquery 支持 **10 个格式分组、52 个扩展名、8 个解析器类**（`parsers/router.py:27-36`），每类解析器有**各自独立的限额与错误码**（3003 / 3201 / 3202） | 一份"上传成功"断言覆盖不了格式差异 → 必须按格式建矩阵（见 `01` 文档） |
| 4 | "PDF 是一种格式" | PDF 在 Kquery 里是**唯一带双路径**（文字页 / 扫描页 OCR）的格式，且带 **6 个策略开关**（`pdf_ocr` / `pdf_tables` / `pdf_ocr_dpi` / `pdf_ocr_max_pages` / `pdf_scan_min_chars` / `assets_dir`） | PDF 必须**单独一套专项**，不能并入通用格式用例 |
| 5 | "检索质量靠人工看" | Kquery **有完整的质量机制**（混合检索 → RRF → 重排 → CRAG 三分支 → 幻觉自检 → 受限重生成 → 拒答），但**没有金标集**（`../analysis/12-测试与验证.md` §八） | 机制可测、质量不可测 → 必须把"机制正确性"与"质量高低"分开断言 |
| 6 | "数据是干净的" | `Text_SCANABLE_EXTENSIONS` 只覆盖**纯文本类**，**`.pdf` / `.docx` 不在入口 PII 扫描白名单**（`test_batch_b_security.py:415-421`） | 二进制格式的 PII 入库侧是**已知盲区**，必须显式登记为风险用例 |
| 7 | "文件能解析就等于内容对" | 表格被**单独成块**（`chunker="table"` / `modality="table"`，`services/knowledge.py:318-345`），正文段不含表格内容 | 断言必须区分"表格在 `tables[]` 里"与"表格在 `chunks[]` 里" |
| 8 | "跑通一次就算过" | `e2e_ui` 有**独立 conftest**，端口 5173/8100 不通就 skip，且会校验页面标题含 "Kquery" 才跑（`backend/tests/e2e_ui/conftest.py:81-93`） | **skip 是本项目最常见的"假绿"来源**，必须统计并公示 skip 数 |

### 0.2 本计划的三条设计原则

1. **格式优先**：每个格式必须独立成组（`DOCX-` / `XLSX-` / `PPTX-` / `MD-` / `TXT-` / `HTML-` / `CODE-` / `IMG-` / `AUD-`），PDF 单独成篇（`PDF-`，见 `01` 文档），不允许用一个"多格式批量上传"用例糊弄；
2. **可检索性断言**：凡"入库成功"的用例，最终必须有一条**从检索侧回读**的断言（`/ask` 出证据、`/knowledge/preview` 出块），否则视为**未测**；
3. **失败必须可归因**：每条用例的判定依据落在**磁盘/向量库/数据库/响应体**这些"OS 可见的事实"上，而不是"UI 说了什么"。

## 1. 被测形态：四个测试层 × 三种运行态

### 1.1 四个测试层

| 层 | 位置 | 定位 | 主工具 | 不应覆盖 |
| --- | --- | --- | --- | --- |
| **unit** | `backend/tests/unit/`（30 文件 / 369 用例） | 解析器 / 切块 / 安全 / 状态机 / 存储适配的纯逻辑 | pytest + mock | 不打 HTTP、不依赖 lifespan 装配 |
| **integration** | `backend/tests/integration/`（26 文件 / 565 用例） | TestClient 全链路：端点 + 真实管线 + 真实向量库（milvus-lite） | pytest | 不验真实 LLM 行为 |
| **e2e** | `backend/tests/e2e/`（2 文件 / 19 用例） | 对**运行中**服务的 API 端到端；含 OpenAPI 全端点巡检 | pytest + httpx | 不做 UI 断言 |
| **e2e_ui** | `backend/tests/e2e_ui/`（4 文件 / 32 用例） | 浏览器级页面链路（独立 conftest，Playwright + 系统 Edge） | pytest + Playwright | 不做单元级断言 |
| **前端单测** | `frontend/tests/`（8 文件 / 48 用例） | 组件 / 工具函数 | vitest + jsdom | 不调真实后端 |
| **脚本级** | `scripts/`（7 个） | 对**部署实例**的冒烟 / 扫描 / 浏览器 / 压测 | Python + httpx | 不进 CI（现状缺口） |

### 1.2 三种运行态（**必须分开测**）

| 运行态 | 启动方式 | 向量库 | Redis | 认证 | 用例前缀 |
| --- | --- | --- | --- | --- | --- |
| **源码态** | `uv run pytest`（进程内 TestClient） | milvus-lite 文件库（win32 回退 faiss，`conftest.py:40-48`） | 无（进程内降级） | `AUTH_ENABLED=false` 走 Header 透传 | `KRN-` `ING-` `ASK-` `RET-` `VAL-` `GRF-` `SEC-` `OPS-` `PDF-` |
| **单机态** | `uv run uvicorn app.main:app` + `npm run dev` | milvus-lite | 可选 | 真实认证档 | `E2E-` `WEB-` |
| **部署态** | `docker compose up -d --build` | milvus 2.6.4 standalone | redis:7-alpine | 真实认证档 + 真实卷 | `DEP-` `PERF-` |

> **部署态失败，不得用"源码态是好的"关闭。**

## 2. 工具选型与铁律

### 2.1 分层选型矩阵

| 要测的东西 | 首选工具 | 能拿到的可分析结果 | 不选什么 / 为什么 |
| --- | --- | --- | --- |
| 解析器单元行为 | **pytest + pymupdf 现场造件** | 函数级断言、warnings 内容、TableRecord 字段 | 不引入真实样本文件做单元测试（体积大、来源不可追溯）；真实样本只进夹具层（`01` §十一） |
| 解析 → 索引 → 可检索 | **integration + TestClient** | preview 的 chunks/tables/outline + `/ask` 的 evidence | 只断言 `status == "indexed"`（假绿来源，见 `01` §二.3） |
| PDF 版式还原度 | **PDF 文本 + 结构快照 diff**（提取关键字段做快照） | 文本差异、表格行列数、outline 层级 | 人工看 PDF 渲染（不可回归、不可量化） |
| 端点可达性 | **OpenAPI 自动枚举巡检**（`tests/e2e/test_all_endpoints.py` 已存在） | 逐端点 PASSED/REJECTED/FAILED | 手写端点清单（必然漏、必然漂移） |
| 前端交互 | **vitest + testing-library**（已有 48 用例） | 组件级断言、payload 校验 | 大量 `sleep` + 端到端浏览器（慢且不稳） |
| 浏览器级页面 | **Playwright（系统 Edge channel=msedge）** | 页面内容断言、JS 错误捕获 | 硬编码像素坐标 |
| 部署面 | **docker compose + `curl` / `scripts/*.py`** | 容器健康、端点状态、端口映射 | 只看 `docker compose up` 退出码 |
| 容量与并发 | **`scripts/load_test.py`（5 场景）** | P50/P95、失败数、限流命中 | 只测单请求 |
| 检索质量 | **金标集（⛔ 待建）** | recall@k / nDCG | 当前**无金标集** → 只能测机制不能测质量（`../analysis/12` §八） |

### 2.2 三条铁律

1. **入库成功 ≠ 内容可用**。凡是 `status == "indexed"` 的用例，必须再断言 `preview.chunks` 非空 **且**（至少一条）`/ask` 能召回该文件的特征串。否则该用例判为 **未覆盖**。
2. **warning 必须被断言**。Kquery 有多条"只 warning 不阻断"的路径（PDF 扫描页超上限、xlsx 超限截断、pptx 空内容、纯文本超 200 万字符截断）。这些路径是**静默半成功**的主要来源，必须逐条断言 warning 文本关键词。
3. **skip 必须公示**。`e2e_ui` 在端口不通时 skip、`e2e` 在服务未起时 skip。**任何 skip 必须在报告中单列**，且"skip 数上升"视为门禁失败（防止用例集体不执行而全绿）。

### 2.3 已知工具禁忌

| 禁忌 | 原因 |
| --- | --- |
| 用真实模型（千问）跑 CI | CI 全 `MODEL_PROVIDER=mock`（`conftest.py:36`）；真实模型路径只能人工本地验证（`../analysis/12` §八） |
| 用仓库根目录当测试工作区 | 会污染真实数据卷；测试必须走 `TemporaryDirectory`（`conftest.py:34-35`） |
| 共用 `DATA_DIR` / 共用端口 | 用例串扰；e2e_ui 的 5173 被别的 vite 占用时会**假红**（`e2e_ui/conftest.py:84-93` 已有标题校验兜底） |
| 把 `.pdf` / `.docx` 送进 PII 入口扫描白名单 | 二进制格式**不在** `TEXT_SCANABLE_EXTENSIONS` 内（`test_batch_b_security.py:415-421`），这是**现状**，测试不得"假设已覆盖" |
| 只断言 HTTP 状态码 | 本项目大量"400 + 可读文案"是**成功路径**（如 `.xls` 提示另存为 `.xlsx`、`router.py:39-42`），只断言状态码会漏掉文案回归 |

## 5. 结果规范：怎么拿到"可分析"的结果

> 原则：**一次运行 = 一个 runId = 一个自包含目录**。任何人拿到这个目录，不看录屏也能定位到行号与文件。

### 5.1 目录结构

```text
doc/testing/artifacts/<runId>/            # runId = <UTC时间戳>-<git短哈希>
├── report.json                # 统一结果（schema 见 5.2）
├── report.junit.xml           # JUnit（CI 消费）
├── summary.md                 # 人读汇总（含发布判定）
├── env.json                   # 环境指纹（git/OS/Python/Node/向量库/端口占用）
├── cases/
│   └── PDF-03/
│       ├── result.json        # 单用例：status/duration/errorCode/steps
│       ├── stdout.log         # pytest / vitest 原始输出
│       ├── screenshots/       # 仅 e2e_ui 层：失败自动截图
│       ├── fixtures/          # 本用例生成的输入文件元数据（页数/字节数/sha256）
│       └── preview.json       # 解析产物快照（segments/tables/outline/warnings）
├── format-report.json         # 格式专项汇总（10 个格式分组 × 能力矩阵）
├── classify.json              # 失败自动归类汇总
└── layers/                    # 每层原始报告快照（保证工件自包含）
```

### 5.2 `report.json` schema

```json
{

  "startedAt": "2026-10-30T03:12:00Z",
  "durationMs": 184320,
```

### 5.3 各层必备产物

| 层 | 必备 | 可选 |
| --- | --- | --- |
| pytest | JUnit XML、`preview.json`（解析类用例） | coverage.xml |

| 脚本级 | `scripts/*.py` 的断言汇总 | 压测 P95 曲线 |

### 5.4 失败自动取证（pytest 钩子，⛔ 待建）

```python
# conftest.py 增补：解析类用例失败时保留输入件与解析产物
@pytest.hookimpl(hookwrapper=True)
def pytest_runtest_makereport(item, call):
    outcome = yield
    rep = outcome.get_result()
    if rep.when != "call" or rep.passed:
        return
    case_dir = Path("doc/testing/artifacts") / run_id / "cases" / item.name
    case_dir.mkdir(parents=True, exist_ok=True)
    # 1) 复制本用例生成的输入文件（按 sha256 命名）
    for f in getattr(item, "funcargs", {}).get("_generated_files", []) or []:
        shutil.copy(f, case_dir / "fixtures" / f.name)
    # 2) dump 解析产物快照
    preview = getattr(item, "funcargs", {}).get("_last_preview", None)
    if preview:
        (case_dir / "preview.json").write_text(json.dumps(preview, ensure_ascii=False, indent=2))
```

### 5.5 格式专项的基线快照

- 目录：`doc/testing/baselines/formats/<format>/<case>.json`；
- 只对**结构性输出**建基线（PDF 的 outline 层级、表格 rows/cols、segments 的 source 列表），**不**对全文文本建基线（不同 pymupdf 版本换行会有微差 → 噪声）；
- 阈值：`maxDiffPixelRatio` 不适用于此（无像素）；改为**键级精确比对 + 允许字段白名单**；
- 基线更新必须走 PR 并附差异，不允许测试里自动覆盖。

### 5.6 汇总与趋势

1. `report-merge.mjs` 把 pytest JUnit + vitest JSON + e2e_ui JSON 合并为统一 `report.json`；
2. 生成 `summary.md`（按层/优先级分组，失败置顶，附 skip 统计）；
3. CI 保留最近 20 次 `report.json`，用于 flaky 率与耗时趋势；**失败率 > 2% 的用例自动进隔离清单**。

## 6. 错误分析：从"看到失败"到"定位责任层"

### 6.1 日志三件套

| 日志 | 位置 | 关键内容 |
| --- | --- | --- |
| `backend.log` | 后端 stdout/stderr（`log_format=json`） | 请求 trace_id、解析阶段、错误码、耗时、warning |
| `frontend.log` | 浏览器 console + pageerror | 未捕获异常、API 错误、SSE 中断 |
| `compose.log` | `docker compose logs` | 六服务启动顺序、healthcheck、restart 计数 |

**关联键**：所有日志行带 `trace_id`（入站复用 `X-Trace-Id`，`core/tracing.py`）；每条用例开始写一条 `=== CASE <id> @ <iso> ===` 分隔符 → 失败时可精确定位时间窗。

### 6.2 失败定位决策树

| 现象 | 首查证据 | 常见根因 | 责任层 |
| --- | --- | --- | --- |
| **上传返回 200 但检索不到** | `preview.chunks` 是否非空；`/ask` 的 evidence | 切块产出 0 块（已触发质量红线但**未阻断**）；向量写入数 ≠ 块数（`services/knowledge.py:386-390` 中止）；BM25 未落 | 切块 / 索引 |
| **上传 200 但内容是空的** | `preview.json` 的 `warnings` | PDF 扫描页超 `ocr_max_pages` 只 warning 不阻断（`pdf.py:80-87`）；xlsx/pptx 超限截断；纯文本超 200 万字符截断 | 解析（**静默半成功**） |
| **上传直接报错 3003** | `backend.log` 的 message | PDF 加密（`needs_pass`）/ 损坏（open 失败）/ 全篇无文本且 OCR 不可用 | 解析 |
| **上传直接报错 3201** | message 文案 | xlsx/pptx/纯文本 打开失败或空内容 | 解析 |
| **上传报 3101** | 扩展名 | 不在 `SUPPORTED_EXTENSIONS`（`router.py:27-36`） | 契约 |
| **上传报 2003** | message | 旧码路径；`.xls`/`.ppt` 有专门可读提示（`router.py:39-42`） | 契约 |
| **PDF 表格查不到** | `preview.tables` | `pdf_tables=False` 策略；表格 rows<2 或 cols<2 被丢弃；OCR 表格正则需 ≥3 行连续 `\|`（`pdf.py:34`） | 解析 |
| **PDF 大纲为空** | `preview.outline` | 样本 <3 行 → 返回空（`pdf.py:223-224`）；标题长度 >60 被排除（`pdf.py:227`） | 解析（**设计如此，非缺陷**） |
| **双栏 PDF 文本混杂** | `preview.segments` 顺序 | `get_text(sort=True)` 只缓解不根治（`pdf.py:70`） | 解析（已知限制） |
| **图谱查不到实体** | `preview` 是否产出实体 | 图存储不可用 → 建图失败但**入库成功**（只 warning） | 图谱 |
| **用户看不到别人的文档**（应看不到却看到） | `acl_filter_of` 闭包内容 | `acl_enabled=false` → KB 判定整体失效（**已知耦合缺口 D10-18**） | 安全 |
| **权限边界偶发失效** | 缓存键中的复合版本号 | 撤权后旧缓存未失效 → 检查 `kb_version` 是否进键 | 安全 |
| **401 但配置是关的** | 环境变量 | `AUTH_ENABLED=false` 只在**进程启动时**读取；测试改了环境变量没重启进程 | 测试自身 |
| **e2e_ui 集体 skip** | 端口 5173 / 8100 | 端口被占用或服务未起 → `e2e_ui/conftest.py:81-83` skip | 环境（**必须公示**） |
| **用例集体失败但像是环境问题** | `env.json` | 端口占用 / 磁盘满 / Milvus 未起 / 向量库锁文件 | env |

### 6.3 错误码映射

| 错误码 | 含义 | 首查 |

| `E_PARSE_FAILED` | 解析抛错 | `backend.log` 的 ErrCode 与 message |

### 6.4 自动归类（`classify.json`）

规则优先级从高到低，命中即归类，避免"一切都算业务 bug"：

| 归类 | 判据 | 处理 |
| --- | --- | --- |
| `env` | 端口占用 / 磁盘满 / Milvus 未起 / 缺向量库 | 修环境，不计缺陷 |
| `skip` | 状态为 `skipped` 且原因属端口/凭据 | 统计并公示；连续两次 skip → 视为门禁失败 |
| `parser` | 失败点在解析器（`E_PARSE_*`） | 解析层缺陷 |
| `chunking` | 失败点在切块（`E_CHUNK_*`） | 切块层缺陷 |
| `index` | 失败点在索引（`E_INDEX_*`） | 索引层缺陷 |
| `retrieval` | 失败点在检索（`E_RETRIEVAL_*`） | 检索层缺陷 |
| `security` | 失败点是越权（`E_ACL_LEAK`） | **P0 缺陷，阻塞发布** |
| `contract` | 错误码 / 信封 / 白名单不符 | 契约缺陷 |
| `test` | 重跑 3 次中 ≥2 次通过（flaky），或失败发生在 setup | 修测试，同时登记 flaky |

**flaky 判定**：同用例连续重跑 3 次，2 次以上通过 → 标记 `flaky`，附 3 份 trace；**不得直接 `retry` 掩盖**（允许 1 次重试仅用于抵消 Milvus/OCR 冷启动抖动，且必须在报告中记录 `attempts`）。

### 6.5 已知坑清单（新用例先查）

1. **e2e_ui 集体 skip**：`backend/tests/e2e_ui/conftest.py:81-83` 在端口不通时 skip，**这是最常见的假绿来源**；必须统计 skip 数并公示。
2. **`AUTH_ENABLED` 启动时读取**：改环境变量不重启进程 → 权限断言全红但产品没问题。
3. **向量库锁文件**：Windows 上 milvus-lite 的 `AllocTimestamp` 未实现且锁文件 teardown 被占用 → conftest 在 win32 回退 faiss（`conftest.py:43-48`）；**Windows 本地绿 ≠ Linux CI 绿**（缺口 G7）。
4. **CRAG 阈值贴合 Mock 评分分布**：测试用 0.3/0.1（`conftest.py:49-51`），**生产默认须按真实评测集标定** → 换模型后阈值用例会翻红。
5. **`.env` 里的真实凭据会被读进来反转断言**：`SPEECH_ASR_PROVIDER=none` 就是为此设的（`conftest.py:52-56`）。
6. **PDF 加密/损坏是 3003 而非 3201**：断言错误码时不要按"解析失败=3201"想当然。
7. **`.xls` / `.ppt` 的 400 是成功路径**：文案必须含 "xlsx"/"pptx"（`router.py:39-42`），只断言状态码会漏文案回归。
8. **二进制格式不在 PII 白名单**：`.pdf`/`.docx` 不走入口 PII 扫描，不要写"上传含手机号的 PDF 应被拦截"这种**期望即错**的用例。
9. **`pypdf` 是死依赖**：`pyproject.toml:16` 声明但代码零 import；不要基于它写用例。
10. **覆盖率门槛可能只报告不拦截**：`fail_under=80` 在 `[tool.coverage.report]`，但 CI 命令未传 `--cov-fail-under`（缺口 G3）。

### 7.3 `harness.mjs` 关键约定

```js
// 产物与数据定位：绝不硬编码端口或路径，base 单一来源
export function resolveBase({ layer, base } = {}) {
  const map = {
    "unit": null, "integration": null, "e2e": "http://127.0.0.1:8100",
    "e2e_ui": "http://127.0.0.1:5173", "scripts": "http://127.0.0.1:8100",
    "compose": "http://127.0.0.1:8100",
  };
  return base ?? process.env.KQUERY_BASE ?? map[layer];
}

// skip 必须公示：不允许"因为端口不通所以全绿"
export function assertNoSilentSkip(report) {
  const masked = report.cases.filter(c => c.status === "skipped" && c.reasonKind === "env");
  if (masked.length > 0) {
    throw new Error(`E_SKIP_MASQUERADE: ${masked.length} 条用例被环境原因跳过`);
  }
}
```

- **缺环境必须失败，不许 skip**：`e2e` / `e2e_ui` / `DEP` / `PERF` 在服务未起时报 `E_ENV_PORT`，避免"没起服务所以全绿"；
- **每个用例独立 `DATA_DIR` + 独立端口探测**，`afterEach` 递归删除；
- **超时分三档**：`启动 90s`、`端点 30s`、`动作 15s`，禁止全局一个 30s。

## 9. 缺陷分级与发布判定

| 级别 | 定义 | 示例 | 处置 |
| --- | --- | --- | --- |
| **Blocker** | 主链路不可用或数据错误 | PDF 上传后整篇检索不到；越权可见他人文档；部署态后端起不来 | 阻断发布 |
| **Critical** | 静默错误结果 | 表格被拦腰切断；扫描页因超上限**静默不入库**；OCR 表格混入正文 | 阻断发布 |
| **Major** | 主流程可用但有明显缺陷 | 扫描页判定阈值误伤；outline 层级错乱；`.doc` 无转换器时报错文案不清 | 带风险发布需签字 |
| **Minor** | 局部体验/边界 | 双栏 PDF 文本次序不完美；warning 文案不精确 | 下个迭代 |
| **Trivial** | 文案/样式 | — | 排期 |

**发布门禁（全绿才可发）**：

1. `unit` + `integration` **0 失败**；
2. `e2e` 0 失败；`e2e_ui` **P0 全通过且 skip 数与上次持平**；
3. `vitest` 0 失败；
4. **格式专项 P0 全通过**（PDF 13 类样本矩阵必须全绿 —— 这是本计划的第一门禁）；
5. `SEC` 组 P0 全通过（越权是**零容忍**）；
6. `DEP` 组 P0 全通过（六服务健康 + 端口 + 卷持久化 + 两种降级）；
7. `PERF-02` 通过（背压不挂死）；
8. `summary.md` 与 skip 统计已归档。

> **门禁顺序即优先级**：格式专项排在安全之后、部署之前 —— 因为"格式解析不过，其余都不必测"。
