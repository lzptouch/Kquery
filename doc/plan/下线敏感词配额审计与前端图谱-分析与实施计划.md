## 1. 需求与范围决策

| 决策点 | 结论 |
|---|---|
| 配额删除范围 | **全删**：租户滑动窗口配额（分钟/每日/token 三维）+ 平台侧账号额度监控（PlatformQuotaMonitor）+ `/admin/quota*` 端点。**保留**：登录限流（`auth.py` 独立桶，6 次/分钟）与令牌桶突发限流（`enforce_rate_limit` 中的 limiter 段） |
| 敏感词中的 PII | **一并删除**：`SensitiveScanner` 内置的身份证/银行卡/手机号检测随功能整体下线，入库不再 PII 硬拦、输出不再掩码 |
| 图谱后端 | **保留后端**：GraphBuilder / `/graph/*` API / Agent 的 GraphSearchTool 不动，问答链路仍可用图谱增强检索；仅移除前端一切图谱展示 |

不在范围内（明确保留）：
- 认证与角色门禁（`auth.py` / `require_role` / ACL / KB 授权）
- 结构化日志与 PII 日志脱敏（`core/logging_setup.py` L23 注释指明与 sensitive.py 正则同源，但属日志设施，**不删**）
- 校验历史落库（`ValidationHistoryStore`，CRAG/自检明细，属评测设施而非审计）
- 令牌桶突发限流与登录限流
- 后端图谱构建与 `/graph/*` 端点（Agent 仍可用图谱增强检索）

## 6. 风险与回滚

| 风险 | 说明与对策 |
|---|---|
| `attach_security` 改构造传参的时序 | `ValidationHistoryStore` 仅依赖 `settings.data_dir`，可安全上移到 pipeline 构造（L339）之前；实施时若发现隐式时序依赖，退回 `attach_history()` 晚绑定方案 |
| `app.state.platform_monitor` 悬空引用 | `dependencies.py` L187 与 `main.py` L860 两处引用必须同步删除，否则 `enforce_rate_limit` / `/healthz` 抛 AttributeError → 500 |
| ErrCode 6201 删除的兼容性 | 前端与脚本经检索**无 6201 字面量**；保守方案是保留枚举成员（`validate_code_uniqueness` 不受影响） |
| 审计删除后的合规留痕 | 结构化日志（`logging_setup`，含 PII 脱敏）仍记录请求级 trace_id 与事件，可满足基础排障；审计级"谁改了什么"能力消失，属需求本身 |
| PII 检测下线的数据面影响 | 入库不再拦截含身份证/银行卡的文档，输出不再掩码——**这是明确需求**，但需在交付说明中显式告知运维（§5 第 6 条已列为确认项） |
| 图谱后端保留但前端隐藏 | `/graph/*` 仍是 admin 门禁端点，无未授权暴露面；Agent 的 GraphSearchTool 证据（`source_route=graph`）在前端按普通文本证据渲染，不泄露图谱结构 |
| 回滚 | 纯删除改动，git 单 commit 可整体 revert；`data/audit/` 历史文件不删除，回滚后审计记录立即可用 |
