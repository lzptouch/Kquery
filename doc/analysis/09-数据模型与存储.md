## 〇、摘要

1. **无传统关系数据库**：真相源 = 向量库（Milvus/FAISS）+ `data/` 下的一组 JSON/JSONL/SQLite 文件；领域模型集中在 `app/domain/schemas.py` 一个文件（17 个 Pydantic 模型），字段按"将来要进数据库"的标准设计（`app/domain/schemas.py:1-5`）。
2. **四处存储损坏即拒绝启动**：文档元数据、向量索引、ACL、DocStore（外加用户目录）——宁可起不来，不以脏数据对外服务（`app/services/knowledge.py:108-116`、`app/services/vectorstore.py:60-75`、`app/services/security/acl.py:71-77`、`app/services/docstore.py:26-35`、`app/services/security/auth.py:225-227`）。
3. **索引版本化是核心一致性机制**：`chunk_id` 形如 `{doc_id}@v{n}#{seq}`，reparse 改名旧块保留供溯源，全局 `index_version` 进缓存键——知识库任何变更使旧缓存自然失效（`app/services/vectorstore.py:25-46`、`app/services/knowledge.py:563-622`、`:76-91`）。
4. **原子写是全域纪律**：metadata / docstore / acl / users / sessions / tasks / FAISS 落盘全部走"临时文件 + replace"（如 `app/services/knowledge.py:136-144`、`app/services/security/acl.py:214-220`）。
5. **会话 30 天 TTL、快问临时文档 2 小时 TTL**；但审计、Agent 检查点、入库任务目录、资产目录**无 TTL**，只增长不收缩（登记为缺口，见「七」「八」）。
6. **图存储默认 SQLite（WAL）**，旧 `graph.json` 启动时自动迁移并改名备份不删除（`app/services/graph/sqlite_store.py:379-417`）。

## 一、领域模型全景

全部模型定义在 `app/domain/schemas.py`。模块 docstring 定了两条设计基调：标识稳定可组合、租户字段从第一天就存在、证据是一等实体（`:1-5`）。

### 1.3 分模块要点

- **知识资产**（DocumentRecord / Chunk / TableRecord / MediaAsset）：`chunk_count` 入库后回填用于完整性校验；`short_chunk_count` 是质量红线（占比 >10% 需调切块参数）；`version` 重新解析时 +1，旧版本块保留供历史引用溯源（`schemas.py:23-26`）。Chunk 冗余存 `tenant_id`，检索时一次过滤完成（`:47`）。
- **问答**（AskRequest / AskResult / Evidence / RetrievalStats / SelfCheckRecord / CragRound）：拒答是一等公民（`verdict=refused` 走成功状态码，`:351-353`）；`acl_filtered` 只报数量，绝不暴露被过滤文档的元信息（`:361-362`）；`RetrievalStats` 同时产出平铺与嵌套两种形态，新旧消费者不必同步切换（`:238-241`）。
- **运行配置**（RetrievalConfig）：变更不立即生效——先存 pending，到生效时刻晋升 active（`:280-288`）；`with_fallbacks` 把存量 JSON 里缺失的新字段（值为 0）回落到全局配置，防止"检索突然什么都召不回"（`:305-324`）。

## 三、损坏即拒绝启动的存储

四类（外加用户目录共五处）存储把"损坏"看得比"缺失"严重：缺失可以按空库起步，损坏意味着真相源不可信。

| 存储 | 拒绝启动条件 | 代码位置 |
|---|---|---|
| 文档元数据 `metadata.json` | 文件存在但 JSON 解析/模型校验失败 → `RuntimeError("文档元数据文件损坏，拒绝启动")` | `app/services/knowledge.py:108-116` |
| 向量索引 `index.faiss` + `chunks.json` | 两文件都不存在 = 空索引启动；存在但读取失败、或**索引行数与元数据条数不一致** → 拒绝启动 | `app/services/vectorstore.py:60-75`（一致性校验在 `:71-72`） |
| ACL `acl.json` | JSON 损坏 → raise（"权限数据损坏比没有权限数据严重得多"） | `app/services/security/acl.py:71-77` |
| 知识库 `knowledge_bases.json` / `kb_grants.json` | JSON 损坏 → raise（"权限数据损坏比没有权限数据严重得多"） | `app/services/security/kb.py:61-72` |
| DocStore `docstore.json` | JSON 损坏或模型校验失败 → `RuntimeError("DocStore 数据损坏，拒绝启动")` | `app/services/docstore.py:26-35` |
| 用户目录 `users.json` | JSON 损坏 → raise（"拒绝以脏数据启动"） | `app/services/security/auth.py:225-227` |

对照组（**不**拒绝启动）：`tasks.json` 损坏忽略重置（`ingest.py:115-116`）、会话文件损坏隔离后按不存在处理（`sessions.py:101-112`）、审计坏行查询时跳过、敏感词表加载失败保旧表、图 JSON 迁移失败用空库、检查点初始化失败降级内存。取舍逻辑：拒绝启动留给"以坏数据服务会造成越权或错误答案"的存储；可再生的派生数据一律降级而非阻断。

## 四、关键实体生命周期

### 4.1 文档（DocumentRecord）

```
上传/入库 ──→ uploaded ──→ parsing ──→ indexed ─┬─→ reparse：status→parsing，version+1，
  （同步 upload                        ↑        │   旧块改名 @v旧 保留供溯源，
   或异步 ingest）                     └────────┘   超出 index_version_keep 份才真删
        任处理态 ──→ failed（error 记录原因，可 rebuild 按原内容原策略重建）
indexed ──→ offline：删索引、chunk_count 归零，源文件与记录保留（knowledge.py:624-632）
indexed/offline ──→ delete：级联删除（见「七 · 7.3」）
```

- 状态常量：`schemas.py:9-12` + `offline`（`:57-58`）。
- reparse 的版本化纪律（`app/services/knowledge.py:625-684`）：旧实现先物理删旧块再重建、chunk_id 复用同一序号空间，导致历史答案里的引用全部指向不存在的块；现做法是先 `_retire_version` 把当前版本块改名为 `@v{旧}` **不删除**，新块打 `@v{新}` 序号空间天然隔离，历史块不参与召回但可在预览接口按 chunk_id 直接溯源。
- rebuild 不改版本（chunk_id 稳定，`:548-561`）；每次版本变更 `_bump_version()` 使旧缓存键失效。

### 4.2 会话（SessionStore，`app/services/agent/sessions.py`）

```
create（id = 租户:用户:随机号，防枚举）──→ 首问自动生成标题（取问题前 24 字，:194-196）
  ──→ 每轮 save_turn：turn+1、快照截断（证据 ≤8 条、历史 ≤6 轮）、expires_at 顺延 30 天
  ──→ 读取时过期即删文件并 410（:113-116）；list 时惰性清理过期快照（:128-130）
  ──→ delete：快照与锁一并删除，不留残留原文（:148-154）
```

TTL 30 天（`sessions.py:22`，配置 `agent_session_ttl_s`，`app/core/config.py:113`）；归属校验在服务端（id 前缀即归属凭证，`:70-73`）；写入带轮次号防乱序、同会话串行（会话维度锁）、跨版本读取缺字段按默认值补齐（`:1-8`）。

### 4.3 ACL 条目

创建/变更走 `set_acl`：写入 + **全局版本 +1** + 原子落盘 + 返回影响反查与风险分级（`app/services/security/acl.py:144-162`）；文档删除时 `remove` 联动清除（`:126-137`），同名文档重新上传不继承旧权限。版本号是缓存键维度之一（见「六」）。

### 4.4 快问临时文档（`app/services/quickask.py`）

```
upload ──→ doc_id = quick_<hex>，临时文件落 data/uploads/quick/（:171-172、:243-248）
  ──→ 解析 + index_transient（向量 + BM25 双写，但不入 metadata.json / DocStore，
      不 bump index_version——否则每次快问都清空全站缓存，:9-17）
  ──→ 元数据入 QuickAskStore（Redis 优先，Fail-Open 降级进程内，:59-120）
  ──→ TTL 2 小时（配置 quick_ask_ttl_s，app/core/config.py:279-281）
  ──→ sweep_expired 定期清扫：限量 50 条 / 预算 5s（:360-423），
      向量走 purge_transient 移除（同样不 bump 版本）
```

### 4.5 Agent 检查点

`thread_id = {session_id}:{turn}`——每轮独立 checkpoint 不互相覆盖，支持逐步回放（`app/services/agent/checkpointer.py:86-92`）。后端三档：sqlite（默认，单文件事务安全）/ memory（测试）/ none（显式关闭，等价于放弃续跑与 HITL）；依赖缺失或初始化失败一律降级 MemorySaver 并在 state 打 degraded 标记（`:31-68`）。**无 TTL 清理**（缺口 2）。

### 4.6 入库任务（IngestTask）

`queued → running → done / partial_failed / failed / cancelled`（`schemas.py:71-77`）；取消只允许在 `{queued, parsing, chunking}` 三阶段（`schemas.py:79-80`）。任务状态每次变更原子落盘 `tasks.json`；服务重启时仍处于执行中态的文件标记 `failed`（"服务重启导致任务中断，可重试"），任务整体降为 `partial_failed`——诚实失败，不留假进度（`app/services/ingest.py:97-116`）。队列有界（满即 503 背压，`:76-78`）。

### 4.7 审计事件

只追加，无修改删除接口，无 TTL（`app/services/security/audit.py:1-9`）；写入路径是内存队列 + 后台批量落盘（崩溃最多丢 pending 部分）。生命周期 = 无限增长 → 缺口 1。事件字典与查询机制 → `08-安全与治理.md` §八。

### 4.8 知识库（KnowledgeBase）

```
首次启动 / 升级启动
   ├─ knowledge_bases.json 不存在 → 创建默认库 kb_id="default"（is_public=True）  kb.py:75-90
   └─ 存量 DocumentRecord.knowledge_base_id 为空 → 回填 "default" 并落盘          knowledge.py:119-124
```

## 六、版本与一致性

### 6.1 两级版本号

| 版本 | 载体 | 变更时机 | 一致性作用 |
|---|---|---|---|
| 全局数据版本 | `data/index_version` 整数（`app/services/knowledge.py:72-91`） | 知识库任何变更（入库/删除/版本退役）`_bump_version` | 进缓存键五维之一 → **旧缓存键自然失效**（键维度详见 `05-检索链路.md`） |
| 文档索引版本 | `DocumentRecord.version` + chunk_id 的 `@v{n}` 段（`app/services/vectorstore.py:25-46`） | reparse 时 +1 | 召回侧只取当前版本块（`is_current_version`），历史块只服务溯源；序号空间按版本隔离不撞号 |
| ACL 全局版本 | `ACLService._version` 内存计数（`app/services/security/acl.py:68-70`、`:139-142`） | 任何 ACL 写操作 | 进缓存键 → **权限撤销后旧缓存失效**（缓存命中路径跳过检索与 ACL 过滤） |

### 6.2 原子写与备份

- **tmp + replace 原子写**是全域纪律：`metadata.json`（`knowledge.py:118-126`）、`docstore.json`（`docstore.py:37-51`）、`acl.json`（`acl.py:214-220`）、`users.json`（`auth.py:235-239`）、`tasks.json`（`ingest.py:118-125`）、会话（`sessions.py:51-68`）、FAISS 双文件（`vectorstore.py:77-89`）。动机在各处注释一致：这些文件的加载侧多为"损坏即拒绝启动"，半截 JSON 等于把整个服务打挂。
- **图存储 JSON → SQLite 自动迁移**：选 sqlite 后端但只存在旧 `graph.json` 时，启动先把 JSON 导入 SQLite，再把 JSON 改名 `.json.migrated` 备份**不删除**——避免升级后"图谱看起来被清空了"（`app/services/graph/sqlite_store.py:379-417`）。SQLite 侧每次写操作即提交，`save()` 为空操作（`:368-369`），WAL 模式（`:85-86`）。
- **检索配置延迟生效**：pending → 到点晋升 active（`schemas.py:280-288`），运行期改参数不打断在飞请求。

## 七、跨存储一致性策略与已知残留

### 7.1 向量条数 == 块条数

FAISS 加载时强校验 `index.ntotal == len(order)`，不一致即拒绝启动（`app/services/vectorstore.py:71-72`）；写入侧 `add` 先校验 chunks 与 vectors 数量一致（`:96-97`）。入库纪律（嵌入整批中止时保留已完成向量，不允许半成品索引）见 `app/services/knowledge.py:10-11` 与 `06-入库与解析链路.md`。

### 7.2 BM25 与向量的版本一致性

BM25 索引**不独立持久化**：启动时从向量库全量块重建（`app/main.py:220-223`），天然与向量库同源同版本；召回前的版本过滤（历史 `@v` 块不参与召回）在融合前完成。快问临时块双写两侧，防止 RRF 退化为单路（`quickask.py:15`）。

### 7.3 删除的级联（`app/services/knowledge.py:665-731`）

`delete(doc_id)` 编排：purge 向量/BM25 块 → 移除文档记录 → best-effort 逐项清理派生副本（ACL 条目、图谱中来源块、图像索引、资产文件、任务文件）。单项失败**不中断整体删除**，失败项记入 residuals 写 warning 日志——运维据此做残留巡检。已知残留：图像索引 `remove_doc` 的清理不彻底（`app/services/graph/images.py:183-196`，缺口 7）。

### 7.4 无 TTL 的存储（登记为缺口）

| 存储 | 增长方式 | 现状 |
|---|---|---|
| `audit/audit.jsonl` | 每请求 ≥3 行 + 管理操作 | 只追加，无轮转无清理（缺口 1） |
| `agent_checkpoints.db` | 每轮 Agent 运行若干行 | 无 TTL 清理（`checkpointer.py:17-18` 注释说明刻意不在装配期引入定时器，缺口 2） |
| `tasks.json` + `ingest/` | 每批入库一份记录 + 源文件 | 无清理（缺口 3） |
| `assets/` | 解析产物 | 仅随文档删除 best-effort 清理（缺口 4） |

有自限机制的对照组：会话（30 天 TTL）、快问（2h TTL + 清扫）、长期记忆（500 条/租户淘汰）、查询分析（1000 条）、校验历史（20MB×20 滚动）、FAISS/Milvus 历史版本块（`index_version_keep` 份数上限）。

### B. 状态机速查

- 文档：`uploaded → parsing → indexed / failed`；`indexed →(reparse, version+1)→ indexed`；`indexed → offline →（rebuild）→ indexed`；任意 → `delete`（级联）。
- 文件：`pending → uploading → queued → parsing → chunking → indexing → done / failed`；可取消阶段 = `{queued, parsing, chunking}`。
- 任务：`queued → running → done / partial_failed / failed / cancelled`；重启时 running 中的文件标 failed。
（常量定义：`app/domain/schemas.py:9-12`、`:57-80`）
