# 06 配置参考

## 1. 配置从哪来

- 唯一真相源：`backend/app/core/config.py` 的 `Settings`（Pydantic Settings）。代码里的默认值就是出厂默认值。
- 环境变量名 = 字段名大写，**没有 `KQUERY_` 前缀**；唯一例外是 `milvus_uri` 显式声明别名 `KQUERY_MILVUS_URI`（避开 pymilvus 内部变量）。
- `backend/.env.example` 由 `scripts/gen_env_example.py` 从 `Settings` 的字段与注释**自动生成**，CI 用 `--check` 校验二者一致。**改配置必须改 `config.py`，然后重新生成**，不要手改 `.env.example`。
- 注释里偶有指向开发期内部工程文档的路径，那些文档不随本仓库发布；对外解释以本篇为准。

```bash
cp backend/.env.example backend/.env     # 然后只填标了「敏感」的字段
python scripts/gen_env_example.py        # 改完 config.py 后重新生成
python scripts/gen_env_example.py --check
```

## 2. 配置分组

| 组 | 关键字段 | 说明 |
| --- | --- | --- |
| 运行模式 | `APP_ENV` | `prod` 会关闭 `/docs`、`/redoc`、`/openapi.json`；必须显式配 |
| 模型 provider | `MODEL_PROVIDER`、`*_API_KEY`、`*_BASE_URL` | 见 §3 |
| 模型选择 | `LLM_MODEL`、`EMBEDDING_MODEL`、`EMBEDDING_DIM`、`RERANK_MODEL` | 维度必须与索引一致，改维度要重建索引 |
| 模型路由与降级 | `LLM_FALLBACK_ENABLED`、`LLM_FALLBACK_MODELS` | 默认关；开启后按候选链依次尝试 |
| 切块 | `CHUNK_SIZE`、`CHUNK_OVERLAP`、`CHUNK_POLICY` | `CHUNK_POLICY` 非空时整体覆盖前两者 |
| 混合检索 | `RETRIEVAL_PER_ROUTE_TOP_N`、`RETRIEVAL_FUSED_TOP_N`、`RRF_K`、`BM25_K1`、`BM25_B`、`TOP_K` | 运行时可被 `/admin/retrieval-config` 覆盖 |
| 向量索引 | `VECTOR_STORE`、`KQUERY_MILVUS_URI`、`MILVUS_COLLECTION`、`VECTOR_INDEX_*` | Milvus 或 FAISS |
| 向量一致性 | `MILVUS_CONSISTENCY_LEVEL` | `Bounded`（默认）或 `Strong`；只在**新建集合**时生效，既有集合需 drop 重建 |
| Query 预处理 | `PREPROCESS_ENABLED`、`INTENT_MODEL`、`QUERY_EXPANDERS`、`FUSION_N`、`QUERY_BUDGET` | 改写与分解的开关和预算 |
| CRAG 与自检 | `CRAG_ENABLED`、`CRAG_CORRECT_TH`、`CRAG_INCORRECT_TH`、`CRAG_MAX_ITERATIONS` | **阈值必须按自有语料标定**，见 §4 |
| 通用知识兜底 | `PARAMETRIC_FALLBACK_*` | 知识库无覆盖时用模型自身知识回答 |
| Agent | `AGENT_ENABLED`、`AGENT_MODE`、`AGENT_MAX_STEPS`、`AGENT_TOOL_FALLBACKS_JSON` | `plan_execute` 为默认模式 |
| 预算治理 | `AGENT_TOKEN_BUDGET`、`AGENT_COST_LIMIT_YUAN`、`AGENT_DEADLINE_MS`、`ASK_DEADLINE_MS` | 预算是降级不是报错 |
| 流式续传 | `SSE_RESUME_ENABLED`、`SSE_RESUME_GRACE_S`、`SSE_REPLAY_TTL_S` | 默认关：续传期间照样烧 token |
| 上下文组装 | `CONTEXT_TOKEN_BUDGET`、`CONTEXT_MMR_LAMBDA`、`CONTEXT_PARTITION_RENDER` | MMR 兼顾多样性 |
| 缓存与限流 | `CACHE_BACKEND`、`CACHE_TTL_S`、`CACHE_SIM_THRESHOLD`、`RATELIMIT_*` | 语义缓存相似度阈值 |
| 并发与熔断 | `PIPELINE_WORKERS`、`UPSTREAM_*_PERMITS`、`UPSTREAM_BREAKER_*` | 上游隔离仓许可之和 ≤ `PIPELINE_WORKERS` |
| 降级阶梯 | `DEGRADE_LADDER_ENABLED`、`DEGRADE_UPSTREAM_SLOW_MS` | 默认关，阈值未标定前不要开 |
| 图谱 | `GRAPH_ENABLED`、`GRAPH_STORE_BACKEND`、`COMMUNITY_LEVELS`、`GRAPH_BFS_DEPTH` | 建图是分钟级后台任务 |
| 多模态 | `IMAGE_VECTOR_ENABLED`、`VLM_ANSWER_ENABLED`、`PDF_OCR_ENABLED`、`OCR_PROVIDER` | 默认关/按需开 |
| 可观测 | `LOG_LEVEL`、`LOG_FORMAT`、`METRICS_PUBLIC`、`METRICS_TOKEN`、`OTEL_ENABLED`、`PROMETHEUS_URL` | 多副本必须配 `PROMETHEUS_URL` |
| 存储 | `DATA_DIR` | 限流/缓存/会话为进程内或本地文件（单副本语义） |
| 上传 | `MAX_UPLOAD_MB`、`INGEST_TASK_RETENTION_S` | |

## 3. Provider 能力矩阵

生成 / 向量 / 重排三条通道**彼此独立**配置（`MODEL_PROVIDER` / `EMBEDDING_PROVIDER` / `RERANK_PROVIDER`），默认都是 `auto`：有对应 Key 就走真实服务，无 Key 回落 `mock`（便于无凭据环境跑通功能测试）。

| Provider | 生成 | 向量 | 重排 | OCR | 备注 |
| --- | --- | --- | --- | --- | --- |
| `dashscope` | ✅ | ✅ | ✅ `/rerank` | ✅ | 默认路径 |
| `deepseek` | ✅ | ❌ | ⚠️ 对话模型 listwise（不是 `/rerank`） | ❌ | 官方只有 `/chat/completions` |
| `minimax` | ✅ | ✅ `embo-01`（1536 维，请求体是 `texts` 非 OpenAI `input`） | ❌ | ❌ | 业务错误放在 HTTP 200 的响应体里（`base_resp.status_code`）；国内站/国际站是两套域名 |
| `zhipu` | ✅ | ✅ `embedding-3`（2048 维） | ✅ `/rerank` | ❌ | `glm-4.5` 默认开思考，需 `ZHIPU_THINKING_ENABLED=false` 否则正文被思考 token 挤空 |
| `openai_compatible` | 取决于服务 | ✅ 走 `{base}/embeddings` | ✅ 走 `{base}/rerank` | ❌ | 需要同时配 `*_BASE_URL` 与 `*_API_KEY` |
| `mock` | 假实现 | 假向量 | 恒等排序 | 假 OCR | 测试用 |

`OCR_PROVIDER` 只允许 `auto | dashscope | mock`——本地 OCR 需要构建期烤权重或运行时下载模型，内网都不可行，最终会表现为"部署后 OCR 静默不可用"。

## 4. 三处必须自己标定的阈值

改配置前先读这一节，这三处**默认值是标定结果，不是经验值**：

1. **`CRAG_CORRECT_TH` / `CRAG_INCORRECT_TH`**（默认 0.14 / 0.08）：按混合语料的分数分布标定。干净 Markdown 的相关检索 Top-2 均分约 0.45~0.78，OCR 扫描件约 0.18~0.25，无关问题约 0.05~0.08。**换评分器或换语料构成必须重新标定**——不同评分器的分数不可直接比较。
2. **`PARAMETRIC_FALLBACK_SCORE_THRESHOLD`**（默认 0.6）：与 Agent reflect 的 `ANSWER_THRESHOLD` 同口径（综合分），不要拿 CRAG 的重排分阈值套。
3. **`DEGRADE_UPSTREAM_SLOW_MS`**（默认 8000）：取实测 P95 的 2 倍。设小了会"一直处于降级"，比迟降级代价更大。

## 5. 并发参数怎么算

`PIPELINE_WORKERS` 是在飞问答线程数，按**上游并发配额**设而不是 CPU 核数。真实模型 8 s/req 时，32 在飞约等于 4 QPS（Little's Law）。排队满返回 503 + `Retry-After`。

`UPSTREAM_LLM_PERMITS`、`UPSTREAM_EMBEDDING_PERMITS`、`UPSTREAM_RERANK_PERMITS`、`UPSTREAM_MILVUS_PERMITS`、`UPSTREAM_MULTIMODAL_PERMITS` 是隔离仓许可，**之和必须 ≤ `PIPELINE_WORKERS`**，否则线程会被"等许可"占满，表现为整体吞吐塌陷而没有明显报错。

## 6. 单副本 vs 多副本

| 项 | 单副本 | 多副本 |
| --- | --- | --- |
| 限流/配额/缓存 | 进程内即可 | **必须配 `REDIS_URL`**，否则实际额度 = 单副本额度 × 副本数 |
| 指标看板 | 进程内 MetricsStore | **必须配 `PROMETHEUS_URL`**，否则 `/admin/metrics/*` 只反映一个副本 |
| Agent checkpoint | SQLite 单文件 | 需共享存储或改外部 checkpointer |
| SSE 续传 | 可选 | 需要粘性会话或共享缓冲 |

## 7. 安全相关

- `APP_ENV=prod` 时关闭交互式 API 文档。
- `METRICS_PUBLIC=false`（默认）时 `/metrics` 需要 `METRICS_TOKEN`；运营数据不应匿名可抓。
- 应用层**没有认证**（见 [03 接口参考 §1](./03-接口参考.md)），公网部署必须在网关层加鉴权。
- 所有标「敏感」的字段留空，真实值只写本地 `backend/.env`，不要提交。
