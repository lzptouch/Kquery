## 〇、摘要

1. **Kquery 已是一个「有默认关闭项的完整 RAG 系统」**：能力域覆盖 D1~D10 共 97 条能力（2026-11-14 按表格逐行实测），其中 62 条默认可用、14 条有条件可用、2 条不可用、19 条已下线（认证 / 角色门禁 / 前端守卫 / ACL / 知识库授权 / 配额 / 敏感词 / 审计，均为 2026-11-12 下线）——但「有条件可用」里集中了 ReAct、HITL、独立 verify 节点、OTel、降级阶梯等最容易被误认为「已经支持」的能力。
2. **混合检索是本项目唯一同时满足「有生产调用点 + 默认开启 + 有主路径测试」三条硬规则的重能力**：`HybridRetriever.search_multi` 是管线内唯一的检索入口（`backend/app/services/retrieval/hybrid.py:111`），默认双路开启，并有 `tests/integration/test_stage2.py` 覆盖主路径。
3. **Agent 侧的三条「进阶」通道全部默认关闭**：ReAct 仅在 `agent_mode=="react"` 时才装配 thinker（`backend/app/services/agent/runner.py:236`），默认 `agent_mode="plan_execute"`（`backend/app/core/config.py:361`）；HITL 默认 `agent_hitl_enabled=False`（`backend/app/core/config.py:337`）；独立 verify 节点默认 `agent_verify_enabled=False`（`backend/app/core/config.py:376`）。
4. **检索质量已可度量，但度量的是「本地口径」**：检索金标 **120 条** + 问答金标 **60 条** + 语料 **26 篇**已落地（`tests/data/eval/`），recall@k / nDCG / MRR / precision / hit_rate / 分路 / 候选池天花板 / 缺口归因 / **配对 bootstrap 显著性** / 成本-质量帕累托前沿全部有实现（基线 recall@10=0.9545、nDCG@10=0.836，`tests/data/eval/baseline.json`）。**边界**：向量路仍是 **mock embedding**，真实链路复测（`MP-04`）未做——本地数字不能当线上数字。
5. **快问（F4）能力存在但受限**：`req.doc_id` 存在时强制走线性路径，因为 Agent 路径的检索未接 `doc_id` 过滤（`backend/app/api/ask.py:53-58`）；且 `redis_url` 默认空时快问临时态只在本进程内（`backend/app/core/config.py:370`），多副本之间互不可见。
6. **两条外部依赖型能力处于「不可用」态**：SQL 业务库工具与联网搜索工具在 `sql_dsn` / `web_search_endpoint` 为空时**根本不注册**（`backend/app/assembly/agent.py:66-104`），因此在默认部署中这两项能力不存在。
7. ~~知识库实体与逐用户授权~~ **已随认证 / 授权一起下线**（2026-11-12）：KB 实体、授权名单、角色粒度限制一并删除；`backend/app/dependencies.py` 现只剩 4 个资源取值依赖（`get_app_settings` / `get_pipeline` / `get_knowledge_service` / `get_session_store`，`:33`/`:37`/`:41`/`:45`）与 3 个请求级依赖（`get_principal` `:49` / `enforce_rate_limit` `:63` / `reject_background_when_busy` `:93`）；`acl_filter_of` 与 `require_role` 已删（删除说明见该文件 `:15-16`）。
