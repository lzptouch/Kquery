## 〇、摘要

1. **分叉点在 API 层，不在 pipeline 内**：`backend/app/api/ask.py:53-58` 的 `_use_agent()` 决定走哪条路径——`req.doc_id` 存在 → **强制线性**；`mode=="agent"` 或带 `session_id` 且 `agent_enabled` → Agentic；否则线性。`RagPipeline` 内部没有分叉逻辑。
2. **线性链路是单一生成器**：`backend/app/services/pipeline.py:664-978` 的 `_core_events()` 产出事件序列，`ask()`（聚合）与 `ask_stream()`（透传）消费同一份事件——两种传输形态、同一套语义（§二）。
3. **敏感词与 PII 检测已下线**：原输入侧只探测不阻断、输出侧掩码/拒答、入库侧硬拦三处均已移除（§二 步骤 1 / 步骤 11）。日志层的 PII 脱敏不受影响。
4. **CRAG 的精炼是"追加"不是"替换"**（`backend/app/services/pipeline.py:793-805`）：替换会让"证据不足 → 反而收窄召回面"，修复动作让情况更糟。
5. **ACL 下推让"权限类拒答"变不可达**，靠空结果路径上的**只读探测**补回（`backend/app/services/pipeline.py:750-767`）；探测只回传原因，不回传任何被过滤文档的元信息。知识库授权是**同一闭包内的第二道闸**（ACL 先、KB 后），撤权通过复合版本号让旧缓存立即失效（`backend/app/main.py:417`）。
6. **权限类拒答不兜底**（`backend/app/services/pipeline.py:812-814`）：通用知识回答可能暗示文档存在。Agentic 路径的等价红线在 `backend/app/services/agent/graph.py:559-565`。
7. **Agent 状态机有 7 个节点、5 个路由函数**（`backend/app/services/agent/graph.py:643-739`），三层熔断分别是总轮数 / 无进展 / 单步超时；`interrupt_before` **刻意不加**（`:735-739`），HITL 必须是条件性中断。
8. **HITL 默认关闭**（`backend/app/core/config.py:134` `agent_hitl_enabled = False`），且前端**无任何 HITL 消费方**——`awaiting_human` 事件不在 SSE 白名单内会被静默丢弃（§五、§十一）。
9. **快问有四条不可让步的约束**（`backend/app/services/quickask.py:9-17`）：不入知识库 / 不 bump 索引版本 / 向量 + BM25 双写 / 缓存键带 scope。
10. **Agent 路径的事件在输出侧扫描后才放行**：`token` 被缓冲到终稿再重放（`backend/app/services/agent/runner.py:359-362`、`:467-472`），保证"不先漏后遮"。

## 一、三条路径的分叉规则

### 1.1 分叉点位置

分叉发生在 **API 层**（`backend/app/api/ask.py`），不在 pipeline 内部：

```python
# backend/app/api/ask.py:53-58
def _use_agent(req: AskRequest, settings: Settings) -> bool:
    if req.doc_id:
        return False
    return settings.agent_enabled and (req.mode == "agent" or req.session_id is not None)
```

`/ask`（`backend/app/api/ask.py:159`）与 `/ask/stream`（`:271`）都调用它，两条路径的分叉结果一致。

### 1.2 判定表

| 序 | 判定条件 | 结果路径 | 证据 |
|---|---|---|---|
| 1 | `req.doc_id` 非空 | **强制线性** | `backend/app/api/ask.py:56-57` |
| 2 | `req.doc_id` 为空 且 `settings.agent_enabled` 为假 | 线性 | `backend/app/api/ask.py:58` |
| 3 | `req.doc_id` 为空 且 `agent_enabled` 为真 且 `req.mode == "agent"` | **Agentic** | `backend/app/api/ask.py:58` |
| 4 | `req.doc_id` 为空 且 `agent_enabled` 为真 且 `req.session_id` 非空 | **Agentic** | `backend/app/api/ask.py:58` |
| 5 | 以上皆否 | 线性 | 兜底 |

### 1.3 三条路径的形态对照

| 维度 | 线性 | Agentic | 快问 |
|---|---|---|---|
| 触发条件 | 默认 | `mode="agent"` 或带 `session_id` | `req.doc_id` 指向快问临时文档 |
| 入口端点 | `POST /ask`、`POST /ask/stream` | 同左 | `POST /quickask/ask`（另有 `/ask` 带 `doc_id` 的等价路径） |
| 核心实现 | `services/pipeline.py:664-978` `_core_events` | `services/agent/graph.py` 状态机 + `services/agent/runner.py` | 线性路径 + `doc_id` 范围过滤 |
| 是否写会话快照 | 否（线性路径不落快照） | 是（`runner.py:512-518`） | 否 |
| 是否消耗 Agent 预算 | 否 | 是（token / cost / deadline） | 否 |
| 拒答口径 | CRAG 分支 + 提示词级归一 | 反思分 + 证据为空 + 提示词级归一 | 同线性 |
| 事件形态 | 17 类内容事件 | 17 类内容事件 + Agent 轨迹事件 | 与线性完全一致（前端零改造） |

### 1.4 为什么 `doc_id` 强制线性

`backend/app/api/ask.py:54-55` 的注释给出理由：**Agent 路径的检索没有接 `doc_id` 过滤**，放行会变成"限定单文档的提问却检索了全库"。这是硬红线，不是性能取舍。

配套的归属校验在 `_assert_quick_doc`（`backend/app/api/ask.py:61-72`）：`doc_id` 必须属于当前主体**且**（若绑定了会话）属于当前会话，否则按3004 处理。

### 3.4 为什么刻意不加 `interrupt_before`

`backend/app/services/agent/graph.py:735-739`：

```python
# checkpointer 是断点续跑 / 多轮状态继承 / 完整回放 / HITL 的共同前提。
# 刻意**不加** `interrupt_before`：那是**静态**中断（指定节点每次都挂起），
# 而 HITL 需要的是「低置信才挂起」的条件性中断——必须由 interrupt() 在
# answer 节点内部动态调用，静态声明会让该节点每次都停。
return graph.compile(checkpointer=checkpointer)
```

静态 `interrupt_before` 会让 `answer` 节点每次都停 —— 哪怕证据充足、置信度极高。这是**语义错误**，不是风格问题。

### 五·3 决策解析

`backend/app/services/agent/graph.py:77-94` 的 `_parse_hitl_decision()`：

| 输入 | 解析结果 |
|---|---|
| 字符串且非空 | `("hint", 字符串)`——简写直接视为补充线索 |
| 字符串且为空 | `("force_answer", "")` |
| `action` ∈ {`stop`,`cancel`,`abort`} | `("stop", "")` |

## 六、预算三维度

### 6.1 三个维度

`backend/app/services/agent/budget.py:25-134`：

| 维度 | 字段 | 语义 | 判定 |
|---|---|---|---|
| token | `token_limit` | 累计 token 上限；0 = 不限 | `backend/app/services/agent/budget.py:62-63` |
| cost | `cost_limit_yuan` | 累计金额上限（元）；0 = 不限 | `backend/app/services/agent/budget.py:64-65` |
| deadline | `deadline_ms` | 整体墙钟上限；0 = 不限 | `backend/app/services/agent/budget.py:60-61` |

判定入口 `exhausted()`（`:56-66`）返回耗尽原因（`deadline` / `token` / `cost` / 空串）；一旦耗尽，原因被**固化**在 `exhausted_reason`（`:58-59`、`:88-90`），后续不再重新判定。

`can_afford(tokens, cost_yuan)`（`:68-81`）回答"能否承担**下一次**调用的下界开销"——**判定用"是否已耗尽"而非"是否会耗尽"**，避免执行到一半才发现超限（那时钱已经花了）。

**预算耗尽不报错，降级作答**（`status="budget_exhausted"`）：预算控制的目的是"别把用户和平台的钱烧光"，不是"拒绝服务"——用户至少该拿到基于已有证据的部分答案（`backend/app/services/agent/budget.py:13-14`）。

预算按租户可覆盖（`agent_token_budget_<tenant>` 这类后缀键），未配置时用全局默认值（`backend/app/services/agent/budget.py:120-134`）。

## 七、长期记忆

### 7.1 设计约束：不存用户原话

`backend/app/services/agent/memory.py:16-22`：记忆是**长期驻留**的数据，明文原话会成为一份绕过内容治理的"影子副本"（审计与敏感词下线后，已无任何环节再对记忆内容做哈希化或掩码）。因此条目只存三样：

| 字段 | 语义 |
|---|---|
| `kind` | 问题类型（由分类器产出，不是原文） |
| `key` | 归一化后的**实体/话题键**（如文档名、指标名），不是整句话 |
| `value` | 结论（"该看 A 文档"）或无效查询的**指纹** |

### 7.2 长问题指纹化

`backend/app/services/agent/memory.py:246-255` 的 `_topic_key()`：

| 问题长度 | 处理 |
|---|---|
| ≤ 24 字（通常是实体/指标名） | 原样保留作为话题键 |
| > 24 字 | 退化为 `指纹:{sha256 前 16 位}`（`query_fingerprint` 在 `:69-71`） |

避免把用户的长句描述写进长期存储。同一问题得到同一指纹，但**不可反推原文**。

### 7.3 四类 kind

`backend/app/services/agent/memory.py:49-52`：

| kind | 常量 | 语义 | 注入时的措辞 |
|---|---|---|---|
| `missing_doc` | `KIND_MISSING_DOC` | 知识库缺这类内容 | "关于「X」的问题知识库通常没有内容，…" |
| `invalid_query` | `KIND_INVALID_QUERY` | 该查询串从未召回 | "查询「X」此前从未召回结果，不要重复尝试同一查询" |
| `correction` | `KIND_CORRECTION` | 用户/人工确认过的正确指向 | "「X」的正确指向是：…" |
| `preference` | `KIND_PREFERENCE` | 答案风格偏好 | "「X」：…" |

### 7.4 淘汰策略

| 项 | 语义 | 证据 |
|---|---|---|
| 每租户上限 | 记忆不能无限增长（否则注入成本失控） | `backend/app/services/agent/memory.py:54`（`MAX_ENTRIES_PER_TENANT`）、`:83` |
| 单次注入上限 | 注入条数上限 | `backend/app/services/agent/memory.py:55`（`MAX_INJECT`） |
| 淘汰规则 | 超出上限时按「命中少 + 最久未用」排序后截尾——保留真正有用的经验 | `backend/app/services/agent/memory.py:138-143` |

| 幂等 | 同 `(tenant, kind, key)` 重复记录只更新值不新增条目 | `backend/app/services/agent/memory.py:127-131` |
| 存储 | JSONL 追加 + 内存索引；Redis 后端由 `core/shared_state.py` 提供，未配置时用本地文件 | `backend/app/services/agent/memory.py:33-36`、`:91-114` |

### 7.5 注入提示词

`backend/app/services/agent/memory.py:186-205` 的 `render_hint()`，首行固定为：

> "以下是你之前在这个租户处理类似问题时的经验（**供参考，不必盲从**）："

措辞刻意如此——记忆是**经验**不是**事实**：知识库更新后旧经验可能已失效，让模型有权忽略它（`backend/app/services/agent/memory.py:190-191`）。

### 7.6 消费与写入路径

| 环节 | 位置 | 说明 |
|---|---|---|
| 读取 → 渲染 | `backend/app/services/agent/runner.py:596-609` | `_memory_hint()`；失败一律返回空串——记忆是**增强**，拿不到不该影响问答 |
