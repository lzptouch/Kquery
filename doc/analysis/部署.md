## 一、项目启动方式全景

Kquery 当前存在 **三种** 启动方式：

| 方式 | 命令 | 适用阶段 | 入口 |
|---|---|---|---|
| **本地 uv 直跑** | `uv run uvicorn app.main:app --port 8000` | 开发 / 单机调试 | `backend/app/main.py` |
| **Docker Compose（Milvus）** | `cd deploy/milvus && docker compose up -d` | 启动向量库（生产） | `deploy/milvus/docker-compose.yml` |
| **Docker 单容器（后端）** | `docker build -t kquery . && docker run ...` | 隔离环境验证 | `backend/Dockerfile`（待补） |

### 1.1 方式一：本地 uv 直跑（开发模式）

```bash
# 1. 向量库（Milvus standalone）
cd deploy/milvus && docker compose up -d

# 2. 后端
cd backend
cp .env.example .env  # 填入 DASHSCOPE_API_KEY
uv sync
uv run uvicorn app.main:app --port 8000

# 3. 前端
cd ../frontend && nvm use && npm install && npm run dev
```

打开 http://localhost:5173 → **先登录**（`/login`）→ 「知识库」上传 PDF / Markdown → 「对话」提问。

> 账号密码档开启后（`AUTH_ENABLED=true` + `AUTH_PASSWORD_ENABLED=true`）：普通用户登录后侧栏**只有「对话」**；知识库 / 图谱 / 管理项仅 admin 可见。开发模式（`AUTH_ENABLED=false`）下前端自动以 admin 进入，无需登录——这是身份头档的明确开发形态，不是漏洞。

### 1.2 关键配置（`backend/app/core/config.py`）

```python
class Settings(BaseSettings):
    # 千问平台
    dashscope_api_key: str | None = None
    embedding_model: str = "text-embedding-v3"
    llm_model: str = "qwen-plus"
    rerank_model: str = "gte-rerank-v2"
    
    # 向量库
    vector_store: str = "faiss"  # 或 "milvus"
    milvus_host: str = "localhost"
    milvus_port: int = 19530
    
    # 数据目录
    data_dir: Path = Path("./data")
    
    # 限流
    rate_limit_per_minute: int = 60
    rate_limit_per_day: int = 10000
    
    # 检索
    bm25_k1: float = 1.5
    bm25_b: float = 0.75
    rrf_k: int = 60
    retrieval_per_route_top_n: int = 20
    retrieval_fused_top_n: int = 10
    
    # 阶段 9 护栏
    auth_enabled: bool = True
    auth_jwt_secret: str = ""            # HS256 密钥（口令档必需；生产由 Secret 注入）
    auth_password_enabled: bool = False  # 账号密码登录档
    auth_registration_enabled: bool = False  # 自助注册（新账号一律 sales）
    auth_session_ttl_s: int = 900        # 令牌有效期（15 分钟）
    auth_bootstrap_admin_password: str = ""  # 首次启动 admin 口令（仅无口令时写入一次）
    acl_enabled: bool = True
    sensitive_scan_enabled: bool = True
    platform_quota_per_day: int = 1000000
    quota_per_minute: int = 60
    quota_per_day: int = 10000
```

> 用户目录的真相源是 `settings.users_file`（`data/users.json`），`auth_users_json` 只是首次启动的初始种子。`backend/data/` 已被 `.gitignore` 忽略，口令哈希不会误入库。

### 1.3 启动日志样例

启动时 `app/main.py` 的 `lifespan` 输出关键信息：

```
Kquery 后端已启动（provider=dashscope, vector_store=faiss, llm=qwen-plus, rerank=gte-rerank-v2, 向量=1200, BM25=1200）
INFO:     Uvicorn running on http://0.0.0.0:8000
```

启动失败（如索引损坏）：
```
ERROR:    向量库索引文件损坏，请重新构建
```

> **关键设计**：索引文件损坏时**拒绝启动**（`app/main.py` 的 `create_app` 的 `lifespan`），不允许以坏索引对外服务。

## 二、Docker 部署

### 2.0 全栈一键起（`docker-compose.yml`，2026-10-25 实测可用）

```bash
docker compose up -d --build      # 构建并启动全栈
docker compose ps                 # 看健康状态
docker compose logs -f backend    # 看后端日志
docker compose down               # 停止
docker compose down -v            # 连同数据卷一起清（会丢向量索引与审计日志）
```

| 服务 | 镜像 | 宿主端口 | 说明 |
|---|---|---|---|
| `etcd` | `quay.io/coreos/etcd:v3.5.18` | — | Milvus 的元数据存储（容器内网） |
| `milvus` | `milvusdb/milvus:v2.6.4` | `19531`（gRPC）/ `9092`（健康） | 向量库。宿主 19530 被本机其它容器占用，故改 19531 |
| `redis` | `redis:7-alpine` | `6381` | 共享状态：语义缓存 / 令牌桶限流 / 滑动窗口配额 / 快问临时态。宿主 6379、6380 均被占用 |
| `init` | `kquery-backend:latest` | — | 一次性建 Milvus 集合与索引（多副本同时建表会失败，故独立成服务） |
| `backend` | `kquery-backend:latest` | `8100` | FastAPI。宿主 8000 被本机其它容器占用 |
| `frontend` | `kquery-frontend:latest` | `8090` | nginx + SPA，同时反代 API。宿主 8080 被占用 |

依赖顺序由 healthcheck gate 保证：`backend` 等 `milvus` healthy + `init` 成功退出才启动；
`redis` 是**可选依赖**——它挂了后端自动降级为进程内（Fail-Open），服务不中断。

**后端容器环境变量**（`docker-compose.yml` 的 `environment`）：`KQUERY_MILVUS_URI=http://milvus:19530`、
`VECTOR_STORE=milvus`、`DATA_DIR=/data`、`REDIS_URL=redis://redis:6379/0`、`CACHE_BACKEND=auto`。
密钥从 `backend/.env` 通过 `env_file` 注入，不进镜像层。

**镜像构建注意**：两个 Dockerfile 都**故意不写** `# syntax=docker/dockerfile:1`。
那行会让构建器去 Docker Hub 拉取前端镜像，在只能走镜像加速站的环境里，
build 会在"解析构建器镜像"这一步就超时失败；用到的能力（多阶段 / `COPY --from` /
`COPY --chown`）BuildKit 内置前端全都原生支持。

**冒烟**：栈起来后跑 `python3 scripts/smoke_api.py --base http://localhost:8100 --token <JWT>`
（81 项断言，覆盖 stage-0~9 + 语音 + 快问）。经 nginx 验证代理则用 `--base http://localhost:8090`。


### 2.1 向量库 Milvus（`deploy/milvus/docker-compose.yml`）

Milvus standalone 模式：

```yaml
services:
  etcd:
    container_name: milvus-etcd
    image: quay.io/coreos/etcd:v3.5.5
    environment:
      ETCD_AUTO_COMPACTION_MODE: revision
      ETCD_AUTO_COMPACTION_RETENTION: 1000
      ETCD_QUOTA_BACKEND_BYTES: 4294967296
    volumes:
      - ${DOCKER_VOLUME_DIR:-./volumes}/etcd:/etcd
    command: ['etcd', '-advertise-client-urls=http://etcd:2379', ...]

  minio:
    container_name: milvus-minio
    image: minio/minio:RELEASE.2023-09-23T17-49-55Z
    environment:
      MINIO_ACCESS_KEY: minioadmin
      MINIO_SECRET_KEY: minioadmin
    volumes:
      - ${DOCKER_VOLUME_DIR:-./volumes}/minio:/minio_data
    command: ['minio', 'server', '/minio_data']

  standalone:
    container_name: milvus-standalone
    image: milvusdb/milvus:v2.3.x
    command: ['milvus', 'run', 'standalone']
    environment:
      ETCD_ENDPOINTS: etcd:2379
      MINIO_ADDRESS: minio:9000
    volumes:
      - ${DOCKER_VOLUME_DIR:-./volumes}/milvus:/var/lib/milvus
    ports:
      - "19530:19530"
      - "9091:9091"
    depends_on:
      - etcd
      - minio

  attu:
    container_name: milvus-attu
    image: zilliz/attu:latest
    ports:
      - "3000:3000"
    depends_on:
      - standalone
```

**关键组件**：
- **etcd**：元数据存储（Collection schema / 索引参数）
- **MinIO**：对象存储（向量 + Payload）
- **standalone**：Milvus 主进程
- **Attu**：Web UI（http://localhost:3000）

### 2.2 后端 Dockerfile（建议补全）

项目当前**未提供后端 Dockerfile**，建议按以下结构补：


| 阶段 | 优化手段 | 效果 |

## 三、数据持久化与备份

### 3.1 数据目录结构（`backend/data/`）

```text
data/
├── assets/                      # 媒体资源（图片 / 音频）
├── audit/                       # 审计日志
│   └── audit.jsonl
├── graph/                       # GraphRAG
│   ├── graph.json
│   └── resolver.json
├── sessions/                    # Agent 多轮会话
│   └── {session_id}.json
├── users.json                   # 用户目录（含 password_hash；含口令，需纳入备份并控制访问权限）
├── acl.json                     # 阶段 9 ACL
├── docstore.json                # 父块 / 表格 / 媒体
├── feedback.json                # 拒答反馈
├── faiss.index                  # FAISS 向量库（demo）
├── image-index.json             # 阶段 7 图像索引
├── query_analysis.json          # 阶段 4 Query 分析
├── retrieval-config.json        # 运行时检索配置
├── sensitive-words.json         # 阶段 9 敏感词
└── tasks.json                   # 入库任务队列
```

### 3.2 备份策略

| 数据 | 备份策略 | 频率 |
|---|---|---|
| FAISS 索引 | `cp faiss.index faiss.index.bak` | 每日 |
| Milvus | MinIO snapshot | 每周 |
| JSON 文件 | `tar czf data.tgz data/` | 每日 |
| 审计日志 | append-only，归档 7 年 | 实时 |

> **关键设计**：JSON 文件 + FAISS 单一真相源 → 备份即"打包 data 目录"；生产切 Milvus 后需 MinIO snapshot 策略。

### 3.3 启动期 fail-fast

`app/main.py` 的 `lifespan` 启动时检查：

```python
# 启动期验证
store = build_vector_store(settings)
store.load()  # 索引损坏 → 抛异常 → 进程退出

bm25 = BM25Retriever(k1=settings.bm25_k1, b=settings.bm25_b)
bm25.rebuild(store.all_chunks())  # BM25 重建失败 → 抛异常
```

> **关键设计**：索引损坏时**拒绝启动**，不允许以坏索引对外服务（避免给出"空答案"或"错误答案"）。

## 四、9 阶段的部署演进

### 4.1 阶段 1~5：FAISS 单机

```
┌─────────────────────────┐
│ Kquery Backend          │
│ ├─ FastAPI              │
│ ├─ FAISS IndexFlatL2    │  ← 内存 / 持久化到 data/faiss.index
│ ├─ BM25 (纯 Python)     │
│ └─ 千问 LLM (外部 API)  │
└─────────────────────────┘
```

**优势**：单进程零依赖；劣势：单实例、向量容量上限 ~100k。

### 4.2 阶段 6~7：Milvus 集群

```
┌─────────────────────────┐     ┌──────────────────────┐
│ Kquery Backend (×N)     │     │ Milvus               │
│ ├─ FastAPI              │     │ ├─ etcd (元数据)      │
│ ├─ Milvus Client        │ ──→ │ ├─ MinIO (对象存储)   │
│ ├─ BM25                 │     │ └─ standalone/query  │
│ └─ 千问 LLM             │     │    node (集群节点)    │
└─────────────────────────┘     └──────────────────────┘
```

**优势**：横向扩展、十亿级向量；劣势：运维复杂。

### 4.3 阶段 8~9：多实例 + 缓存层

```
                    ┌──────────────────┐
                    │ nginx / Load     │
                    │ Balancer         │
                    └────────┬─────────┘
                             │
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        ┌─────────┐    ┌─────────┐    ┌─────────┐
        │ Kquery  │    │ Kquery  │    │ Kquery  │  (多实例)
        │ 8000    │    │ 8000    │    │ 8000    │
        └────┬────┘    └────┬────┘    └────┬────┘
             │              │              │
             └──────────────┼──────────────┘
                            ▼
        ┌─────────────────────────────────┐
        │ 共享依赖                          │
        │ ├─ Milvus 集群                   │
        │ ├─ Redis (语义缓存 / 限流 / 配额) │
        │ ├─ 千问 DashScope (外部 API)     │
        │ └─ S3 / OSS (媒体资源)           │
        └─────────────────────────────────┘
```

**关键能力**：
- **多实例横向扩展**：FastAPI 工作进程（`--workers N`）
- **Redis 语义缓存**：跨实例共享
- **Redis 滑动窗口配额**：跨实例共享
- **Milvus 集群**：向量共享

## 五、改进建议

### 5.1 启动期 fail-fast 增强

1. **千问 API 连通性验证**：启动期 ping 一次千问平台（`dashscope.aliyuncs.com`），避免"启动 OK 但所有请求 500"
2. **Redis 连通性验证**：阶段 2 后引入 Redis，启动期 ping
3. **Milvus 连通性验证**：生产部署时启动期 ping

### 5.2 健康探针分级

按 K8s 三级探针模型：
- **liveness**：`GET /health/live`（仅存活，不探依赖）
- **readiness**：`GET /health/ready`（探 Milvus / Redis / 千问）
- **startup**：`GET /health`（首启期，可放宽超时）

> 当前 `/health` 仅返回 `{"status": "up"}`；建议拆为三级。

### 5.3 数据备份自动化

1. **Milvus MinIO**：cron + mc 客户端 snapshot
2. **JSON 数据**：cron + `tar czf` 归档到 S3
3. **审计日志**：cron + logrotate + 7 年归档

### 5.4 限流与配额分层

1. **API 网关层**：Kong / Envoy 应用级限流（全局 QPS）
2. **应用层**：阶段 2 令牌桶（per-user QPS）
3. **租户层**：阶段 9 滑动窗口（per-tenant QPS / 每日）
4. **平台层**：阶段 9 PlatformQuotaMonitor（千问账号级）

### 5.5 密钥管理

阶段 9 Keychain 当前是本地文件（加密）→ 生产应接云 KMS / HashiCorp Vault。

| `DATA_DIR` | `./data` | 数据目录 |
| `RATE_LIMIT_PER_MINUTE` | `60` | 每分钟限流 |
| `RATE_LIMIT_PER_DAY` | `10000` | 每日限流 |
| `AUTH_ENABLED` | `true` | 阶段 9 认证开关 |
| `AUTH_PASSWORD_ENABLED` | `false` | 账号密码登录档 |
| `AUTH_BOOTSTRAP_ADMIN_PASSWORD` | `""` | 首次启动 admin 口令（仅无口令时写入一次） |
| `AUTH_REGISTRATION_ENABLED` | `false` | 自助注册（新账号一律 sales） |
| `AUTH_SESSION_TTL_S` | `900` | 登录令牌有效期（秒） |
| `AUTH_JWT_SECRET` | `""` | HS256 签名密钥（口令档必需，生产由 Secret 注入） |
