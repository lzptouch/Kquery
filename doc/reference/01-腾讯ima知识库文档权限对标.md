## 一、概念模型：知识库是文档的强容器

### 1.1 实体层级

```text
用户（微信账号）
 ├─ 个人知识库 ×N          ← 仅本人可见，默认形态
 ├─ 我创建的共享知识库 ×N  ← 本人是创建者（owner）
 └─ 我加入的共享知识库 ×N  ← 本人是成员（被邀请/申请加入）

知识库（knowledge base）
 ├─ 文件夹 ×N               ← 二级组织，可在库内再分主题
 ├─ 文档 ×N                 ← 挂在某个知识库下（也挂某个文件夹）
 └─ 笔记（ima 内部创建）    ← 与文档同级的轻量内容单元
```

关键事实（来源交叉验证）：

| # | 事实 | 来源 |
|---|------|------|
| F1 | 用户可创建**多个**知识库，按用途命名（教程建议「按用途分类，而不是按时间」） | ima 知识号《修虾传·第10节》 |
| F2 | 知识库内可建**文件夹**、文档可加**标签**，问答可「基于标签/文件夹」收敛范围 | 腾讯隐私保护指引 |
| F3 | 文档**有归属**：创建共享库时可「从本地文件或**个人知识库**」往共享库里放内容——个人库中的已有文档可被搬运/复用 | 腾讯新闻 20250106 |
| F4 | 知识库是「**核心底座**。所有 AI 能力都建立在知识库之上」；问答时以「@共享库名 + 问题」显式指定库范围 | ima 知识号《企业AI落地》、知识库案例教程 |
| F5 | 客户端侧栏明确区分「个人知识库」「我创建的共享知识库」「我加入的共享知识库」三个入口 | 腾讯新闻 20250106 |

### 1.2 文档入库渠道（= 文档进入知识库的路径）

| 渠道 | 说明 | 入库格式 |
|------|------|----------|
| 本地文件/文件夹上传 | 单文件最大 200MB；音频最大 100MB 或 ≤2 小时 | PDF / Word(doc,docx,docm,dotx) / Excel(xlsx,csv) / PPT / TXT / MD / XMind |
| 微信生态 | 微信文章/群文件 →「更多打开方式」→ ima 知识库 | 公众号文章、微信文件 |
| 网页链接 | 对话框粘贴 URL 或浏览时一键收藏 | 网页快照 |
| 图片/截图 | 上传后 OCR，文字可检索 | JPG/JPEG/PNG/WebP |
| 音频 | 上传后转写 | MP3/M4A/WAV/AAC |
| 腾讯文档 | 账号体系内直接关联导入 | 腾讯文档链接 |
| ima 内部笔记 | 边读边写的小笔记，可收藏进库 | 笔记 |

**对 Kquery 的启示**：ima 把「文档怎么进来」做成 7 条渠道，但**知识库实体本身独立存在**——先建库（5 秒），再往库里装东西。文档与库是「挂载」关系而非「文档自带分桶属性」。这一点直接证伪了"文档上挂一个 folder 字段就够了"的简化路线（挂载关系可以迁移、一文档可属于多库、库可整体授权）。

## 二、权限体系：库级角色 + 库级开关 + 内容级细粒度

这是本对标的**核心**。ima 的权限是**三层叠加**：

```text
第 1 层：知识库归属      个人库（仅自己） / 共享库（成员制）
第 2 层：库内角色        创建者 / 管理员 / 协作成员 / 普通成员
第 3 层：内容细粒度      库级开关（加入确认/查看全文/下载导出）
                       文件夹权限（仅管理员可见 / 可查看不可导出）
                       单文件权限（独立查看 / 独立导出）
```

### 2.1 库内角色（官方产品页口径）

| 角色 | 权限 | 官方原话要点 |
|------|------|------------|
| 创建者 | 所有权限 | 完全控制权限；决定公开与否；设置管理员；删除知识库 |
| 管理员 | 管理团队成员、编辑内容 | 可设内容权限、编辑知识库内容、邀请新成员；**最多 5 名** |
| 协作成员 | 上传、管理自己的文件 | 上传文件至知识库；查看知识库内容；基于知识库问答；**最多 50 名** |
| 普通成员 | 查看 + 问答 | 查看知识库内容；基于知识库问答；评论互动 |

来源：ima.qq.com/download 官方产品页「灵活的权限管理」一节；人数上限来自 ima 知识号《ima赚钱指南》教程。

### 2.2 库级开关（隐私指引口径）

创建者对**每个共享知识库**单独设置：

| 开关 | 作用 |
|------|------|
| 成员加入需确认 | 防陌生人涌入；开启后新成员加入要管理员审批 |
| 成员可查看文件具体内容 | 关闭后成员只能看**标题和摘要**，不可看全文（防资料外泄） |
| 成员下载/导出权限 | 控制是否允许把文件导出 |
| 一键转私密 | 随时把整个知识库收回「仅自己可见」 |

### 2.3 内容级细粒度（教程口径）

| 粒度 | 权限项 |
|------|--------|
| 文件夹 | 仅管理员可见 / 可查看不可导出 |
| 单文件 | 成员内容权限 → 独立查看权限、独立导出权限 |

### 2.4 访客与问答次数

| 身份 | 问答额度 |
|------|---------|
| 访客（未加入） | 3 轮（体验额度） |
| 成员 | 无限 |

来源：新华社 2025-01-03 电（记者王丰），为官方新闻稿口径。

### 2.5 管理操作入口

- 共享知识库页面顶部「···」→「权限管理」→ 切换各开关；
- 「分享」/「邀请协作」→ 链接或二维码邀请，按成员设角色与权限；
- 发布后可将知识库上架「广场」（发布后不再占用个人云存储空间）。

## 三、问答时的知识库范围选择

| 场景 | 范围确定方式 |
|------|------------|
| 对话中显式指定 | 输入「@共享库名 + 问题」，AI 只基于该库回答并标注出处 |
| 个人库问答 | 默认在「我的库」范围内检索 |
| 全网问答 | 可选脱离知识库、走全网 |
| 标签/文件夹收敛 | 问答可按标签/文件夹过滤（隐私指引明确支持） |

**对 Kquery 的启示**：ima 把「检索范围」当成**用户显式选择的资源句柄**（@库名），而不是隐式的「你能看到什么就搜什么」。这与 Kquery 现状（租户 ∩ 文档 ACL 的隐式全集过滤，见 `backend/app/services/pipeline.py:360-394`）是**两种互补机制**：ima 做的是「主动圈定」，Kquery 需要新增的是「管理员授权的被动边界」。两者可以叠加：先按授权过滤出可见 KB 集合，再让用户在其中 @某个 KB 圈定。

## 四、交互模式目录（可复用清单）

归一化为 Kquery 可直接借鉴的交互模式：

| # | 模式 | ima 的做法 | Kquery 借鉴点 |
|---|------|-----------|--------------|
| M1 | 库先于文档 | 「新建知识库」5 秒完成，空库即可存在 | KB 是独立实体，创建不依赖文档 |
| M2 | 三个入口分流 | 个人库 / 我创建的共享库 / 我加入的共享库 | Kquery 管理区可按「全部 KB / 我负责的 / 我被授权的」分 tab |
| M3 | 权限管理总开关面板 | 「···」→「权限管理」，开关列表 + 风险文案 | 复用现有 `AclPage.tsx` 的 modal + 风险分级交互 |
| M4 | 角色阶梯 | 创建者 > 管理员(≤5) > 协作成员(≤50) > 普通成员 | 对照现有硬编码 `ROLE_CAPABILITIES`（`backend/app/api/security.py:340-346`），KB 角色建议走库级而非全局 |
| M5 | 加入需审批 | 开关控制 + 申请通知 | 对应新增「授权请求」或直接由管理员显式授权（Kquery 是管理员主导模型，不需要申请流） |
| M6 | 内容级覆盖 | 文件夹/单文件可收紧可见与导出 | 对照现有文档级 ACL（`backend/app/services/security/acl.py`）——KB 授权与文档 ACL 取**交集** |
| M7 | 问答圈定 | @库名显式指定 | 前端 AskRequest 增加 `kb_id` 可选字段 |
| M8 | 访客体验额度 | 非成员 3 轮问答 | 对 Kquery 不适用（无访客概念，未认证直接 401） |

## 五、明确不借鉴的事（反面清单）

| # | ima 有，Kquery 不抄 | 理由 |
|---|--------------------|------|
| N1 | 微信小程序 / 公众号导入渠道 | Kquery 是企业内部署形态，无微信生态 |
| N2 | 知识库「广场」公域分发 | 企业私域场景，公域分发是安全事故源 |
| N3 | 访客 3 轮问答体验额度 | 与 Kquery「未认证不可用」的安全模型冲突 |
| N4 | 腾讯文档联动 | 无腾讯账号体系 |
| N5 | 库内成员自管理（协作成员删自己的文件） | Kquery 现阶段文档管理权限收敛在 admin（`require_role("admin")`），成员自管理属 P2 |
| N6 | 发布到广场后「不占用个人云存储」 | 存储计费模型不同，无对应概念 |

## 七、局限声明

1. ima 不公开技术实现，本文全部结论来自**产品文案与教程的交叉验证**，未做任何账号级实测；
2. 人数上限（管理员 5 / 协作成员 50）、访客问答额度（3 轮）等数字以 2025-01 官方新闻稿口径为准，后续版本可能调整；
3. 「文档从个人库搬运到共享库」的语义（复制 or 移动 or 引用）无法从公开资料确认，Kquery 设计时应自行拍板（建议：**复制**，避免共享库 ACL 回收影响个人库）；
4. 文件夹权限与单文件权限的具体优先级规则（谁覆盖谁）公开资料未说明，Kquery 设计时需自行定义（建议：库级授权 → 文件夹/文档 ACL 收紧，deny 永远优先，与现有 ACL 判定树一致）。
