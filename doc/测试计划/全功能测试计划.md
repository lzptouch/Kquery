## 2. 测试策略

### 测试流程

```
1. 后端 API 测试（curl） → 验证接口可访问性、参数校验、响应结构
2. 前端 API 代理测试 → 验证前后端联通性
3. 浏览器 E2E 测试 → 验证完整用户交互流程
4. 发现问题 → 定位根因 → 修复 → 重新测试
```

### 测试判定标准

| 标记 | 含义 |
|------|------|
| ✅ | 通过 - 功能正常 |
| ⚠️ | 警告 - 功能可用但有小问题 |
| ❌ | 失败 - 功能有缺陷需修复 |
| 🔧 | 已修复 - 缺陷已修复并通过重测 |
| — | 跳过 - 依赖外部服务或暂不支持 |

### 每项测试验证内容

1. **HTTP 状态码** 是否符合预期（200/201/204/400/401/404/500）
2. **响应结构** 是否与文档一致
3. **参数校验** 是否正确处理边界情况
4. **认证鉴权** 是否生效
5. **错误处理** 是否返回友好错误信息
