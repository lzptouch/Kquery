### 2.2 A-07：领域异常基类

现状：29 处 `raise RuntimeError` / `raise ValueError` 散在 `core` 与 `services`（口径与审计计划一致；全 `app/` 口径为 33，多出的 4 处是 `main.py` 启动期校验与 `core/envelope.py` 的错误码自检——均属合理保留）。

**目标**：在 `backend/app/core/envelope.py` 附近建立**领域异常基类**：

```python
class DomainError(Exception):
    """领域异常的基类：携带错误码，由 ApiError 之外的唯一出口转成信封。"""
    code: int = ErrCode.INTERNAL_ERROR
    http_status: int = 500
```

派生：

| 异常 | 码 | HTTP | 用途 |
|---|---|---|---|
| `ConfigError` | 1004 | 500 | 配置非法（启动期） |
| `StorageCorruptedError` | 5001 | 500 | 真相源文件损坏（**拒绝启动**） |
| `UpstreamError` | 4001 | 502 | 上游（LLM / Embedding / Rerank）故障 |
| `UpstreamTimeoutError` | 4002 | 504 | 上游超时 |
| `QuotaExceededError` | 6201 | 429 | 配额耗尽 |
| `RateLimitedError` | 6101 | 429 | 限流 |
| `OverloadedError` | 6101 | 503 | 过载背压 |

**全局处理器**：在 `backend/app/main.py` 的四层异常处理器里加一层 `DomainError` 处理器（放在 `ApiError` 之后、`Exception` 之前），保证：

- 一次异常只在一处记堆栈（**处理函数记 `logger.exception`，端点不记**）；
- HTTP 状态码由异常自带，不再由端点决定。

**逐点替换**：29 处按「异常语义 → 异常类」映射，逐个改（`agent/tools.py` 7 处与 `parsers/audio.py` 5 处占大头）；**不要**为了改得快把全部换成 `DomainError`（那就等于没分类）。

**验收**：裸 `raise RuntimeError|ValueError` 计数 ≤ 9；每个替换点有单测；`/ask` 的 LLM 故障返回 **502** 而非 200（见 §二.3）。

### 2.3 X-04（与 A-07 联动）：失败语义不再是 HTTP 200

现状：`backend/app/api/ask.py:198-199`：

```python
except LLMError as exc:
    return error_envelope(exc.code, exc.message, trace_id, ...)   # ← HTTP 仍是 200
```

后果：网关 / 告警按 5xx 统计会**全部漏掉**。

**目标**：`LLMError` → 抛 `UpstreamError`（或 `UpstreamTimeoutError`），由全局处理器转成 **502 / 504 + 统一信封**。

**验收**：

- 让 LLM 抛错 → `/ask` 返回 **502**（不是 200）；
- 响应体仍是统一信封（`status="error"` + `error.code` + `error.message` + `meta`）；
- `main.py` 的 `http_error_handler` 对 **任意 404** 仍映射 `DOCUMENT_NOT_FOUND(3002)` 的问题**顺带分层**：路由未命中 → 1004 `INVALID_REQUEST`（区分「URL 拼错」与「文档不存在」）。

## 五、A-05 · `/healthz` 不回显异常原文

### 5.1 问题

`backend/app/main.py:832-836`：

```python
except Exception as exc:
    deps.append({..., "error": str(exc)[:200]})
```

`str(exc)` 未脱敏 → **连接串 / 文件路径 / 内部结构可能直接进响应体**。这在运维上是便利，在安全上是泄露（`/healthz` 是公开端点）。

### 5.2 目标

- 响应体只给**错误类别 + 错误码**，不给原文；
- 原文进**日志**（带 trace_id），运维查日志即可。

```python
except Exception as exc:
    logger.warning("探针 %s 失败: %s", name, exc, exc_info=True)   # 完整堆栈进日志
    deps.append({"name": name, "status": "down", "latency_ms": ..., "error_kind": type(exc).__name__})
```

### 5.3 验收

- 断网访问 Milvus → `/healthz` 响应体**不含**连接串 / 路径 / 异常原文；
- 日志里有完整 traceback。

## 六、A-11 · 图存储损坏时拒绝启动

### 6.1 问题

`backend/app/services/graph/sqlite_store.py:10` 自述：

> 非原子 | 写一半崩溃 → 文件损坏 → 下次启动「加载失败，从空图启动」，**全部图谱丢失**

这与全局「真相源损坏即拒绝启动」纪律**直接矛盾**（对比 `backend/app/services/knowledge.py:116` 的 `RuntimeError("文档元数据文件损坏，拒绝启动")`）。

### 6.2 目标

```python
# sqlite_store.py 加载路径
if path.exists():
    try:
        self._load(path)
    except sqlite3.DatabaseError as exc:
        raise StorageCorruptedError(
            f"图谱存储文件损坏，拒绝启动: {path}\n"
            "请从备份恢复，或手动删除该文件后重新构建图谱（POST /admin/graph/build）。"

```

**注意**：这里**不能**把路径原样放进异常消息（会进日志，但日志是内部的，可以；不能进 HTTP 响应体——见 §五）。

### 6.3 配套：原子写

### 6.4 验收

- 人为破坏 sqlite 文件 → 启动失败，日志给出可操作指引；
- 与 `knowledge.py` / `acl.py` 的行为一致。

## 七、B0 KQ-26 · 证据区扫描敏感词

### 7.1 问题

`backend/app/services/pipeline.py:930-944`：

```python
sensitive = self._scanner.scan(answer, tenant_id)     # 只扫答案
...
for ev in evidence:
    yield "evidence", ev.model_dump()                  # 证据原样输出
```

文档里的敏感片段会**绕过输出侧扫描**，直接以证据卡形式展示给用户。

### 7.2 目标

证据逐条扫描：

```python
for ev in evidence:
    hit = self._scanner.scan(ev.content, tenant_id)
    if hit["action"] == "refuse":
        continue                       # 该条证据不外带（不进上下文，也不进证据列表）
    if hit["action"] == "mask":
        ev.content = hit["masked_text"]
    yield "evidence", ev.model_dump()
```

**顺序要求**：扫描必须在**证据进上下文之前**（否则答案里已经含了未脱敏内容）。当前流程是「检索 → 组装上下文 → 生成答案 → 输出侧扫描」，因此证据扫描应插在**组装上下文之后、生成之前**。

### 7.3 配套：子串匹配误伤

`backend/app/services/security/sensitive.py:95`：

```python
if pattern and pattern in normalized:     # 子串匹配
```

词表含「内部」时，「内部审计」会误命中。

**目标**：改**词边界匹配**（英文用 `\b`，中文用「前后不是同类型字符」启发式），或引入 AC 自动机。**边界规则必须写进 `doc/analysis/08-安全与治理.md` §七**，否则用户会遇到「为什么这个词总被拦」。

### 7.4 配套：`_reload()` 每次 `stat`

`sensitive.py:84` 每次 `scan` 都调 `_reload()` → 每次 `stat`。高 QPS 下是系统调用风暴。

**目标**：用 mtime 缓存 + 后台定时刷新（当前已有 `_reload` 骨架，改为「mtime 未变则跳过」）。

### 7.5 验收

- 证据含敏感词 → 该条证据不出现在响应中；
- 词表含「内部」时，「内部审计」不误命中；
- 压测下 `stat` 调用次数不随 QPS 线性增长。

## 八、A-06 / A-15 ~ A-18 · 日志与生命周期纪律

### 8.1 A-06：已完成入库任务无淘汰

现状：`backend/app/services/ingest.py:78` 只对**待处理队列**限了 `maxsize=200`；**已完成任务对象仍留在 `_tasks` 字典**，长期运行持续增长。

**目标**：`TaskManager` 加**完成态淘汰**——任务进入终态（`done` / `failed` / `partial_failed` / `cancelled`）后保留 N 分钟（可配，如 30 分钟）供前端查看，之后从 `_tasks` 移除。

**验收**：连续上传 600 个文档后，`len(task_manager._tasks)` 稳定在有界范围。

```python
def get_logger(name: str) -> logging.Logger:
```

全部 78 处改为 `from app.core.logging_setup import get_logger` + `get_logger(__name__)`。

**动机不只是洁癖**：绕过入口的 logger **不会拿到 `ContextFilter` 注入的 `trace_id`**，排障时无法把日志和请求串起来。

### 8.3 A-16：启动期脱敏配置回显


**落点**：`backend/app/services/pipeline.py` 的 `_core_events` 末尾（已有各阶段计时变量：`stats.retrieval_ms` / `stats.rerank_ms` 等，见 `backend/app/domain/schemas.py:261-305`）。

### 8.5 A-18：`extra` 字段截断

目标：日志 `extra` 里的长字段截断到 **512 字符**，防止单条日志膨胀到 MB 级。

**落点**：`backend/app/core/logging_setup.py` 的自定义 `Formatter`（或 `LogRecordFactory`）统一处理。

### 8.6 X-13：`_top_queries` 无淘汰

现状：`backend/app/core/metrics.py:155`（声明）、`:209`（写入）、`:294`（读取）——**无容量上限**。

**目标**：改固定容量 LRU（如 256 条），超出即淘汰最旧。

**落点**：`backend/app/core/metrics.py`。

## 九、A-19 / A-20 / X-25 · 文档与断言

### 9.1 A-19：`scripts/gen_env_example.py`

**目标**：从 `backend/app/core/config.py` 的 `Settings` 字段**自动生成** `.env.example`：

- 字段名 → 环境变量名（前缀 `KQUERY_`，`milvus_uri` 走 alias）；
- 默认值 → 作为注释给出；
- 敏感字段（key / token / secret / password）→ 值留空 + 提示；
- CI 校验：生成物与仓库内 `.env.example` **逐行一致**，不一致即红。

**注意**：`backend/app/core/config.py` 的 `config_items()`（`:329-373`）已经在做「配置项声明」这件事——生成脚本应**复用它**，不要另写一套解析。

### 9.2 A-20：写端点限流断言

**目标**：一个**自动断言**保证所有写端点（POST / PUT / DELETE）挂了 `enforce_rate_limit`。

**实现**：从 `app.openapi()` 取所有非 GET 端点，逐个检查其 `dependencies` 里是否含 `enforce_rate_limit`。这比 grep 可靠（grep 只能看到源码写法，看不到 `router` 级依赖继承）。

**落点**：`backend/tests/unit/test_write_endpoints_rate_limited.py`。
